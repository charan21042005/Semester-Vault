# UNIT II — PART 4: CRUD → READ

The **R** in CRUD means:

> **Read** = retrieve/query existing documents from MongoDB.

MongoDB's main shell methods for this are:

```
find()
findOne()
```

> `find()` returns a cursor to matching documents, while `findOne()` returns a single matching document. MongoDB also lets us control which fields come back using **projection**.

Our journey:

```
READ
 │
 ├── find()
 │
 ├── findOne()
 │
 ├── Filtering
 │     ├── equality
 │     ├── comparison operators
 │     └── logical operators
 │
 ├── Projection
 │
 ├── Nested fields
 │
 ├── Arrays
 │
 ├── sort()
 │
 ├── limit()
 │
 └── skip()
```

We'll build this slowly.

---

## 1. 🧠 First, Understand the Problem

Suppose our collection contains:

```js
db.students.insertMany([
    {
        name: "Rahul",
        age: 21,
        branch: "CSE",
        cgpa: 8.5
    },
    {
        name: "Priya",
        age: 20,
        branch: "ECE",
        cgpa: 9.1
    },
    {
        name: "Arjun",
        age: 22,
        branch: "CSE",
        cgpa: 8.2
    },
    {
        name: "Kiran",
        age: 21,
        branch: "MECH",
        cgpa: 7.8
    }
])
```

Now imagine I ask:

> Give me all students.

Or:

> Give me only CSE students.

Or:

> Give me students whose CGPA is greater than 8.5.

Or:

> Give me only their names and CGPAs.

Or:

> Give me the top 2 students by CGPA.

That's **READ**.

---

## 2. 🧠 `find()` — The Foundation

The simplest query:

```js
db.students.find()
```

means:

> "Find documents from the `students` collection."

> With no filter, it returns all documents. MongoDB actually returns a **cursor** representing the matching results.

Conceptually:

```
students
   │
   ├── Rahul
   ├── Priya
   ├── Arjun
   └── Kiran

db.students.find()
        ↓
ALL MATCHING DOCUMENTS
```

---

## 3. 🧩 Why Is It Called `find()`?

Think like this:

```
find(WHAT?)
```

The thing inside `find()` tells MongoDB:

> What documents should I select?

For example:

```js
db.students.find({
    branch: "CSE"
})
```

means:

> Find students whose branch is CSE.

So:

```
find()
  ↓
Query
  ↓
Matching documents
```

---

## 4. 🧠 Empty `{}` vs No Argument

These two:

```js
db.students.find()
```

and:

```js
db.students.find({})
```

both mean:

> return all documents.

> Because an empty query document means there is no filtering condition.

So:

```
db.students.find()
```

is basically the beginner-friendly version of:

```
db.students.find({})
```

---

## 5. 🔥 The Real Power Begins — Filtering

Suppose we want only:

```
branch = CSE
```

We write:

```js
db.students.find({
    branch: "CSE"
})
```

This is an **equality query**.

MongoDB checks every document conceptually:

```
Rahul → branch = CSE  → ✅
Priya → branch = ECE  → ❌
Arjun → branch = CSE  → ✅
Kiran → branch = MECH → ❌
```

Result:

```
Rahul
Arjun
```

---

## 6. 🧩 Understand the Query Structure

Look at:

```js
db.students.find({
    branch: "CSE"
})
```

Break it down:

```
db
 ↓
students
 ↓
find()
 ↓
{
    branch: "CSE"
}
```

And inside:

```
{
    branch: "CSE"
}
```

means:

```
FIELD       VALUE
  ↓           ↓
branch      "CSE"
```

> MongoDB finds documents where that field matches the specified value. Equality can also be written explicitly using `$eq`, although the simple `{ field: value }` form is usually cleaner.

---

## 7. 🧠 Equality — Different Examples

Find students named Rahul:

```js
db.students.find({
    name: "Rahul"
})
```

Find CSE students:

```js
db.students.find({
    branch: "CSE"
})
```

Find students with age 21:

```js
db.students.find({
    age: 21
})
```

Find students with CGPA exactly 8.5:

```js
db.students.find({
    cgpa: 8.5
})
```

The mental pattern is:

```js
db.collection.find({
    field: value
})
```

This pattern should become automatic.

---

## 8. 🧠 `findOne()` — I Want Just One

Now suppose I don't want a whole set.

I want **one** matching document.

Use:

```js
db.students.findOne({
    name: "Rahul"
})
```

This returns a single document.

> MongoDB documents `findOne()` as essentially a `find()` operation with a limit of 1.

So:

```
find()
   ↓
possibly MANY documents

findOne()
   ↓
ONE document
```

---

## 9. 🧩 `find()` vs `findOne()`

|                     | `find()`                    | `findOne()`                    |
|---------------------|------------------------------|----------------------------------|
| Purpose             | Find matching documents      | Find one matching document       |
| Result concept      | Cursor                        | Single document                  |
| Can return multiple?| Yes                            | No                                |
| Example             | `find({branch:"CSE"})`        | `findOne({name:"Rahul"})`        |

Think:

> `find` = "show me the matching group"
>
> `findOne` = "show me one matching document"

---

## 10. 🧠 `findOne()` Without a Filter

You can even do:

```js
db.students.findOne()
```

This asks MongoDB for one document from the collection.

But don't think it means:

> "Give me the first document in some permanently guaranteed order."

That's an important distinction.

> MongoDB doesn't promise that a normal collection's natural result order is something you should rely upon.

If you specifically care about order, use `sort()`.

We'll get there.

---

## 11. 🔥 Multiple Conditions — AND

Now things get interesting.

Suppose we want:

> CSE students AND CGPA greater than 8.

We can write:

```js
db.students.find({
    branch: "CSE",
    cgpa: { $gt: 8 }
})
```

This means:

```
branch = CSE
AND
cgpa > 8
```

> MongoDB's comparison operators include `$gt`, `$gte`, `$lt`, `$lte`, `$eq`, `$ne`, `$in`, and `$nin`.

Let's dry-run:

```
Rahul
branch = CSE → ✅
cgpa 8.5 > 8 → ✅
→ MATCH

Priya
branch = ECE → ❌
→ NO

Arjun
branch = CSE → ✅
cgpa 8.2 > 8 → ✅
→ MATCH

Kiran
branch = MECH → ❌
→ NO
```

Result:

```
Rahul
Arjun
```

---

## 12. 🧠 `$gt` — Greater Than

This:

```js
{
    cgpa: { $gt: 8 }
}
```

means:

> CGPA greater than 8.

Think:

```
$gt
 ↓
Greater Than
 >
```

Examples:

```js
db.students.find({
    cgpa: { $gt: 8.5 }
})
```

means:

```
cgpa > 8.5
```

---

## 13. 🧠 `$gte` — Greater Than or Equal

```js
db.students.find({
    cgpa: { $gte: 8.5 }
})
```

means:

```
cgpa >= 8.5
```

So if:

```
Rahul = 8.5
```

Rahul **does** match.

> MongoDB defines `$gte` as selecting documents where the field value is greater than or equal to the specified value.

---

## 14. 🧠 `$lt` — Less Than

```js
db.students.find({
    cgpa: { $lt: 8 }
})
```

means:

```
cgpa < 8
```

---

## 15. 🧠 `$lte` — Less Than or Equal

```js
db.students.find({
    cgpa: { $lte: 8 }
})
```

means:

```
cgpa <= 8
```

---

## 16. 🧠 `$ne` — Not Equal

Suppose:

> Find everyone who is NOT from CSE.

```js
db.students.find({
    branch: { $ne: "CSE" }
})
```

Meaning:

```
branch ≠ CSE
```

> MongoDB's `$ne` matches values not equal to the specified value.

---

## 17. 🧠 `$in` — Match One of Several Values

Suppose we want:

> CSE OR ECE students.

We can say:

```js
db.students.find({
    branch: {
        $in: ["CSE", "ECE"]
    }
})
```

Think:

```
branch ∈ {CSE, ECE}
```

> MongoDB's `$in` matches when the field value is one of the specified values.

---

## 18. 🧠 `$nin` — NOT In

Opposite:

```js
db.students.find({
    branch: {
        $nin: ["CSE", "ECE"]
    }
})
```

means:

> branch is neither CSE nor ECE.

---

## 19. 📝 Comparison Operators — Memorize the Family

This little table is worth burning into your brain:

| Operator | Meaning              | Symbol |
|----------|----------------------|--------|
| `$eq`    | Equal                | =      |
| `$ne`    | Not equal            | ≠      |
| `$gt`    | Greater than         | >      |
| `$gte`   | Greater/equal        | >=     |
| `$lt`    | Less than            | <      |
| `$lte`   | Less/equal           | <=     |
| `$in`    | One of these values  | ∈      |
| `$nin`   | Not any of these     | ∉      |

> These are **query operators**.
>
> They are **not** JavaScript operators.

That's an important distinction.

---

## 20. 🔥 Logical Operators

Now suppose the requirement becomes:

> Give me CSE students OR students with CGPA above 9.

That's no longer a simple AND.

We can explicitly use:

```js
db.students.find({
    $or: [
        { branch: "CSE" },
        { cgpa: { $gt: 9 } }
    ]
})
```

Meaning:

```
branch = CSE
       OR
cgpa > 9
```

> MongoDB provides `$and`, `$or`, `$nor`, and `$not` for logical query conditions.

---

## 21. 🧠 `$or` Visualized

Suppose:

```
Rahul → CSE, 8.5
Priya → ECE, 9.1
Arjun → CSE, 8.2
Kiran → MECH, 7.8
```

Query:

```js
{
    $or: [
        { branch: "CSE" },
        { cgpa: { $gt: 9 } }
    ]
}
```

Check:

```
Rahul
CSE? YES → ✅

Priya
CSE? NO
CGPA > 9? YES → ✅

Arjun
CSE? YES → ✅

Kiran
CSE? NO
CGPA > 9? NO → ❌
```

Result:

```
Rahul
Priya
Arjun
```

---

## 22. 🧠 `$and`

You can explicitly write:

```js
db.students.find({
    $and: [
        { branch: "CSE" },
        { cgpa: { $gt: 8 } }
    ]
})
```

Meaning:

```
CSE
AND
CGPA > 8
```

But here's a nice MongoDB syntax shortcut:

> You usually don't need `$and` for simple different-field conditions.

This:

```js
{
    branch: "CSE",
    cgpa: { $gt: 8 }
}
```

already means:

```
branch = CSE
AND
cgpa > 8
```

So don't unnecessarily make your query complicated.

---

## 23. 🔥 Now Comes a VERY Important Concept — Projection

Suppose:

```js
db.students.find({
    branch: "CSE"
})
```

returns:

```
_id
name
age
branch
cgpa
```

But imagine an application only needs:

```
name
cgpa
```

Why send all the other fields?

That's where **projection** comes in.

Projection means:

> Specify which fields should be returned from matching documents.

> MongoDB's `find()` supports a projection parameter for this.

---

## 24. 🧩 Projection Syntax

```js
db.students.find(
    { branch: "CSE" },
    { name: 1, cgpa: 1 }
)
```

There are now two objects.

**First:**

```
{ branch: "CSE" }
```

= Which documents?

**Second:**

```
{ name: 1, cgpa: 1 }
```

= Which fields?

This distinction is **HUGE**.

Think:

```
find(
    FILTER,
    PROJECTION
)
```

---

## 25. 🧠 `1` Means Include

```js
{
    name: 1,
    cgpa: 1
}
```

means:

> Include `name` and `cgpa`.

So instead of:

```
{
    _id,
    name,
    age,
    branch,
    cgpa
}
```

we get approximately:

```
{
    _id,
    name,
    cgpa
}
```

Notice something strange?

`_id` is still there.

---

## 26. 🧠 Why Is `_id` Still There?

> MongoDB includes `_id` by default unless you explicitly exclude it from the projection.

So:

```js
db.students.find(
    { branch: "CSE" },
    {
        name: 1,
        cgpa: 1,
        _id: 0
    }
)
```

gives:

```js
{
    name: "Rahul",
    cgpa: 8.5
}
```

Now `_id` is removed.

This is an extremely common MongoDB query pattern.

---

## 27. 🧠 Projection Mental Model

```
Query
 │
 ├── FILTER
 │      ↓
 │   Which documents?
 │
 └── PROJECTION
        ↓
     Which fields?
```

Example:

```js
db.students.find(
    { branch: "CSE" },
    { name: 1, cgpa: 1, _id: 0 }
)
```

Translation:

> Find CSE students, but return only their name and CGPA.

That's a proper database query, mate.

---

## 28. 🔥 Nested Fields — MongoDB Gets Beautiful Here

Suppose our document is:

```json
{
    "name": "Rahul",
    "branch": "CSE",
    "address": {
        "city": "Chennai",
        "state": "Tamil Nadu"
    }
}
```

What if we want:

> Find students whose city is Chennai.

MongoDB uses **dot notation**:

```js
db.students.find({
    "address.city": "Chennai"
})
```

Read it as:

```
address
   ↓
city
```

So:

```
"address.city"
```

means:

> the `city` field inside the `address` embedded document.

> MongoDB's query documentation demonstrates this same dot-notation approach for fields inside embedded documents.

---

## 29. 🧠 Nested Field Dry Run

Document:

```json
{
    "name": "Rahul",
    "address": {
        "city": "Chennai",
        "state": "Tamil Nadu"
    }
}
```

Query:

```js
db.students.find({
    "address.city": "Chennai"
})
```

MongoDB follows:

```
document
   ↓
address
   ↓
city
   ↓
"Chennai"
```

Match → ✅

## 30. 🧩 Arrays — Querying Becomes Interesting

Suppose:

```json
{
    "name": "Rahul",
    "skills": [
        "C++",
        "Python",
        "MongoDB"
    ]
}
```

We can search:

```js
db.students.find({
    skills: "Python"
})
```

> This can match documents where the array contains `"Python"`.

So MongoDB's document-oriented model lets us query inside arrays naturally.

Later we'll go much deeper into array operators.

## 31. 🔥 Sort the Results

Suppose we want students ordered by CGPA.

Use:

```js
db.students.find().sort({
    cgpa: 1
})
```

Here:

```
1
↓
ascending
```

So:

```
7.8
8.2
8.5
9.1
```

For descending:

```js
db.students.find().sort({
    cgpa: -1
})
```

Now:

```
9.1
8.5
8.2
7.8
```

Mental rule:

```
1  → ASCENDING
-1 → DESCENDING
```

---

## 32. 🧠 Top Students

Now combine what we know.

Question:

> Give me the top 2 students by CGPA.

```js
db.students.find()
    .sort({ cgpa: -1 })
    .limit(2)
```

Think of the pipeline-like flow:

```
ALL STUDENTS
     ↓
sort CGPA descending
     ↓
9.1
8.5
8.2
7.8
     ↓
limit 2
     ↓
9.1
8.5
```

This is a very practical query.

---

## 33. 🧠 `limit()`

```js
db.students.find().limit(2)
```

means:

> Return at most 2 documents.

> MongoDB's `find()` supports `limit` as an option to restrict the result set.

---

## 34. 🧠 `skip()`

Suppose:

```
1 → Rahul
2 → Priya
3 → Arjun
4 → Kiran
```

We can skip the first two:

```js
db.students.find().skip(2)
```

Conceptually:

```
skip 2
 ↓
Rahul ❌
Priya ❌
Arjun ✅
Kiran ✅
```

This is especially useful for **pagination**.

---

## 35. 🔥 Pagination Mental Model

Imagine an e-commerce website:

```
Page 1
products 1–10

Page 2

```

MongoDB can conceptually do:

db.products.find()

## 36. 🔥 Combine Everything

Now we're going to write a serious query.

Question:

> Find CSE students whose CGPA is at least 8, show only their name and CGPA, order them from highest to lowest CGPA, and return only the first 2.

That's a lot.

But look how naturally it builds:

**Step 1 — Filter**

```js
{
    branch: "CSE",
    cgpa: { $gte: 8 }
}
```

**Step 2 — Projection**

```js
{
    name: 1,
    cgpa: 1,
    _id: 0
}
```

**Step 3 — Sort**

```js
.sort({ cgpa: -1 })
```

**Step 4 — Limit**

```js
.limit(2)
```

**Final:**

```js
db.students.find(
    {
        branch: "CSE",
        cgpa: { $gte: 8 }
    },
    {
        name: 1,
        cgpa: 1,
        _id: 0
    }
)
.sort({ cgpa: -1 })
.limit(2)
```

Now look at what you've just done.

You've combined:

```
FILTER
  ↓
PROJECT
  ↓
SORT
  ↓
LIMIT
```

That's real MongoDB querying.

## 38. ⚠️ A Crucial Distinction: Filter vs Projection

Beginners frequently mix these up.

Look at:

```js
db.students.find(
    { branch: "CSE" },
    { name: 1, cgpa: 1 }
)
```

**First object:**

```
{ branch: "CSE" }
```

asks:

> Which documents?

**Second object:**

```
{ name: 1, cgpa: 1 }
```

asks:

> Which fields?

Remember:

```
FILTER     → documents
PROJECTION → fields
```

Burn that into memory.

---

## 39. ⚠️ Another Important Trap — `"8.5"` vs `8.5`

Remember Part 2's BSON types?

This matters during READ.

Suppose document:

```json
{
    "cgpa": 8.5
}
```

Here:

```
8.5
```

is **numeric**.

But:

```json
{
    "cgpa": "8.5"
}
```

is a **string**.

So don't casually query:

```js
{ cgpa: "8.5" }
```

when your stored data is numeric.

> MongoDB's comparison behavior depends heavily on BSON types; comparison operators generally compare matching BSON types, with limited type bracketing.

This is why BSON data types from Part 2 directly matter when querying.
