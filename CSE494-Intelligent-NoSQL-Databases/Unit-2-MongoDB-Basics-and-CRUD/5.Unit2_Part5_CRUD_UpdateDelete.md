# PART A — UPDATE

## 1. 🧠 First, Understand the Problem

Suppose our collection is:

```json
{
    "name": "Rahul",
    "age": 21,
    "branch": "CSE",
    "cgpa": 8.5
}
```

Now Rahul's CGPA becomes:

```
8.5 → 8.8
```

We don't want to delete the whole document and recreate it.

We simply want:

```
CHANGE ONE FIELD
```

That's what UPDATE does.

Think:

```
Existing document
      ↓
Find target document
      ↓
Modify selected field(s)
      ↓
Updated document
```

---

## 2. 🧠 `updateOne()`

Basic syntax:

```js
db.collection.updateOne(
    filter,
    update
)
```

Example:

```js
db.students.updateOne(
    { name: "Rahul" },
    { $set: { cgpa: 8.8 } }
)
```

Read this like English:

> Find one student whose name is Rahul and set his CGPA to 8.8.

---

## 3. 🧩 Break It Apart

```js
db.students.updateOne(
    { name: "Rahul" },
    { $set: { cgpa: 8.8 } }
)
```

**Part 1**

```
{ name: "Rahul" }
```

= Which document?

**Part 2**

```
{ $set: { cgpa: 8.8 } }
```

= What change?

So:

```
updateOne(
    FILTER,
    MODIFICATION
)
```

This is extremely important.

---

## 4. 🔥 Dry Run

Before:

```json
{
    "name": "Rahul",
    "age": 21,
    "branch": "CSE",
    "cgpa": 8.5
}
```

Command:

```js
db.students.updateOne(
    { name: "Rahul" },
    { $set: { cgpa: 8.8 } }
)
```

After:

```json
{
    "name": "Rahul",
    "age": 21,
    "branch": "CSE",
    "cgpa": 8.8
}
```

Notice:

```
name   → unchanged
age    → unchanged
branch → unchanged
cgpa   → changed
```

That's the beauty of `$set`.

## 5. 🧠 `$set` — The Most Fundamental Update Operator

> `$set` sets/replaces the value of a specified field. If the field doesn't exist, `$set` can add it.

Syntax:

```js
{
    $set: {
        field: value
    }
}
```

Example:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $set: {
            cgpa: 8.8
        }
    }
)
```

---

## 6. 🧩 `$set` Can Add a NEW Field

Suppose Rahul doesn't have:

```
graduationYear
```

We can do:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $set: {
            graduationYear: 2027
        }
    }
)
```

Before:

```json
{
    "name": "Rahul",
    "cgpa": 8.8
}
```

After:

```json
{
    "name": "Rahul",
    "cgpa": 8.8,
    "graduationYear": 2027
}
```

So `$set` doesn't only mean "change an existing field."

It can also mean:

> Create this field with this value if it doesn't exist.

---

## 7. 🧠 Updating Multiple Fields with `$set`

We can update several fields in one operation:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $set: {
            cgpa: 9.0,
            age: 22,
            status: "Excellent"
        }
    }
)
```

Conceptually:

```
cgpa   → 9.0
age    → 22
status → Excellent
```

All targeted in the same update operation.

---

## 8. 🔥 `$inc` — Increase/Decrease a Number

Now suppose:

```
age = 21
```

and we want:

```
age = 22
```

We could technically write:

```
$set: { age: 22 }
```

But what if we don't know the current value?

Maybe:

```
age = 21
```

or:

```
age = 22
```

or:

```
age = 23
```

We simply want:

> Increase age by 1.

That's where:

```
$inc
```

comes in.

> MongoDB's `$inc` increments a numeric field by the specified amount. It can also accept a negative number to decrease the value.

---

## 9. 🧠 `$inc` Example

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $inc: {
            age: 1
        }
    }
)
```

If:

```
age = 21
```

then:

```
21 + 1 = 22
```

If:

```
age = 22
```

then:

```
22 + 1 = 23
```

We don't need to know the original value.

---

## 10. 🧠 `$inc` Can Decrease Too

Suppose:

```
stock = 50
```

Customer buys 3.

```js
db.products.updateOne(
    { name: "Keyboard" },
    {
        $inc: {
            stock: -3
        }
    }
)
```

Result:

```
50 → 47
```

So:

```
$inc:  { stock: 5 }   → +5
$inc:  { stock: -5 }  → -5
```

Very useful for:

```
stock
scores
counters
views
likes
balances
quantities
```

---

## 11. ⚠️ `$inc` Is NOT `$set`

This distinction is important.

Suppose:

```
score = 80
```

**`$set`**

```
{ $set: { score: 90 } }
```

means:

```
80 → 90
```

**`$inc`**

```
{ $inc: { score: 10 } }
```

means:

```
80 → 90
```

They happen to produce the same result here, but their meanings are completely different.

`$set`:

> Make the value 90.

`$inc`:

> Increase the current value by 10.

---

## 12. 🧠 `$inc` Can Create a Missing Field

Suppose:

```json
{
    "name": "Rahul"
}
```

and we execute:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $inc: {
            credits: 5
        }
    }
)
```

> If `credits` didn't exist, MongoDB creates it with the specified increment value.

So:

```
Before:
credits → doesn't exist

After:
credits → 5
```

## 13. 🔥 Updating Nested Fields

Remember our nested document:

```json
{
    "name": "Rahul",

    "address": {
        "city": "Chennai",
        "state": "Tamil Nadu"
    }
}
```

Suppose city changes:

```
Chennai → Bengaluru
```

We use **dot notation**:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $set: {
            "address.city": "Bengaluru"
        }
    }
)
```

Result:

```json
{
    "name": "Rahul",
    "address": {
        "city": "Bengaluru",
        "state": "Tamil Nadu"
    }
}
```

Only the nested field changed.

---

## 14. ⚠️ Very Important `$set` Trap

Suppose we have:

```js
address: {
    city: "Chennai",
    state: "Tamil Nadu"
}
```

Now imagine we do:

```js
{
    $set: {
        address: {
            city: "Bengaluru"
        }
    }
}
```

You're not just changing `city`.

You're **replacing the entire `address` embedded document** with:

```js
{
    city: "Bengaluru"
}
```

So:

```
Before:
address
 ├── city
 └── state

After:
address
 └── city
```

The `state` field is **gone**.

If you only want to change `city`, use:

```js
{
    $set: {
        "address.city": "Bengaluru"
    }
}
```

> MongoDB's documentation explicitly distinguishes dot-notation field updates from replacing the whole embedded document.

This is a very important practical trap.

## 15. 🔥 `updateMany()`

Now imagine:

```
CSE students:
Rahul
Arjun
Vijay
Kiran
```

Suppose the college changes the branch label:

```
CSE → Computer Science
```

We don't want to update them one by one.

Use:

```js
db.students.updateMany(
    { branch: "CSE" },
    {
        $set: {
            branch: "Computer Science"
        }
    }
)
```

> `updateMany()` updates all documents matching the filter.

---

## 16. 🧩 `updateOne()` vs `updateMany()`

Burn this into your brain:

| Method         | Meaning                              |
|-----------------|----------------------------------------|
| `updateOne()`   | Update at most one matching document  |
| `updateMany()`  | Update all matching documents         |

Imagine:

```
Filter:
branch = CSE

Documents:
Rahul → CSE
Arjun → CSE
Priya → ECE
Kiran → CSE
```

**`updateOne()`**

```
Rahul → changed
Arjun → unchanged
Priya → unchanged
Kiran → unchanged
```

**`updateMany()`**

```
Rahul → changed
Arjun → changed
Priya → unchanged
Kiran → changed
```

This distinction is critical.

## 17. 🧠 Update Result

When you run:

```js
db.students.updateOne(
    { name: "Rahul" },
    { $set: { cgpa: 9.0 } }
)
```

MongoDB returns information about the operation, including values such as:

```
matchedCount
modifiedCount
```

Conceptually:

```json
{
    "acknowledged": true,
    "matchedCount": 1,
    "modifiedCount": 1
}
```

Think:

**`matchedCount`**

> How many documents matched my filter?

**`modifiedCount`**

> How many documents actually changed?

That distinction matters.

Suppose Rahul already has:

```
cgpa = 9.0
```

and we execute:

```
$set: { cgpa: 9.0 }
```

You can have:

```
matchedCount = 1
modifiedCount = 0
```

because MongoDB found Rahul, but there was no actual value change.

## 18. 🔥 `$push` — Add Something to an Array

Now let's use the document model properly.

Suppose:

```json
{
    "name": "Rahul",
    "skills": [
        "C++",
        "Python"
    ]
}
```

Rahul learns MongoDB.

We want:

```
["C++", "Python"]
```

to become:

```
["C++", "Python", "MongoDB"]
```

Use:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $push: {
            skills: "MongoDB"
        }
    }
)
```

> `$push` appends a value to an array. If the field is absent, MongoDB can create it as an array containing that value; if the field exists but isn't an array, the operation fails.

---

## 19. 🧠 `$push` Dry Run

Before:

```
skills: [
    "C++",
    "Python"
]
```

Command:

```js
$push: {
    skills: "MongoDB"
}
```

After:

```
skills: [
    "C++",
    "Python",
    "MongoDB"
]
```

Very intuitive:

```
$push
  ↓
PUSH something INTO an array
```

---

## 20. 🧩 `$push` Multiple Values

Suppose Rahul learns:

```
MongoDB
Node.js
Docker
```

You can use `$each` with `$push`:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $push: {
            skills: {
                $each: ["MongoDB", "Node.js", "Docker"]
            }
        }
    }
)
```

Now:

```
C++
Python
MongoDB
Node.js
Docker
```

> `$each` is a modifier that lets `$push` append multiple values.

---

## 21. 🔥 `$pull` — Remove from an Array

Now Rahul says:

> "I don't want C++ in my skills list anymore."

We can use:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $pull: {
            skills: "C++"
        }
    }
)
```

> `$pull` removes array elements matching the specified value or condition.

Before:

```
["C++", "Python", "MongoDB"]
```

After:

```
["Python", "MongoDB"]
```

Think:

```
$push → put into array
$pull → pull out of array
```

🔥 Easy memory trick.

---

## 22. 🧠 `$pull` Can Use a Condition

Suppose:

```
scores: [45, 80, 32, 90, 25]
```

We want to remove scores below 40.

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $pull: {
            scores: { $lt: 40 }
        }
    }
)
```

Result:

```
[45, 80, 90]
```

Because `$pull` can remove all array elements matching a condition.

---

## 23. 🔥 `$unset` — Remove a Field

Suppose:

```json
{
    "name": "Rahul",
    "age": 21,
    "temporaryPassword": "abc123"
}
```

We want to remove:

```
temporaryPassword
```

Use:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $unset: {
            temporaryPassword: ""
        }
    }
)
```

After:

```json
{
    "name": "Rahul",
    "age": 21
}
```

> `$unset` removes the specified field. The value supplied in the `$unset` expression doesn't affect the removal.

So don't get confused by:

```
temporaryPassword: ""
```

It does **not** mean:

> Set `temporaryPassword` to empty string.

It means:

> Delete this field.

---

## 24. ⚠️ `$unset` vs `$set: null`

Very important distinction.

**This:**

```js
{
    $set: {
        phone: null
    }
}
```

means:

```
phone field EXISTS
value = null
```

**But:**

```js
{
    $unset: {
        phone: ""
    }
}
```

means:

```
phone field DOES NOT EXIST
```

So:

```
null ≠ field removed
```

That's a subtle database concept.

```js
db.students.updateOne(

```

After:

```json
{
    "name": "Rahul",
    "mobile": "9876543210"
}
```

> `$rename` changes the name of a field.

## 27. 🔥 Let's Combine Update Operators

Suppose:

```json
{
    "name": "Rahul",
    "age": 21,
    "cgpa": 8.5,
    "skills": ["C++", "Python"],
    "temporaryPassword": "abc123"
}
```

We want:

```
age → +1
cgpa → 9.0
add MongoDB
remove temporaryPassword
```

We can do:

```js
db.students.updateOne(
    { name: "Rahul" },
    {
        $inc: {
            age: 1
        },

        $set: {
            cgpa: 9.0
        },

        $push: {
            skills: "MongoDB"
        },

        $unset: {
            temporaryPassword: ""
        }
    }
)
```

After:

```json
{
    "name": "Rahul",
    "age": 22,
    "cgpa": 9.0,
    "skills": [
        "C++",
        "Python",
        "MongoDB"
    ]
}
```

Now that's a real update operation.

---

## 28. 🧠 One Scary Concept — `upsert`

There's one more important update concept.

Suppose:

```js
db.students.updateOne(
    { name: "Rahul" },
    { $set: { cgpa: 9.0 } },
    { upsert: true }
)
```

What does:

```
upsert
```

mean?

> Update if found; insert if not found.

So:

```
Does Rahul exist?
       │
    ┌──┴──┐
   YES    NO
    │      │
 UPDATE   INSERT
```

> MongoDB's `updateOne()` supports `upsert: true`; when no document matches, MongoDB creates a new document based on the filter and update information.

This is extremely useful in real applications.

But remember:

```
upsert
=
update + insert-if-missing
```

Not simply "update."

# PART B — DELETE 💀

Now we've modified documents.

What if we don't need them anymore?

That's:

```
DELETE
```

MongoDB provides:

```
deleteOne()
deleteMany()
```

> `deleteOne()` removes one matching document; `deleteMany()` removes all documents matching the filter.

---

## 29. 🧠 `deleteOne()`

Suppose:

```json
{
    "name": "Rahul",
    "branch": "CSE"
}
```

We want to remove Rahul.

```js
db.students.deleteOne({
    name: "Rahul"
})
```

MongoDB finds a matching document and deletes one document.

---

## 30. ⚠️ Why Should We Prefer `_id` for Precise Deletion?

Suppose there are:

```
Rahul
Rahul
Rahul
```

If you execute:

```js
db.students.deleteOne({
    name: "Rahul"
})
```

MongoDB deletes one matching document, not all three.

But **which** one?

You shouldn't depend on an arbitrary natural ordering.

If you know the unique `_id`:

```js
db.students.deleteOne({
    _id: ObjectId("...")
})
```

that's much more precise.

Mental rule:

> For deleting one exact document, `_id` is your safest friend.

---

## 31. 🔥 `deleteMany()`

Suppose:

```
branch = MECH
```

and we want to remove all MECH students.

```js
db.students.deleteMany({
    branch: "MECH"
})
```

If there are:

```
Kiran → MECH
Vijay → MECH
Arun → MECH
```

all three are deleted.

Conceptually:

```
deleteMany()
     ↓
check filter
     ↓
ALL matching docs
     ↓
DELETE
```

> MongoDB defines `deleteMany()` as removing all documents matching its filter.

---

## 32. 💀 The Dangerous Command

Look at this:

```js
db.students.deleteMany({})
```

Remember:

```
{}
```

means:

> No filter.

Therefore:

```
deleteMany({})
       ↓
ALL DOCUMENTS
       ↓
💀
```

So:

```js
db.students.deleteMany({})
```

deletes **all documents** from the collection.

This is why you should always inspect your filter before executing a destructive command.

And remember:

```js
db.students.drop()
```

is different — that drops the entire collection, including its indexes.

---

## 33. 🧠 `deleteOne({})`

Similarly:

```js
db.students.deleteOne({})
```

means:

> Delete one document with no filtering condition.

> MongoDB documents this as deleting the first document returned by the collection when the filter is empty.

So:

```
deleteOne({})
    ↓
ONE document
```

whereas:

```
deleteMany({})
    ↓
ALL documents
```

Huge difference.

---

## 34. 🧠 Delete Result

For:

```js
db.students.deleteOne({
    _id: 101
})
```

you'll get something conceptually like:

```json
{
    "acknowledged": true,
    "deletedCount": 1
}
```

`deletedCount` tells you how many documents were deleted.

For `deleteMany()`:

```json
{
    "acknowledged": true,
    "deletedCount": 5
}
```

means:

> 5 documents deleted.

## 36. 🧠 CRUD Using ONE Student Example

Let's make this painfully clear.

**CREATE**

```js
db.students.insertOne({
    name: "Rahul",

    branch: "CSE",
```

```js
db.students.findOne({
```

```js
db.students.updateOne(
```

```js
db.students.deleteOne({
    name: "Rahul"
})
```

So:

```
CREATE
   ↓
Rahul enters database

READ
   ↓
Find Rahul

UPDATE
   ↓
Change Rahul's CGPA

DELETE
   ↓
Remove Rahul
```

That's literally CRUD.

## 37. 📝 Operator Cheat Sheet

This is the table I want you to know cold:

| Operator  | Meaning                              |
|-----------|----------------------------------------|
| `$set`    | Set/change a field                     |
| `$inc`    | Increase/decrease numeric value        |
| `$push`   | Add item to array                      |
| `$pull`   | Remove matching item(s) from array     |
| `$unset`  | Remove a field                         |
| `$rename` | Rename a field                         |

And:

| Method          | Meaning                              |
|------------------|----------------------------------------|
| `updateOne()`   | Modify one matching document          |
| `updateMany()`  | Modify all matching documents         |
| `deleteOne()`   | Delete one matching document          |
| `deleteMany()`  | Delete all matching documents         |

```js
        $inc: { age: 1 }
    }
)
```

Now:

```
age: 21 → 22
```

**Operation 3**

```js
db.students.updateOne(
    { _id: 101 },
    {
        $push: { skills: "MongoDB" }
    }
)
```

Now:

```
skills:
[
    "C++",
    "Python",
    "MongoDB"
]
```

**Operation 4**

```js
db.students.updateOne(
    { _id: 101 },
    {
        $pull: { skills: "C++" }
    }
)
```

Now:

```
skills:
[
    "Python",
    "MongoDB"
]
```

**Operation 5**

```js
db.students.updateOne(
    { _id: 101 },
    {
        $unset: { temporaryPassword: "" }
    }
)
```

Now:

```
temporaryPassword → GONE
```

Final document:

```json
{
    "_id": 101,
    "name": "Rahul",
    "age": 22,
    "branch": "CSE",
    "cgpa": 9.0,
    "skills": [
        "Python",
        "MongoDB"
    ]
}
```

Nothing else was accidentally destroyed.

That's targeted document modification.

## 🧠 Part 5 — What I Want Permanently in Your Brain

If someone asks:

> How do you update a MongoDB document?

Think:

```
updateOne(filter, update)
```

or:

```
updateMany(filter, update)
```

Then ask:

> What modification?

```
$set
$inc
$push
$pull
$unset
$rename
```

If someone asks:

> How do you delete?

Think:

```
deleteOne(filter)
deleteMany(filter)
```

And the golden rule:

> **FILTER FIRST.**
> **THEN MODIFY/DELETE.**

Because this:

```js
db.students.updateMany(
    {},
    { $set: { status: "active" } }
)
```

means:

> update everyone.

And this:

```js
db.students.deleteMany({})
```

means:

> delete everyone. 💀
