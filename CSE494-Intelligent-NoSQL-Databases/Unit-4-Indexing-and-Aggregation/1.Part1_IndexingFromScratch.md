## 2. What is an Index?

### Simple definition:

> An index is a separate data structure maintained by MongoDB that helps locate documents more efficiently for supported queries.

> MongoDB stores index information separately from the collection's documents, and indexes can improve read performance by helping MongoDB identify relevant documents without scanning the entire collection.

Think:

```
COLLECTION
│
├── Document 1
├── Document 2
├── Document 3
├── ...
└── Document 1,000,000


INDEX
│
├── indexed value
├── indexed value
├── indexed value
└── references toward documents
```

The index is like a shortcut structure.

---

## 3. Without an Index

Suppose:

```json
{
    "name": "Rahul",
    "email": "rahul@gmail.com",
    "branch": "CSE"
}
```

and we have:

```
10 million students
```

Our query:

```js
db.students.find({
    email: "rahul@gmail.com"
})
```

Without a useful index, MongoDB may need to inspect documents throughout the collection.

Conceptually:

```
Query
  ↓
students collection
  ↓
Document 1 → email? ❌
Document 2 → email? ❌
Document 3 → email? ❌
Document 4 → email? ❌
...
Document 8,736,214 → email? ✅
```

This is:

```
COLLSCAN
```

Meaning:

```
COLlection SCAN
```

## 4. What is COLLSCAN?

Break the word:

```
COLL
 ↓
Collection

SCAN
 ↓
Scan
```

So:

```
COLLSCAN
=
Collection Scan
```

> MongoDB's explain output can show a `COLLSCAN` stage when the query plan scans the collection rather than using an applicable index.

Mental picture:

```
                 QUERY
                   │
                   ▼
             ┌───────────┐
             │ COLLECTION│
             └───────────┘
                   │
       ┌───────────┼───────────┐
       ↓           ↓           ↓
     Doc 1       Doc 2       Doc 3
       ↓           ↓           ↓
      check       check       check
       ...
```

Potentially expensive.

---

## 5. With an Index

Now create:

```js
db.students.createIndex({
    email: 1
})
```

MongoDB builds an index on:

```
email
```

Now conceptually:

```
QUERY
  ↓
INDEX
  ↓
email = "rahul@gmail.com"
  ↓
relevant document
```

Instead of:

```
10 million documents
       ↓
potentially inspect many/all
```

we have:

```
INDEX
  ↓
narrow down candidates
  ↓
document(s)
```

This index-assisted operation is represented in execution plans using:

```
IXSCAN
```

Meaning:

```
IX
 ↓
Index

SCAN
 ↓
Scan
```

So:

```
IXSCAN
=
Index Scan
```

> MongoDB's explain output uses `IXSCAN` for index scans, while a covered query can have an `IXSCAN` without a `FETCH` stage.

## 6. COLLSCAN vs IXSCAN

This is one of your first Unit IV must-know comparisons.

| COLLSCAN                                    | IXSCAN                                  |
|--------------------------------------------------|----------------------------------------------|
| Collection scan                                     | Index scan                                     |
| Searches collection documents                         | Searches index structure                         |
| Can examine many documents                              | Can narrow search using index                     |
| Often less efficient for selective indexed queries        | Often more efficient                                 |
| No useful index used                                         | Appropriate index used                                 |

Visual:

**COLLSCAN**

```
QUERY
 ↓
COLLECTION
 ↓
Doc → Doc → Doc → Doc → Doc
```

versus:

**IXSCAN**

```
QUERY
 ↓
INDEX
 ↓
Relevant keys
 ↓
Relevant documents
```

But here's an important mature understanding:

> Seeing `IXSCAN` does not automatically mean the query is optimal.

Why?

Because later we'll examine:

```
totalKeysExamined
totalDocsExamined
nReturned
executionTimeMillis
```

An index can exist and still be poorly chosen for a workload.

That's why Unit IV is about **performance**, not merely "create an index."

## 7. Why Doesn't MongoDB Just Index Everything?

Excellent question.

Imagine:

```
students
```

has:

```
10 million documents
```

And we create indexes on:

```
name
email
age
branch
cgpa
city
phone
address
skills
...
```

Sounds amazing, right?

More indexes = faster everything?

❌ **NO.**

Indexes have costs.

> MongoDB's current documentation explicitly notes that indexes can improve read performance but add storage and write-maintenance overhead because writes may need to update indexes too.

Think:

```
MORE INDEXES
     │
     ├──────────────→ potentially faster reads
     │
     ├──────────────→ more storage
     │
     └──────────────→ more work during writes
```

So indexing is a trade-off.

---

## 8. Read vs Write Trade-off

Suppose:

```
10,000,000 documents
```

and:

```
5 indexes
```

When you insert a document:

```
INSERT
  │
  ├── update collection
  │
  ├── update index 1
  │
  ├── update index 2
  │
  ├── update index 3
  │
  ├── update index 4
  │
  └── update index 5
```

So indexes can make reads faster while adding work to writes.

This is why MongoDB recommends creating indexes around actual/common query patterns, not indiscriminately.

## 10. What Exactly Is the Index Storing?

Suppose:

```
students
```

contains:

```json
{
    "name": "Rahul",
    "email": "rahul@gmail.com"
}
```

```json
{
    "name": "Priya",
    "email": "priya@gmail.com"
}
```

```json
{
    "name": "Arjun",
    "email": "arjun@gmail.com"
}
```

We create:

```js
db.students.createIndex({
    email: 1
})
```

Conceptually, MongoDB maintains something like:

```
EMAIL INDEX

arjun@gmail.com
      ↓
   document

priya@gmail.com
      ↓
   document

rahul@gmail.com
      ↓
   document
```

The exact internal implementation is more technical, but the important conceptual idea is:

> The index organizes indexed values so MongoDB can efficiently navigate toward corresponding documents.

> MongoDB's standard indexes use a B-tree structure.

---

## 11. 🧠 What is a B-tree?

Don't panic.

You're not expected to implement one here.

Think of a B-tree as a:

> balanced, organized search structure that lets the database navigate toward values efficiently instead of checking every value sequentially.

Very simplified:

```
                 50
              /      \
            25        75
          /   \      /   \
        10    40    60    90
```

Want:

```
60
```

You don't check:

```
10
25
40
50
...
```

You navigate:

```
50
 ↓
greater than 50
 ↓
75
 ↓
less than 75
 ↓
60
```

That's the intuition.

> MongoDB's standard indexes use B-tree structures, but you don't need to manually manage the tree.


---

## 13. What Does `1` Mean?

```
email: 1
```

means:

> Ascending index order.

And:

```
email: -1
```

means:

> Descending index order.

So:

```js
db.students.createIndex({
    email: 1
})
```

versus:

```js
db.students.createIndex({
    email: -1
})
```

### Don't overthink single-field direction.

For many equality lookups, either direction can support the lookup; direction becomes more important when index ordering interacts with sorting, especially with compound indexes. MongoDB documents this distinction explicitly.

We'll go deep into this in Part 2 and especially Part 3.

## 14. What Index Already Exists?

This is important.

MongoDB automatically creates an index on:

```
_id
```

for standard collections.

> MongoDB's documentation states that all collections have an index on `_id` by default.

So conceptually:

```
students

Indexes:
   ↓
_id_      ← automatically created
```

If we create:

```js
db.students.createIndex({
    email: 1
})
```

then:

```
students

Indexes:
   ├── _id_
   └── email_1
```

## 15. Why Does `_id` Need an Index?

Suppose:

```js
db.students.find({
    _id: ObjectId("...")

```

MongoDB needs to efficiently find that unique document.

The `_id` index helps.

Remember:

```
_id
 ↓
unique identity
 ↓
automatic unique index
```

So the `_id` index is not something you normally create yourself.

```
QUERY FREQUENCY
```

## 19. What Is Selectivity?

You already encountered this in Unit II, but Unit IV will make it much more important.

Suppose we have:

```
1,000,000 students
```

**Query A:**

```js
{
    email: "rahul@gmail.com"
}
```

Probably returns:

```
1 document
```

Very selective.

**Query B:**

```js
{
    branch: "CSE"
}
```

might return:

```
300,000 documents
```

Much less selective.

Selectivity means roughly:

> How effectively does a query narrow down the candidate documents.

Think:

```
1,000,000 documents
        ↓
email query
        ↓
1 document
```

Huge narrowing.

Versus:

```
1,000,000 documents
        ↓
branch = CSE
        ↓
300,000 documents
```

Much weaker narrowing.

This matters when deciding whether an index will be useful.

## 23. Index Types — Preview

Your syllabus specifically asks for:

```
INDEXES
   │
   ├── Single
   │
   ├── Compound
   │
   └── Text
```

Let's understand their broad purpose before we deep-dive.

### 🟢 Single-Field Index

One field:

```js
db.students.createIndex({
    email: 1
})
```

Think:

```
email
```

> MongoDB defines a single-field index as an index containing information from one field.

### 🔵 Compound Index

Multiple fields:

```js
db.students.createIndex({
    branch: 1,
    cgpa: -1
})
```

Think:

```
branch + cgpa
```

> Compound indexes contain multiple fields, and the order matters.

### 🟣 Text Index

For word-based text search:

```js
db.books.createIndex({
    title: "text"
})
```

Then:

```js
db.books.find({
    $text: {
        $search: "mongodb"
    }
})
```

> MongoDB text indexes support `$text` queries over indexed string content.

Don't confuse:

```
INDEX
```


> A structure that helps the database search efficiently.

**Query:**

> The request asking the database for data.

Example:

```js

    email: "rahul@gmail.com"
})
```

is the:

```
QUERY
```

while:

```js
db.students.createIndex({
    email: 1
})
```

creates the:

```
INDEX
```

Relationship:

```
QUERY
  ↓
Can an INDEX help?
  ↓
YES
  ↓
INDEX-assisted execution
```

## 25. Index vs Aggregation — Don't Mix Them

This is where the second half of Unit IV will eventually come in.

**Indexing:**

> "I need to FIND data efficiently."

**Aggregation:**

> "I need to PROCESS data and derive information."

**Example:**

**Indexing query**

> Find all CSE students.

```js

    branch: "CSE"
```


> What is the average CGPA of each branch?

Now we're not merely finding documents.

We're doing:

```

```

That's:


## 29. 🔥 PART 1 — WHAT YOU MUST REMEMBER

If I asked you right now:

**What is an index?**

> A separate data structure that helps MongoDB efficiently locate documents for supported queries.

**What is COLLSCAN?**

> A collection scan where MongoDB examines documents in the collection to satisfy a query.

**What is IXSCAN?**

> An index scan where MongoDB scans an applicable index to help satisfy a query.

**Why not index everything?**

> Indexes improve reads but consume storage and add maintenance overhead to writes and updates.

**What is `createIndex()`?**

```js
db.collection.createIndex({
    field: 1
})
```

**What does `1` mean?**

> Ascending index order.

**What does `-1` mean?**

> Descending index order.

**What index automatically exists?**

> The `_id` index.

**What does `explain()` do?**

> It provides information about how MongoDB plans and/or executes a query.
