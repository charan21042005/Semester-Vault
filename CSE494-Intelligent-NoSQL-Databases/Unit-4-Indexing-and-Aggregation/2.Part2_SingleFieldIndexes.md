## 1. First: What exactly is a Single-Field Index?

The name itself tells you:

> A single-field index is an index built on one field of a document.

For example, suppose we have:

```js
db.students.insertMany([
    { name: "Rahul", branch: "CSE", cgpa: 8.7 },
    { name: "Priya", branch: "ECE", cgpa: 9.1 },
    { name: "Arjun", branch: "CSE", cgpa: 7.8 },
    { name: "Sneha", branch: "EEE", cgpa: 8.9 }
])
```

Suppose our application frequently asks:

```js
db.students.find({ cgpa: 8.9 })
```

or:

```js
db.students.find({ cgpa: { $gte: 8.5 } })
```

Then we can create:

```js
db.students.createIndex({ cgpa: 1 })
```

Now MongoDB has a separate index structure based on only `cgpa`.

> MongoDB's documentation describes a single-field index as storing information from one field in each document. You can create these indexes on top-level fields or fields inside embedded documents.

---

## 2. Let's visualize it

Our collection might look like:

```
students collection

┌────┬────────┬────────┬──────┐
│ _id│ name   │ branch │ cgpa │
├────┼────────┼────────┼──────┤
│  1 │ Rahul  │ CSE    │ 8.7  │
│  2 │ Priya  │ ECE    │ 9.1  │
│  3 │ Arjun  │ CSE    │ 7.8  │
│  4 │ Sneha  │ EEE    │ 8.9  │
└────┴────────┴────────┴──────┘
```

Now:

```js
db.students.createIndex({ cgpa: 1 })
```

Conceptually, MongoDB maintains something like:

```
INDEX ON cgpa

7.8  → document 3
8.7  → document 1
8.9  → document 4
9.1  → document 2
```

So if we ask:

```
{ cgpa: 8.9 }
```

MongoDB can use the index to locate the relevant document rather than blindly checking every document.

That's the basic power of indexing.

---

## 3. Why do we specify `1`?

You've already seen:

```
{ cgpa: 1 }
```

and:

```
{ cgpa: -1 }
```

These indicate the index's sort direction:

| Value | Meaning    |
|---------|--------------|
| `1`       | Ascending      |
| `-1`      | Descending     |

So:

```js
db.students.createIndex({ cgpa: 1 })
```

means:

```
7.8
8.7
8.9
9.1
```

Conceptually ascending.

Whereas:

```js
db.students.createIndex({ cgpa: -1 })
```

is descending.

```
9.1
8.9
8.7
7.8
```

> MongoDB's single-field index syntax uses exactly this `1` / `-1` sort-order specification.

---

## 4. Important: Does `1` mean "index this field"?

This is a very common beginner misunderstanding.

You might think:

```
{ cgpa: 1 }
```

means:

> "Yes, index `cgpa`."

Technically, the field name tells MongoDB **what** to index.

The `1` tells it the **ordering direction**.

So:

```
{ cgpa: 1 }
```

means:

> Create an index on `cgpa`, ascending.

And:

```
{ cgpa: -1 }
```

means:

> Create an index on `cgpa`, descending.

---

## 5. Creating a Single-Field Index

Basic syntax:

```js
db.collection.createIndex({ field: 1 })
```

Example:

```js
db.students.createIndex({ cgpa: 1 })
```

Let's break it down.

**`db`**

> Current database.

**`students`**

> Collection.

**`createIndex()`**

> MongoDB method for creating an index.

**`{ cgpa: 1 }`**

> The index specification.

So the entire command means:

> "Create an ascending index on the `cgpa` field of the `students` collection."

## 6. Another realistic example

Imagine an employee database:

```json
{
    "employeeId": 101,
    "name": "Aman",
    "department": "Engineering",
    "salary": 75000
}
```

If HR constantly searches:

```js
db.employees.find({ employeeId: 101 })
```

we could create:

```js
db.employees.createIndex({ employeeId: 1 })
```

Now the database has an index specifically designed to help with queries involving `employeeId`.

> MongoDB's own example recommends a single-field index when an application repeatedly queries the same field.

## 7. When should I create a single-field index?

This is more important than memorizing the syntax.

Don't think:

> "I have a field, therefore I need an index."

Instead think:

> "My application frequently queries this field. Would an index help?"

For example:

```js
db.users.find({ email: "abc@gmail.com" })
```

Suppose this query runs thousands of times.

Then:

```js
db.users.createIndex({ email: 1 })
```

makes sense.

### Example: E-commerce

Suppose:

```js
db.products.find({ category: "Laptop" })
```

is executed constantly.

Potential index:

```js
db.products.createIndex({ category: 1 })
```

### Example: University

Frequent query:

```js
db.students.find({ rollNo: 20240123 })
```

Index:

```js
db.students.createIndex({ rollNo: 1 })
```

### Example: Banking

Frequent query:

```js
db.accounts.find({ accountNumber: "AC102938" })
```

Index:

```js
db.accounts.createIndex({ accountNumber: 1 })
```

The principle is always:

```
FREQUENT QUERY
      ↓
IDENTIFY SEARCH FIELD
      ↓
CREATE INDEX
      ↓
QUERY CAN POTENTIALLY USE INDEX
```

## 8. What happens without the index?

Suppose:

```
1,000,000 students
```

and we ask:

```js
db.students.find({ rollNo: 500123 })
```

Without a suitable index, MongoDB may need to inspect many documents.

Conceptually:

```
Query
 ↓
Student 1? ❌
Student 2? ❌
Student 3? ❌
Student 4? ❌
...
Student 500123? ✅
...
```

This is the kind of execution associated with:

```
COLLSCAN
```

## 9. With the index

Suppose:

```js
db.students.createIndex({ rollNo: 1 })
```

Now MongoDB can use the index to narrow down the relevant location.

Conceptually:

```
Query
 ↓
rollNo index
 ↓
500123
 ↓
matching document
```

Execution may involve:

```
IXSCAN
```

instead of:

```
COLLSCAN
```

But remember the golden rule from Part 1:

> Creating an index does NOT guarantee MongoDB will use it for every query.

We verify actual behavior with:

```
explain()
```

We'll go deep into that later.

## 10. The `_id` index — very important

There's one special index you don't normally have to create yourself.

MongoDB automatically creates a unique index on:

```
_id
```

for collections.

So when you create:

```json
{
    "_id": 101,
    "name": "Rahul"
}
```

MongoDB maintains the `_id` index.

Conceptually:

```
_id index

101 → document
102 → document
103 → document
```

You don't need:

```js
db.students.createIndex({ _id: 1 })
```

as a normal step.

## 12. Index names

When you create:

```js
db.students.createIndex({ cgpa: 1 })
```

MongoDB can generate a name such as:

```
cgpa_1
```

Similarly:

```js
db.students.createIndex({ cgpa: -1 })
```

might have:

```
cgpa_-1
```

You can also explicitly specify a name:

```js
db.students.createIndex(
    { cgpa: 1 },
    { name: "student_cgpa_index" }
)
```

Then:

```js
db.students.getIndexes()
```

can show:

```
student_cgpa_index
```

This becomes useful when managing indexes.

## 13. Removing a single-field index

Suppose we created:

```js
db.students.createIndex({ cgpa: 1 })
```

and its name is:

```
cgpa_1
```

We can remove it:

```js
db.students.dropIndex("cgpa_1")
```

Or, depending on the command form, specify the index specification.

Then:

```js
db.students.getIndexes()
```

can confirm what's left.

Remember:

```
createIndex()
      ↓
index exists

dropIndex()
      ↓
that index is removed
```

This is where things become interesting because MongoDB supports indexing fields inside embedded documents too.


```
 city

```
```
"address.city"
```

## 16. Single-field index on arrays — Multikey Index

Now we reach a very important concept.

Suppose:

```json
{
    "name": "Rahul",
    "skills": ["Python", "MongoDB", "Java"]
}
```

Notice:

```
skills = ARRAY
```

If we create:

```js
db.students.createIndex({
    skills: 1
})
```

> MongoDB automatically treats this as a multikey index because the indexed field contains an array. You don't manually say "multikey" when creating it.

---

## 17. Why "multikey"?

Imagine these documents:

```json
{ "name": "Rahul", "skills": ["Python", "MongoDB"] }
```

```json
{ "name": "Priya", "skills": ["Java", "MongoDB"] }
```

```json
{ "name": "Arjun", "skills": ["C++", "Python"] }
```

Index:

```js
db.students.createIndex({ skills: 1 })
```

Conceptually, the index can contain entries like:

```
C++
 ↓
Arjun

Java
 ↓
Priya

MongoDB
 ↓
Rahul
Priya

Python
 ↓
Rahul
Arjun
```

Each distinct array value can produce an index entry pointing back to the document. That's why a single document can have multiple entries in a multikey index.

---

## 18. Querying that array

Now:

```js
db.students.find({
    skills: "MongoDB"
})
```

can find:

```
Rahul
Priya
```

because `"MongoDB"` exists in their `skills` arrays.

The multikey index can improve queries against array fields.

---

## 19. Another array example

Suppose:

```json
{
    "name": "Rahul",
    "test_scores": [88, 97]
}
```

and:

```json
{
    "name": "Wei",
    "test_scores": [62, 73]
}
```

and:

```json
{
    "name": "Jacob",
    "test_scores": [92, 89]
}
```

Create:

```js
db.students.createIndex({
    test_scores: 1
})
```

MongoDB automatically creates a multikey index because `test_scores` is an array.

Conceptually:

```
62 → Wei
73 → Wei

88 → Rahul
97 → Rahul

89 → Jacob
92 → Jacob
```

Now a query such as:

```js
db.students.find({
    test_scores: { $elemMatch: { $gt: 90 } }
})
```

can use the multikey index to efficiently find students having a score greater than 90.

## 20. Embedded documents inside arrays

This is another situation you'll see.

Suppose:

```json
{
    "item": "T-shirt",
    "stock": [
        {
            "size": "small",
            "quantity": 8
        },
        {
            "size": "large",
            "quantity": 10
        }
    ]
}
```

Suppose we frequently ask:

> Which products have some stock quantity below 5?

We can index:

```js
db.inventory.createIndex({
    "stock.quantity": 1
})
```

Because `stock` is an array, this becomes a multikey index. MongoDB supports indexing embedded fields inside arrays this way.

Then:

```js
db.inventory.find({
    "stock.quantity": { $lt: 5 }
})
```

can use that index.

## 22. Very important distinction

Don't memorize:

> "Array index = separate index type I have to create."

No.

You still write:

```js
db.students.createIndex({
    skills: 1
})
```

MongoDB determines that the indexed field contains arrays and maintains it as a multikey index.

So:

```
You:
createIndex({ skills: 1 })

MongoDB:
"Oh, skills contains arrays."
          ↓
maintains multikey index
```

## 23. Selectivity — let's revisit it properly

Remember selectivity from Part 1?

Let's make it practical.

Suppose we have:

```

```

```

```


That's not very selective.

Now:

```

```

## 26. One field = one index?

Here's a subtle thing.

Suppose you have:

```json
{
    "name": "Rahul",
    "branch": "CSE",
    "cgpa": 8.7
}
```

You could create:

```js
db.students.createIndex({ name: 1 })
```

and separately:

```js
db.students.createIndex({ branch: 1 })
```

and:

```js
db.students.createIndex({ cgpa: 1 })
```

These are three separate indexes.

Conceptually:

```
students
│
├── name index
├── branch index
└── cgpa index
```

But don't immediately conclude:

> "More indexes = better performance."

Absolutely not. 😭

Every index has costs.

---

## 27. Why not index every field?

Because indexes aren't free.

They require:

**Storage**

> Indexes occupy disk/memory resources.

**Maintenance**

When you insert:

```
{ cgpa: 8.7 }
```

MongoDB has to maintain the relevant indexes too.

When you update:

```
cgpa
```

the relevant index may also need maintenance.

Therefore:

```
MORE INDEXES
      ↓
potentially faster reads
      +
more storage
      +
more write/update/delete maintenance
```

> MongoDB explicitly notes that indexes improve supported query performance but introduce write overhead, so indexing should be driven by actual query patterns.
