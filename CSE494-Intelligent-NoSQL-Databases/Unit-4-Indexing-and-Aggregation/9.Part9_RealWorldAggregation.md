# 🧠 CASE STUDY 1 — UNIVERSITY ANALYTICS

Let's start with something familiar.

Suppose we have:

```json
{
    "name": "Rahul",
    "branch": "CSE",
    "year": 4,
    "cgpa": 8.7,
    "skills": ["Python", "MongoDB", "C++"]
}
```

```json
{
    "name": "Priya",
    "branch": "ECE",
    "year": 4,
    "cgpa": 9.1,
    "skills": ["Python", "Java"]
}
```

```json
{
    "name": "Arjun",
    "branch": "CSE",
    "year": 3,
    "cgpa": 7.8,
    "skills": ["C++", "MongoDB"]
}
```

```json
{
    "name": "Sneha",
    "branch": "CSE",
    "year": 4,
    "cgpa": 8.9,
    "skills": ["Python", "MongoDB"]
}
```

## Question 1

> Find the average CGPA of each branch.

Translate:

```
each branch
    ↓
$group

average CGPA
    ↓
$avg
```

Pipeline:

```js
db.students.aggregate([
    {
        $group: {
            _id: "$branch",

            averageCgpa: {
                $avg: "$cgpa"
            }
        }
    }
])
```

Output:

```
CSE → 8.466...
ECE → 9.1
```

Simple.

## Question 2

> Find the number of students in each branch.

Translate:

```
branch
 ↓
$group

count
 ↓
$sum: 1
```

```js
db.students.aggregate([
    {
        $group: {
            _id: "$branch",

            studentCount: {
                $sum: 1
            }
        }
    }
])
```

Output:

```
CSE → 3
ECE → 1
```

## Question 3 — Top branch by average CGPA

Now:

> Which branch has the highest average CGPA?

We need:

```
GROUP
 ↓
AVERAGE
 ↓
SORT
 ↓
TOP 1
```

```js
db.students.aggregate([
    {
        $group: {
            _id: "$branch",

            averageCgpa: {
                $avg: "$cgpa"
            }
        }
    },

    {
        $sort: {
            averageCgpa: -1
        }
    },

    {
        $limit: 1
    }
])
```

Result:

```json
{
    "_id": "ECE",
    "averageCgpa": 9.1
}
```

**Mental translation:**

> "highest average" = calculate average → descending sort → limit 1.

## Question 4 — Fourth-year branch analytics

Question:

> Among fourth-year students, find the number of students and average CGPA for each branch.

Translate carefully.

```
"Among fourth-year"
$match

"each branch"
$group

"number"
$sum: 1

"average CGPA"
$avg
```

Code:

```js
db.students.aggregate([
    {
        $match: {
            year: 4
        }
    },

    {
        $group: {
            _id: "$branch",

            studentCount: {
                $sum: 1
            },

            averageCgpa: {
                $avg: "$cgpa"
            }
        }
    }
])
```

This is already a realistic college analytics query.

## Question 5 — Most popular skill

Now it becomes interesting.

Question:

> Which skill is possessed by the largest number of students?

We have:

```
Rahul  → Python, MongoDB, C++
Priya  → Python, Java
Arjun  → C++, MongoDB
Sneha  → Python, MongoDB
```

We cannot directly count the array as a whole.

We first need:

```
skills[]
   ↓
$unwind
```

Then:

```
individual skill
   ↓
$group
   ↓
count
```

Then:

```
$sort
   ↓
$limit
```

Full pipeline:

```js
db.students.aggregate([
    {
        $unwind: "$skills"
    },

    {
        $group: {
            _id: "$skills",

            studentCount: {
                $sum: 1
            }
        }
    },

    {
        $sort: {
            studentCount: -1
        }
    },

    {
        $limit: 1
    }
])
```

Let's dry-run.

After `$unwind`:

```
Rahul → Python
Rahul → MongoDB
Rahul → C++

Priya → Python
Priya → Java

Arjun → C++
Arjun → MongoDB

Sneha → Python
Sneha → MongoDB
```

Group:

```
Python   → 3
MongoDB  → 3
C++      → 2
Java     → 1
```

Sort descending:

```
Python   → 3
MongoDB  → 3
C++      → 2
Java     → 1
```

`$limit: 1` returns one of the tied top results.

**Important practical point:**

> If ties matter, don't blindly use `$limit: 1`. The question might instead require returning all top ties, which needs a more advanced design.

Now we're entering the classic aggregation territory.

Suppose an order looks like:

```json
{
    "orderId": 1001,

    "customer": "Rahul",

    "status": "completed",

    "items": [
        {
            "product": "Laptop",
            "category": "Electronics",
            "price": 80000,
            "quantity": 1
        },

        {
            "product": "Mouse",
            "category": "Electronics",
            "price": 1000,
            "quantity": 2
        }
    ]
}
```

Another:

```json
{
    "orderId": 1002,

    "customer": "Priya",

    "status": "completed",

    "items": [
        {
            "product": "Keyboard",
            "category": "Electronics",
            "price": 2000,
            "quantity": 1
        }
    ]
}
```

## Question 1 — Total revenue

> Calculate total revenue from all order items.

We have:

```
price × quantity
```

So:

```
$unwind
 ↓
$set
 ↓
$group
 ↓
$sum
```

Pipeline:

```js
db.orders.aggregate([
    {
        $unwind: "$items"
    },

    {
        $set: {
            itemRevenue: {
                $multiply: [
                    "$items.price",
                    "$items.quantity"
                ]
            }
        }
    },

    {
        $group: {
            _id: null,

            totalRevenue: {
                $sum: "$itemRevenue"
            }
        }
    }
])
```

Let's calculate:

```
Laptop:
80000 × 1 = 80000

Mouse:
1000 × 2 = 2000

Keyboard:
2000 × 1 = 2000

Total:

80000 + 2000 + 2000
= 84000
```

Result:

```json
{
    "_id": null,
    "totalRevenue": 84000
}
```

Notice:

```
_id: null
```

because we want one overall total, not separate totals.

## Question 2 — Revenue by product

Now:

> Find total revenue for each product.

Instead of:

```
_id: null
```

we group by:

```
_id: "$items.product"
```

```js
db.orders.aggregate([
    {
        $unwind: "$items"
    },

    {
        $set: {
            itemRevenue: {
                $multiply: [
                    "$items.price",
                    "$items.quantity"
                ]
            }
        }
    },

    {
        $group: {
            _id: "$items.product",

            totalRevenue: {
                $sum: "$itemRevenue"
            }
        }
    },

    {
        $sort: {
            totalRevenue: -1
        }
    }
])
```

Output:

```
Laptop    → 80000
Mouse     → 2000
Keyboard  → 2000
```

## Question 3 — Top 2 products

Simply add:

```js
{
    $limit: 2
}
```

So:

```js
db.orders.aggregate([
    { $unwind: "$items" },

    {
        $set: {
            itemRevenue: {
                $multiply: [
                    "$items.price",
                    "$items.quantity"
                ]
            }
        }
    },

    {
        $group: {
            _id: "$items.product",
            totalRevenue: { $sum: "$itemRevenue" }
        }
    },

    {
        $sort: {
            totalRevenue: -1
        }
    },

    {
        $limit: 2
    }
])
```

This pattern is worth memorizing:

```
ARRAY
 ↓
$unwind
 ↓
CALCULATE
 ↓
$set
 ↓
GROUP
 ↓
$group
 ↓
ORDER
 ↓
$sort
 ↓
TOP N
 ↓
$limit
```

## Question 4 — Revenue by category

Now change only the grouping key.

Instead of:

```
_id: "$items.product"
```

we use:

```
_id: "$items.category"
```

```js
db.orders.aggregate([
    { $unwind: "$items" },

    {
        $set: {
            itemRevenue: {
                $multiply: [
                    "$items.price",
                    "$items.quantity"
                ]
            }
        }
    },

    {
        $group: {

```

Now we're doing:

```
GROUP BY CATEGORY
```

instead of:

```
GROUP BY PRODUCT
```

That's an important realization:

> A large part of aggregation problem solving is simply identifying the correct grouping key.

```js
db.orders.aggregate([
```

# 🧠 CASE STUDY 3 — FOOD DELIVERY

Now let's build a slightly more realistic model.

**Orders:**

```json
{
    "orderId": 5001,

    "customerId": 101,

    "restaurantId": 501,

    "status": "delivered",

    "items": [
        {
            "name": "Chicken Biryani",
            "price": 250,
            "quantity": 2
        },
        {
            "name": "Coke",
            "price": 50,
            "quantity": 2
        }
    ]
}
```

And separate restaurants:

```json
{
    "_id": 501,
    "name": "Spice House",
    "city": "Amritsar"
}
```

### Question:

> Find the total revenue generated by each restaurant.

Now we have two possibilities.

We could already have restaurant name in the order.

But suppose the order only stores:

```
restaurantId
```

Then we need:

```
orders
 ↓
$lookup
 ↓
restaurants
```

But first, we need to calculate order revenue.

### Step 1 — `$unwind`

```js
{
    $unwind: "$items"
}
```

Now each item becomes individually processable.

### Step 2 — Calculate item total

```js
{
    $set: {
        itemTotal: {
            $multiply: [
                "$items.price",
                "$items.quantity"
            ]
        }
    }
}
```

### Step 3 — Group by restaurant ID

```js
{
    $group: {
        _id: "$restaurantId",

        totalRevenue: {
            $sum: "$itemTotal"
        }
    }
}
```

Now we have:

```
501 → 1250
502 → 900
503 → 2100
```

But the question asks for restaurant names.

So we need `$lookup`.

### Step 4 — `$lookup`

```js
{
    $lookup: {
        from: "restaurants",

        localField: "_id",

        foreignField: "_id",

        as: "restaurant"
    }
}
```

Now:

```json
{
    "_id": 501,

    "totalRevenue": 1250,

    "restaurant": [
        {
            "_id": 501,
            "name": "Spice House",
            "city": "Amritsar"
        }
    ]
}
```

Remember:

```
$lookup → array
```

### Step 5 — `$unwind`

```js
{
    $unwind: "$restaurant"
}
```

Now:

```json
{
    "_id": 501,

    "totalRevenue": 1250,

    "restaurant": {
        "_id": 501,
        "name": "Spice House",
        "city": "Amritsar"
    }
}
```

### Step 6 — `$project`

We only want:

```
restaurant name
revenue
```

So:

```js
{
    $project: {
        _id: 0,

        restaurant: "$restaurant.name",

        totalRevenue: 1
    }
}
```

Final:

```json
{
    "restaurant": "Spice House",
    "totalRevenue": 1250
}
```

### FULL FOOD DELIVERY PIPELINE

```js
db.orders.aggregate([
    {
        $match: {
            status: "delivered"
        }
    },

    {
        $unwind: "$items"
```

```js
db.movies.aggregate([
```

## Question 4 — Top-rated movie each year

This is more interesting.

Question:

> Find the highest-rated movie for each year.

We need:

```
SORT rating descending
      ↓
GROUP year
      ↓
FIRST movie
```

Pipeline:

```js
db.movies.aggregate([
    {
        $sort: {
            rating: -1
        }
    },

    {
        $group: {
            _id: "$year",

            topMovie: {
                $first: "$title"
            },

            highestRating: {
                $first: "$rating"
            }
        }
    }
])
```

This is where `$first` finally becomes meaningful.

Because we deliberately created the ordering first.

# 🧠 THE MOST IMPORTANT AGGREGATION PATTERNS

Mate, let's now compress everything we've learned into reusable patterns.

**Pattern 1 — Simple filtering**

```
$match
```

Question words:

```
only, where, among, having condition, completed, fourth-year, active
```

**Pattern 2 — Summary by category**

```
$group
```

Question words:

```
per branch, by category, by city, by product
```

**Pattern 3 — Count**

```
$group
+
$sum: 1
```

Question words:

```
how many, count
```

**Pattern 4 — Average**

```
$group
+
$avg
```

Question words:

```
average, mean
```

**Pattern 5 — Total**

```
$group
+
$sum: "$field"
```

Question words:

```
total, sum, revenue, sales
```

**Pattern 6 — Highest/lowest**

```
$max
$min
```

or, when you need the document associated with the max/min, often:

```
$sort
↓
$group
↓
$first
```

**Pattern 7 — Array analysis**

```
$unwind
↓
$group
```

Question words:

```
each item, each skill, each tag, each category in an array
```

**Pattern 8 — Top N**

```
$sort
↓
$limit
```

**Pattern 9 — Calculate before grouping**

```
$set
↓
$group
```

Example:

```
price × quantity
      ↓
itemRevenue
      ↓
$group
```

**Pattern 10 — Reference another collection**

```
$lookup
↓
$unwind
↓
$project
```

Potentially:

```
$lookup
↓
$unwind
↓
$group
```

depending on the question.

> MongoDB's `$lookup` performs a left outer join and adds matching foreign documents as an array; MongoDB also recommends indexing the foreign join field for equality-match `$lookup` performance.

# 🔥 NOW — THE MEGA QUESTION

Let's combine almost everything.

### Problem

> From all delivered orders, find the top 3 restaurants by total revenue. Each order contains an array of items, and restaurant information is stored separately.

Let's not code immediately.

Think.

**Step 1 — "delivered orders"**

```
$match
```

**Step 2 — "array of items"**

```
$unwind
```

**Step 3 — revenue**

```
price × quantity
```

Therefore:

```
$set
```

**Step 4 — "total revenue per restaurant"**

```
$group
```

with:

```
_id: "$restaurantId"
```

and:

```
$sum: "$itemTotal"
```

**Step 5 — restaurant information is separate**

```
$lookup
```

**Step 6 — lookup produces an array**

```
$unwind
```

**Step 7 — highest revenue**

```
$sort
```

**Step 8 — top 3**

```
$limit
```

### Complete pipeline

```js
db.orders.aggregate([
    {
        $match: {
            status: "delivered"
        }
    },

    {
        $unwind: "$items"
    },

    {
        $set: {
            itemTotal: {
                $multiply: [
                    "$items.price",
                    "$items.quantity"
                ]
            }
        }
    },

    {
        $group: {
            _id: "$restaurantId",

            totalRevenue: {
                $sum: "$itemTotal"
            }
        }
    },

    {
        $lookup: {
            from: "restaurants",

            localField: "_id",

            foreignField: "_id",

            as: "restaurant"
        }
    },

    {
        $unwind: "$restaurant"
    },

    {
        $sort: {
            totalRevenue: -1
        }
    },

    {
        $limit: 3
    },

    {
        $project: {
            _id: 0,

            restaurant: "$restaurant.name",

            totalRevenue: 1
        }
    }
])
```

That is a proper real-world MongoDB aggregation pipeline.

Now one more connection.

Suppose:

```js
{
    $match: {
        status: "delivered"
    }
}
```

```
orders.restaurantId
        ↓
$lookup
        ↓
restaurants._id
```

So:

```
INDEX
 ↓
FIND / FILTER
 ↓
AGGREGATION
 ↓
TRANSFORM
 ↓
GROUP
 ↓
JOIN
 ↓
ANALYZE
 ↓
REPORT
```

# 🚨 AGGREGATION PRACTICAL EXAM TRAPS

### Trap 1 — Forgetting `$unwind`

You have:

```
items: [...]
```

and question asks:

> "per item/product"

Usually think:

```
$unwind
```

before grouping.

### Trap 2 — Wrong grouping key

Question:

> Revenue per product

Wrong:

```
_id: "$category"
```

Correct:

```
_id: "$items.product"
```

Always ask:

> "Per WHAT?"

That tells you the `_id` of `$group`.

### Trap 3 — Counting quantities incorrectly

If:

```
quantity: 5
```

then:

```
$unwind
```

doesn't create five documents.

You still need:

```
price × quantity
```

if calculating revenue.

### Trap 4 — `$lookup` output is an array

Remember:

```
$lookup
 ↓
array
```

If you need one embedded object:

```
$unwind
```

### Trap 5 — `$first` without `$sort`

If question says:

> highest-rated movie per year

Don't do:

```
$group
↓
$first
```

blindly.

Think:

```
$sort rating DESC
↓
$group
↓
$first
```

### Trap 6 — `$group` doesn't sort

After:

```
$group
```

if you want:

```
highest → lowest
```

you still need:

```
$sort
```

### Trap 7 — `$limit` placement

Top 5:

```
$sort
↓
$limit
```

not generally:

```
$limit
↓
$sort
```
