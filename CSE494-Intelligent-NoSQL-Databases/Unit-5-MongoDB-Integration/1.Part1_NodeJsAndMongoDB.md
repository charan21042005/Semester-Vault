## 1. What is a driver?

Forget MongoDB for a second.

Imagine you want to talk to a person who speaks only Japanese. You speak English. You need a **translator**.

```
YOU (English)  →  TRANSLATOR  →  PERSON (Japanese)
```

Your program speaks JavaScript (or Python). MongoDB speaks its own **wire protocol** (binary messages in BSON).

A **driver** is the translator:

```
YOUR CODE (JavaScript)  →  DRIVER  →  MONGODB (wire protocol + BSON)
```

> A MongoDB driver is a library that lets application code connect to a MongoDB deployment and perform operations such as inserting, querying, updating and deleting documents.

So:

```
Driver = library that lets your program talk to MongoDB
```

MongoDB provides official drivers for many languages. Your syllabus asks for two ecosystems:

```
Node.js  → official "mongodb" driver  (+ Mongoose on top)
Python   → official "PyMongo" driver
```

Memorize this picture. It is the base of everything in Unit V.

```
└─────────────────────────────┘
```

Every Unit V sentence fits into one of these three layers.

## 4. Node.js — only what you need

You don't need to be a Node expert. You need five ideas.

### 4.1 What is Node.js?

> Node.js is a runtime that lets you run JavaScript outside the browser — on your computer or a server.

Check installation:

```bash
node -v
npm -v
```

If both print version numbers, you're ready.

### 4.2 What is npm?

> npm (Node Package Manager) downloads and manages libraries (packages) for your project.

Think:

```
npm = app store for JavaScript libraries
```

### 4.3 What is `package.json`?

It is your project's identity card: name, version, dependencies.

Create a project:

```bash
mkdir student-app
cd student-app
npm init -y
```

`npm init -y` generates a `package.json` with defaults.

### 4.4 Modules: CommonJS vs ES Modules

Node supports two styles.

**CommonJS** (older, still very common):

```js
const { MongoClient } = require("mongodb");
```

**ES Modules** (modern):

```js
import { MongoClient } from "mongodb";
```

To use `import`, add this to `package.json`:

```json
{
    "type": "module"
}
```

For your notes and practicals, we'll use **ES Modules** (`import`) with files ending in `.js` and `"type": "module"` set. If your college lab uses `require`, simply swap the first line — everything else is identical.

```
CommonJS:   const x = require("pkg")
ES Module:  import x from "pkg"
```

### 4.5 Asynchronous code — THE most important Node idea

Database calls take time (network + disk). Node does not freeze while waiting; it uses **asynchronous** programming.

Old way: callbacks. Then: Promises. Now: **async/await**.

```js
// Promise style
students.find({}).toArray().then(result => console.log(result));

// async/await style (cleaner)
const result = await students.find({}).toArray();
console.log(result);
```

Rules of `async/await`:

```
1. A function that uses await must be declared async.
2. await pauses THAT function until the Promise finishes.
3. Wrap awaited code in try/catch to handle errors.
4. Forgetting await = you get a Promise object, not data.  🚨
```

Example:

```js
async function showStudents() {
    const result = await students.find({}).toArray();
    console.log(result);
}
```

Modern Node ES modules also allow **top-level await** (using `await` outside a function in a `.js` file with `"type": "module"`). We'll use that for short scripts.

> MongoDB's Node.js driver is promise-based; its operations return Promises, so `await` is the standard way to use it.

## 6. The connection string (URI)

To connect, the driver needs to know **where** MongoDB is. That address is the **connection string**.

### 6.1 Local MongoDB

```
mongodb://localhost:27017
```

Parts:

```
mongodb://        → protocol
localhost         → host (your own machine)
27017             → default MongoDB port
```

With a database name and options:

```
mongodb://localhost:27017/collegeDB
```

### 6.2 MongoDB Atlas (cloud)

Atlas gives you something like:

```
mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
```

Breakdown:

```
mongodb+srv://   → use DNS SRV lookup to find all cluster servers
<username>       → database user
<password>       → that user's password
cluster0.xxxxx.mongodb.net → your cluster address
?retryWrites=true&w=majority → options
```

> `mongodb+srv` URIs use DNS to discover the cluster's hosts, so you don't list each server manually.

### 6.3 Local vs Atlas

| Feature              | Local `mongod`              | Atlas                          |
|--------------------------|---------------------------------|------------------------------------|
| Where it runs               | Your computer                       | MongoDB's cloud                       |
| URI prefix                    | `mongodb://`                          | `mongodb+srv://`                        |
| Setup                           | Install MongoDB yourself                | Create free cluster online                |
| Authentication                    | Often off in dev                          | Always on                                   |
| Network access                      | Local only                                  | You must allow your IP address                |

🚨 **Special characters in passwords** (like `@`, `:`, `/`) must be URL-encoded in the URI (for example `@` → `%40`), or the connection fails in confusing ways.

## 7. Never hard-code secrets 🔐

Bad:

```js
const uri = "mongodb+srv://admin:MyPassword123@cluster0.mongodb.net";
```

If this file goes to GitHub, your database is public.

Good: put it in a `.env` file.

**`.env`**

```
MONGODB_URI=mongodb://localhost:27017
DB_NAME=collegeDB
```

**`.gitignore`**

```
node_modules
.env
```

Load it in code:

```js
import "dotenv/config";

const uri = process.env.MONGODB_URI;
const dbName = process.env.DB_NAME;
```

```
.env file → process.env → your code
```

Rule: **`.env` never goes to Git.**

## 8. `MongoClient` — the connection object

```js
import { MongoClient } from "mongodb";

const client = new MongoClient(uri);
```

This only **creates** the client object. It does not necessarily connect yet.

Then:

```js
await client.connect();
```

Then pick a database and a collection:

```js
const db = client.db("collegeDB");
const students = db.collection("students");
```

Finally, when completely finished:

```js
await client.close();
```

Memory chain:

```
MongoClient  →  db()  →  collection()  →  operations
   client        db       students        insertOne / find ...
```

Compare with mongosh:

```
mongosh:  use collegeDB   →   db.students.find()
Node:     client.db("collegeDB")  →  .collection("students").find()
```

> In recent Node.js driver versions, calling `connect()` explicitly is optional, because the client connects automatically on first operation. Explicit `connect()` is still good practice for scripts because it fails early if the URI is wrong.

## 9. Your first connection test — the ping

Create `ping.js`:

```js
import "dotenv/config";
import { MongoClient } from "mongodb";

const client = new MongoClient(process.env.MONGODB_URI);

try {
    await client.connect();
    await client.db("admin").command({ ping: 1 });
    console.log("✅ Connected to MongoDB");
} catch (err) {
    console.error("❌ Connection failed:", err.message);
} finally {
    await client.close();
}
```

Run:

```bash
node ping.js
```

Expected:

```
✅ Connected to MongoDB
```

### Dry run

```
new MongoClient(uri)      → object created
client.connect()          → opens connection(s)
command({ ping: 1 })      → tiny "are you alive?" request
console.log(...)          → success message
finally → client.close()  → always releases connection
```

### Why `try / catch / finally`?

```
try      → run risky code (network!)
catch    → handle the failure (wrong password, server off)
finally  → ALWAYS run: close the connection
```

## 10. Connection pooling — a very important idea

Opening a network connection is expensive. Imagine every web request opening and closing a new connection to MongoDB:

```
Request 1 → connect → query → close
Request 2 → connect → query → close
Request 3 → connect → query → close
(slow and wasteful)
```

Instead, the driver keeps a **pool** of ready connections:

```
          ┌──────────────── POOL ────────────────┐
Request 1 → │ conn A │ conn B │ conn C │ conn D │ ... → MongoDB
Request 2 →     (reused again and again)
```

> The MongoDB drivers maintain a connection pool for each client, reusing connections across operations rather than opening a new one every time.

### The golden rule

```
Create ONE MongoClient per application.
Reuse it everywhere.
Close it only when the app shuts down.
```

🚨 Beginner trap: creating `new MongoClient()` **inside** every route/function. This floods MongoDB with connections.

Good structure — a small shared file `db.js`:

```js
import "dotenv/config";
import { MongoClient } from "mongodb";

const client = new MongoClient(process.env.MONGODB_URI);
let db;

export async function getDb() {
    if (!db) {
        await client.connect();
        db = client.db(process.env.DB_NAME);
    }
    return db;
}

export async function closeDb() {
    await client.close();
    db = undefined;
}
```

Now any file can do:

```js
import { getDb } from "./db.js";
const db = await getDb();
```

## 11. Documents in JavaScript

A MongoDB document and a JavaScript object look almost identical.

```js
const student = {
    name: "Rahul",
    branch: "CSE",
    cgpa: 8.7,
    skills: ["Python", "MongoDB"]
};
```

That is **why MongoDB feels natural in JavaScript** — BSON/JSON-like documents map to JS objects.

```
JS object  ⇄  BSON document  ⇄  stored in MongoDB
```

| MongoDB (BSON) type | JavaScript value                    |
|--------------------------|-----------------------------------------|
| String                      | `string`                                    |
| Int32 / Double                | `number`                                      |
| Boolean                         | `boolean`                                       |
| Array                             | `array`                                           |
| Embedded document                   | `object`                                            |
| Date                                  | `Date`                                                |
| ObjectId                                | `ObjectId` (from the driver)                           |
| null                                      | `null`                                                   |

## 12. `ObjectId` in code

Every document gets an `_id`. If you don't give one, MongoDB generates an `ObjectId`.

```js
import { ObjectId } from "mongodb";

const id = new ObjectId();            // a brand new id
console.log(id.toString());           // "6650f1a2b3c4d5e6f7a8b9c0" (24 hex chars)
```

Finding by id — a super common trap:

```js
// ❌ WRONG: _id is an ObjectId, not a string
await students.findOne({ _id: "6650f1a2b3c4d5e6f7a8b9c0" });

// ✅ RIGHT: convert the string first
await students.findOne({ _id: new ObjectId("6650f1a2b3c4d5e6f7a8b9c0") });
```

```
String "6650..."   ≠   ObjectId("6650...")
```

If the string isn't a valid 24-hex-character id, `new ObjectId(str)` throws an error — handle it.

## 13. First complete script — insert then read

Create `first.js`:

```js
import { getDb, closeDb } from "./db.js";

try {
    const db = await getDb();
    const students = db.collection("students");

    // CREATE
    const result = await students.insertOne({
        name: "Rahul",
        branch: "CSE",
        cgpa: 8.7
    });
    console.log("Inserted _id:", result.insertedId);

    // READ
    const found = await students.findOne({ name: "Rahul" });
    console.log("Found:", found);
} catch (err) {
    console.error("Error:", err.message);
} finally {
    await closeDb();
}
```

Run:

```bash
node first.js
```

Output (conceptually):

```
Inserted _id: new ObjectId('6650f1a2b3c4d5e6f7a8b9c0')
Found: {
  _id: new ObjectId('6650f1a2b3c4d5e6f7a8b9c0'),
  name: 'Rahul',
  branch: 'CSE',
  cgpa: 8.7
}
```

### Dry run

```
getDb()                    → client connected, db handle returned
db.collection("students")  → collection handle (created lazily on first write)
insertOne({...})           → document written; result.insertedId available

closeDb()                  → pool closed
```

Important facts:

```
insertOne() → returns { acknowledged, insertedId }
findOne()   → returns ONE document or null
find()      → returns a CURSOR (not an array!)
```

## 14. Cursor vs array — a classic trap

```js
const cursor = students.find({ branch: "CSE" });
console.log(cursor);   // ❌ prints a FindCursor object, not your data
```

`find()` returns a **cursor** — a pointer that fetches documents in batches. To get all documents as an array:

```js
const list = await students.find({ branch: "CSE" }).toArray();
```

Or loop through it without loading everything into memory:

```js
for await (const doc of students.find({ branch: "CSE" })) {
    console.log(doc.name);
}
```

```
find()      → cursor
.toArray()  → array of all docs (fine for small results)
for await   → process one by one (better for huge results)
```

Cursor chaining uses the same Unit II ideas:

```js
const top = await students
    .find({ branch: "CSE" })
    .project({ name: 1, cgpa: 1, _id: 0 })
    .sort({ cgpa: -1 })
    .limit(3)
    .toArray();
```

Notice: in the Node driver, projection is written with `.project({...})` (or an options object), and it matches the projection ideas from Unit II.

## 15. Error handling — what can go wrong?

| Problem                              | Typical cause                                    |
|-----------------------------------------|------------------------------------------------------|
| `MongoServerSelectionError`                | Server not running, wrong host, IP not allowed in Atlas  |
| Authentication failed                        | Wrong username/password                                      |
| `MongoServerError` with code `11000`          | Duplicate key (unique index violated)                          |
| `BSONError` / invalid ObjectId                  | Bad id string                                                    |
| Timeout                                           | Network/firewall issue                                             |

Always wrap DB code:

```js
try {
    // database work
} catch (err) {
    console.error(err.name, err.message);
} finally {
    // cleanup
}
```

A good habit — check the error `code`:

```js
catch (err) {
    if (err.code === 11000) {
        console.log("Duplicate value — that record already exists");
    } else {
        throw err;   // unknown error → don't hide it
    }
}
```

## 16. Driver vs Mongoose — preview

You now know the **native driver**: very close to the shell, flexible, minimal.

But look at this:

```js
await students.insertOne({ name: "Rahul", cgpa: "eight point seven" });
```

MongoDB happily stores a **string** in `cgpa`. MongoDB collections are flexible by default (Unit III: schema flexibility). In a big app with many developers, that flexibility can create bugs.

**Mongoose** adds:

```
Schemas       → define the shape of documents in code
Validation    → reject bad data BEFORE it reaches MongoDB
Models        → classes with handy methods
Middleware    → run code before/after save
populate()    → join-like referencing
```

Visual:

```
NATIVE DRIVER                      MONGOOSE
─────────────                      ────────
Close to MongoDB                   Structure + rules
Maximum flexibility                Productivity
You validate yourself              Built-in validation
Great for scripts / performance    Great for typical web apps
```

Part 2 is entirely Mongoose.

## 18. Common traps 🚨

### Trap 1 — Forgetting `await`

```js
const doc = students.findOne({ name: "Rahul" });   // ❌ Promise
console.log(doc);                                   // Promise { <pending> }
```

### Trap 2 — Creating a new client per request

Use **one** shared client.

### Trap 3 — Committing `.env`

Add it to `.gitignore` **before** your first commit.

### Trap 4 — Treating `find()` result as an array

It is a **cursor**; use `.toArray()` or `for await`.

### Trap 5 — String vs ObjectId

`_id` lookups need `new ObjectId(str)`.

### Trap 6 — Atlas IP access list

"Server selection timed out" on Atlas very often just means your current IP is not in the **Network Access** list.

### Trap 7 — Closing the client too early

Closing it before awaited operations finish gives "client must be connected" style errors.

### Trap 8 — Special characters in the password

Must be URL-encoded.

**Which package is the official Node.js driver?**

> `mongodb` (installed with `npm install mongodb`).

**What does a connection string look like?**

```
mongodb://localhost:27017
mongodb+srv://user:pass@cluster0.xxxxx.mongodb.net/
```

**What is the object chain?**

```
MongoClient → db() → collection() → operation
```

**What does `find()` return?**

> A cursor — convert with `.toArray()`.

**How many MongoClients should an app create?**

> One, reused for the whole application (connection pooling).

**How do we store secrets?**

> In a `.env` file read via `process.env`, never committed to Git.

**Why `async/await`?**

> Database operations are asynchronous and return Promises.

---

## 🧠 THE ONE LINE I WANT LOOPING IN YOUR BRAIN

> Your application never "opens MongoDB" — it opens a **connection through a driver**, reuses it, and sends operations that look like the shell commands you already know.
