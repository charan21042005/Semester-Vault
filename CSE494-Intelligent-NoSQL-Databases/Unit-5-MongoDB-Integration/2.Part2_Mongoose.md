## 1. What is Mongoose?

> Mongoose is an **ODM (Object Data Modeling) library** for MongoDB and Node.js. It lets you define schemas and models in JavaScript and provides validation, middleware, and convenient query methods.

Break the acronym:

```
O → Object
D → Data
M → Modeling
```

Relational analogy you already know:

```
SQL world:    ORM  (Object-Relational Mapping)  e.g. Sequelize, Hibernate
Mongo world:  ODM  (Object-Document Mapping)     e.g. Mongoose
```

Mongoose does **not** replace MongoDB. It sits on top of the Node.js driver:

```
YOUR CODE
    ↓
 MONGOOSE   ← schemas, validation, hooks, populate
    ↓
NODE.JS DRIVER
    ↓
 MONGODB
```

> Mongoose is built on top of the official MongoDB Node.js driver.

## 2. Install and connect

```bash
npm install mongoose dotenv
```

`.env`:

```
MONGODB_URI=mongodb://localhost:27017
DB_NAME=collegeDB
```

`connect.js`:

```js
import "dotenv/config";
import mongoose from "mongoose";

export async function connectDB() {
    await mongoose.connect(process.env.MONGODB_URI, {
        dbName: process.env.DB_NAME
    });
    console.log("✅ Mongoose connected");
}

export async function disconnectDB() {
    await mongoose.disconnect();
}
```

Notice the difference from Part 1:

```
Native driver:  you create and hold a MongoClient object.
Mongoose:       you call mongoose.connect() once; Mongoose manages the connection
                for all models in the app.
```

Mongoose still uses a connection pool internally — same "connect once, reuse everywhere" rule.

> In current Mongoose versions, operations return Promises (callbacks were removed in Mongoose 7), so `async/await` is the way to use it.

Optional connection events:

```js
mongoose.connection.on("connected", () => console.log("connected"));
mongoose.connection.on("error", err => console.error("DB error:", err));
mongoose.connection.on("disconnected", () => console.log("disconnected"));
```

## 3. The Mongoose trinity: Schema → Model → Document

This is THE concept of Part 2. Burn it in.

```
SCHEMA     = blueprint (the rules / shape)
   ↓ compiled into
MODEL      = factory + gateway to a collection (has find, create, ...)
   ↓ produces
DOCUMENT   = one actual record (an instance of the model)
```

Analogy — building houses:

```
Architect's blueprint   → Schema
Construction company    → Model   (can build and search houses)
An actual house         → Document
```

Another mapping to MongoDB itself:

| Mongoose  | MongoDB equivalent          |
|--------------|--------------------------------|
| Schema          | (no direct equivalent — rules in code) |
| Model             | Collection (you query through it)          |
| Document            | Document                                      |

## 4. Your first Schema and Model

`models/Student.js`:

```js
import mongoose from "mongoose";

const studentSchema = new mongoose.Schema({
    name:   String,
    branch: String,
    cgpa:   Number,
    year:   Number
});

const Student = mongoose.model("Student", studentSchema);

export default Student;
```

Line by line:

```
new mongoose.Schema({...})        → define fields and types
mongoose.model("Student", schema) → compile schema into a Model
export default Student            → other files can use it
```

### Collection naming rule

The model name `"Student"` becomes the collection **`students`** — Mongoose lowercases and pluralizes it automatically.

```
"Student"  → students
"Order"    → orders
"Category" → categories
```

To force a name:

```js
const Student = mongoose.model("Student", studentSchema, "my_students");
```

## 5. Schema data types

```js
const exampleSchema = new mongoose.Schema({
    title:    String,
    count:    Number,
    active:   Boolean,
    created:  Date,
    tags:     [String],                     // array of strings
    owner:    mongoose.Schema.Types.ObjectId, // reference id
    meta:     mongoose.Schema.Types.Mixed,    // anything (avoid when possible)
    address: {                              // nested object
        city:  String,
        state: String
    }
});
```

| Mongoose type                     | Stores                        |
|--------------------------------------|----------------------------------|
| `String`                                | text                                |
| `Number`                                  | integers/decimals                     |
| `Boolean`                                   | true/false                              |
| `Date`                                        | date-time                                 |
| `[String]` / `[Number]`                         | arrays                                      |
| `Schema.Types.ObjectId`                           | ids / references                              |
| `Schema.Types.Mixed`                                | any shape (no validation)                       |
| `Map`, `Decimal128`, `Buffer`, `UUID`                 | specialised types                                   |

Mongoose **casts** values when it can: the string `"8.7"` becomes the number `8.7` for a `Number` field. If it can't cast (`"banana"` → Number), it raises a `CastError`/validation error.

## 6. Validation — the superpower

Instead of a bare type, give a **configuration object**.

```js
const studentSchema = new mongoose.Schema({
    name: {
        type: String,
        required: [true, "Name is required"],
        trim: true,
        minlength: [2, "Name too short"],
        maxlength: 50
    },

    email: {
        type: String,
        required: true,
        unique: true,
        lowercase: true,
        match: [/^\S+@\S+\.\S+$/, "Invalid email format"]
    },

    branch: {
        type: String,
        enum: {
            values: ["CSE", "ECE", "EEE", "ME"],
            message: "{VALUE} is not a valid branch"
        },
        required: true
    },

    cgpa: {
        type: Number,
        min: [0, "CGPA cannot be negative"],
        max: [10, "CGPA cannot exceed 10"],
        default: 0
    },

    year: {
        type: Number,
        min: 1,
        max: 4
    }
});
```

### The built-in options at a glance

| Option                 | Applies to  | Meaning                                         |
|---------------------------|----------------|-----------------------------------------------------|
| `required`                   | all               | field must be present                                  |
| `default`                      | all                 | value used when none supplied                             |
| `min` / `max`                    | Number, Date         | numeric/date bounds                                          |
| `minlength` / `maxlength`          | String                 | length bounds                                                   |
| `enum`                               | String, Number           | value must be in list                                              |
| `match`                                | String                     | must match a regex                                                    |
| `trim`                                   | String                       | removes surrounding spaces                                               |
| `lowercase` / `uppercase`                  | String                         | transforms before saving                                                    |
| `validate`                                   | all                              | custom validator function                                                      |
| `unique`                                       | all                                | creates a unique INDEX (see next section!)                                        |
| `immutable`                                      | all                                  | cannot be changed after creation                                                     |

> Mongoose documents validation as running automatically before saving a document; built-in validators include `required`, `min`, `max`, `enum`, `match`, and length validators for strings.

## 7. A custom validator

```js
phone: {
    type: String,
    validate: {
        validator: v => /^\d{10}$/.test(v),
        message: props => `${props.value} is not a valid 10-digit phone number`
    }
}
```

```
validator → function returning true (OK) or false (invalid)
message   → text used in the error
```

## 8. 🚨 `unique` is NOT a validator

This is the #1 Mongoose misconception — and a classic viva question.

```js
email: { type: String, unique: true }
```

`unique: true` does **not** run a validation check in JavaScript. It instructs Mongoose to create a **unique index** in MongoDB (remember Unit IV: indexes!).

```
unique: true
     ↓
creates unique index on email
     ↓
MongoDB itself rejects duplicates
     ↓
you get a MongoServerError with code 11000   (NOT a ValidationError)
```

Consequences:

```
1. The error type is a duplicate-key error (code 11000), not ValidationError.
2. The index must actually exist. Mongoose builds it on startup (autoIndex)
   — but existing duplicate data will make index creation fail.
3. In production, many teams turn autoIndex off and create indexes deliberately.
```

Handling it:

```js
try {
    await Student.create({ name: "Rahul", email: "rahul@x.com", branch: "CSE" });
} catch (err) {
    if (err.code === 11000) {
        console.log("Duplicate:", err.keyValue);   // { email: 'rahul@x.com' }
    } else if (err.name === "ValidationError") {
        console.log("Validation failed");
    } else throw err;
}
```

## 9. What does a validation error look like?

```js
try {
    await Student.create({ name: "R", branch: "XYZ", cgpa: 12 });
} catch (err) {
    console.log(err.name);                 // "ValidationError"
    for (const field in err.errors) {
        console.log(field, "→", err.errors[field].message);
    }
}
```

Output:

```
ValidationError
name   → Name too short
email  → Path `email` is required.
branch → XYZ is not a valid branch
cgpa   → CGPA cannot exceed 10
```

### Dry run

```
Student.create(obj)
   ↓
Mongoose builds a document from obj  (casts types, applies defaults, trim, lowercase)
   ↓
Runs all validators
   ↓
 ┌── any failure ──→ throws ValidationError  → NOTHING sent to MongoDB
 └── all pass    ──→ sends insert to MongoDB
```

That is the big benefit: bad data is stopped **before** the database.

## 10. Strict mode — unknown fields are dropped

```js
await Student.create({ name: "Rahul", branch: "CSE", favouriteColor: "blue" });
```

`favouriteColor` is **not in the schema**. By default Mongoose runs in **strict** mode and silently ignores it — it won't be saved.

```
strict: true  (default) → fields not in schema are NOT saved
strict: false           → saved anyway
strict: "throw"         → throws an error
```

```js
const schema = new mongoose.Schema({ ... }, { strict: "throw" });
```

## 11. Timestamps

Almost every real collection needs `createdAt` and `updatedAt`.

```js
const studentSchema = new mongoose.Schema({ /* fields */ }, { timestamps: true });
```

Mongoose adds and maintains both fields automatically.

```json
{
    "name": "Rahul",
    "createdAt": "2026-11-20T04:30:00.000Z",
    "updatedAt": "2026-11-20T04:30:00.000Z"
}
```

Also automatically added: `_id` and `__v` (the **version key**, used to detect certain array-modification conflicts). You can hide `__v` in output if you like; don't delete it from logic casually.

### Array of strings


### Array of sub-documents

```js
const addressSchema = new mongoose.Schema({ city: String, pincode: Number }, { _id: false });

```

## 13. Virtuals — computed, not stored

A **virtual** is a property calculated on the fly; it is **not saved** in MongoDB.

```js
studentSchema.virtual("grade").get(function () {
    if (this.cgpa >= 9) return "A+";
    if (this.cgpa >= 8) return "A";
    if (this.cgpa >= 7) return "B";
    return "C";
});
```

Use:

```js
const s = await Student.findOne({ name: "Rahul" });
console.log(s.grade);          // "A"
```

To include virtuals in JSON output (e.g. API responses):

```js
const studentSchema = new mongoose.Schema({ /* ... */ }, {
    toJSON:   { virtuals: true },
    toObject: { virtuals: true }
});
```

```
Real field → stored in MongoDB
Virtual    → computed in JavaScript each time, not stored, NOT queryable in MongoDB
```

🚨 You cannot query by a virtual: `Student.find({ grade: "A" })` does not work, because MongoDB doesn't know about `grade`.

## 14. Instance methods and statics

### Instance method — works on ONE document

```js
studentSchema.methods.isTopper = function () {
    return this.cgpa >= 9;
};

const s = await Student.findOne({ name: "Priya" });
console.log(s.isTopper());     // true
```

### Static method — works on the MODEL (the whole collection)

```js
studentSchema.statics.findByBranch = function (branch) {
    return this.find({ branch });
};

const cseStudents = await Student.findByBranch("CSE");
```

```
methods  → s.isTopper()               (on a document)
statics  → Student.findByBranch(...)   (on the model)
```

Use plain `function`, not arrow functions, so `this` refers to the document/model.

## 15. Middleware (hooks)

Middleware = functions that run **before or after** an operation.

```
pre  hook → runs BEFORE the operation
post hook → runs AFTER  the operation
```

### Example — normalise data before save

```js
studentSchema.pre("save", function () {
    this.name = this.name.trim();
    console.log("About to save:", this.name);
});
```

### Example — log after save

```js
studentSchema.post("save", function (doc) {
    console.log("Saved student with id", doc._id);
});
```

### Classic use: hashing a password

```js
import bcrypt from "bcrypt";

userSchema.pre("save", async function () {
    if (!this.isModified("password")) return;
    this.password = await bcrypt.hash(this.password, 10);
});
```

Flow:

```
User.create({...})
     ↓
 pre("save")  → hash password
     ↓
 validation   (note: Mongoose validates before pre-save hooks run)
     ↓
 insert into MongoDB
     ↓
 post("save") → log / notify
```

🚨 Hooks are tied to specific operations. `pre("save")` runs for `doc.save()` and `Model.create()`, but **not** for `Model.updateOne()` — that needs `pre("updateOne")` (query middleware). Don't assume one hook covers everything.

## 16. Indexes in a Mongoose schema (Unit IV connection 🔗)

Remember Unit IV: single-field, compound, text indexes. Mongoose lets you declare them **in the schema**.

### Field-level

```js
email: { type: String, unique: true },     // unique index
name:  { type: String, index: true }       // ordinary index
```

### Schema-level (compound, text)

```js
studentSchema.index({ branch: 1, cgpa: -1 });            // compound  (Part 3, Unit IV)
studentSchema.index({ name: "text", bio: "text" });      // text index (Part 4, Unit IV)
```

On startup, Mongoose calls `createIndex()` for these (the `autoIndex` option, on by default). You can build them manually too:

```js
await Student.syncIndexes();       // make DB indexes match the schema
```

```
UNIT IV: db.students.createIndex({ branch: 1, cgpa: -1 })
UNIT V : studentSchema.index({ branch: 1, cgpa: -1 })
          ↑ same index, declared in code
```

> Mongoose documents `autoIndex` as enabled by default, and recommends considering disabling it in production because building indexes on large collections can be expensive.

## 17. References and `populate()` (Unit III + IV connection 🔗)

Unit III: **embed vs reference**. Mongoose's way to reference:

```js
const departmentSchema = new mongoose.Schema({
    name: String,
    hod:  String
});
const Department = mongoose.model("Department", departmentSchema);

const studentSchema = new mongoose.Schema({
    name: String,
    department: {
        type: mongoose.Schema.Types.ObjectId,
        ref: "Department"            // which model this id points to
    }
});
const Student = mongoose.model("Student", studentSchema);
```

Stored data:

```json
{ "name": "Rahul", "department": ObjectId("6650...aaa") }
```

Only the **id** is stored. To get the actual department document, use `populate()`:

```js
const s = await Student.findOne({ name: "Rahul" }).populate("department");
console.log(s.department.name);    // "Computer Science"
```

Result:

```json
{
    "name": "Rahul",
    "department": { "_id": "6650...aaa", "name": "Computer Science", "hod": "Dr. Singh" }
}
```

Select only some fields of the populated document:

```js
.populate("department", "name -_id")
```

### populate() vs `$lookup`

| Feature          | `populate()`                        | `$lookup` (Unit IV)                  |
|--------------------|----------------------------------------|-----------------------------------------|
| Where it runs         | Mongoose (in your app)                    | Inside MongoDB (aggregation stage)         |
| How it works            | Runs a **second query** and stitches results | One aggregation pipeline on the server       |
| Result shape              | Replaces id with document                    | Adds an **array** field                         |
| Best for                    | Convenient app code                            | Analytics, joins inside pipelines                  |

```
populate()  = convenience layer in Mongoose  (multiple queries)
$lookup     = join-like operation in MongoDB (server side)
```

Both follow the same rule as Unit III: reference when data is shared or large; embed when it is small and read together. And performance tip from Unit IV: index the referenced field (`_id` is already indexed; for other fields add an index).

## 18. `lean()` — faster read-only results

A normal Mongoose query returns **full Mongoose documents** (with methods, virtuals, change tracking). That's heavy.

If you only need plain data (e.g. to send JSON), use `lean()`:

```js
const list = await Student.find({ branch: "CSE" }).lean();
```

```
Without lean() → Mongoose Documents (heavier, has .save(), virtuals, getters)
With lean()    → plain JavaScript objects (lighter, faster, no .save())
```

> Mongoose documentation notes that `lean()` skips hydrating results into full Mongoose documents, which makes read queries faster and lighter in memory.

🚨 After `lean()`, virtuals and instance methods don't exist, and you cannot call `.save()`.

## 19. Complete model file — put it together

`models/Student.js`:

```js
import mongoose from "mongoose";

const studentSchema = new mongoose.Schema(
    {
        name: {
            type: String,
            required: [true, "Name is required"],
            trim: true,
            minlength: 2
        },
        email: {
            type: String,
            required: true,
            unique: true,
            lowercase: true,
            match: [/^\S+@\S+\.\S+$/, "Invalid email"]
        },
        branch: {
            type: String,
            enum: ["CSE", "ECE", "EEE", "ME"],
            required: true
        },
        cgpa: { type: Number, min: 0, max: 10, default: 0 },
        year: { type: Number, min: 1, max: 4 },
        skills: [String],
        address: { city: String, state: String }
    },
    { timestamps: true }
);

studentSchema.index({ branch: 1, cgpa: -1 });

studentSchema.virtual("grade").get(function () {
    return this.cgpa >= 9 ? "A+" : this.cgpa >= 8 ? "A" : this.cgpa >= 7 ? "B" : "C";
});

studentSchema.methods.isTopper = function () {
    return this.cgpa >= 9;
};

studentSchema.statics.findByBranch = function (branch) {
    return this.find({ branch });
};

export default mongoose.model("Student", studentSchema);
```

## 20. Practical lab — try it

`lab2.js`:

```js
import { connectDB, disconnectDB } from "./connect.js";
import Student from "./models/Student.js";

try {
    await connectDB();
    await Student.deleteMany({});
    await Student.syncIndexes();

    // 1) valid insert
    const rahul = await Student.create({
        name: "  Rahul ",
        email: "RAHUL@Example.com",
        branch: "CSE",
        cgpa: 8.7,
        year: 4,
        skills: ["Python", "MongoDB"]
    });
    console.log("Saved:", rahul.name, rahul.email, rahul.grade);   // Rahul rahul@example.com A

    // 2) invalid insert
    try {
        await Student.create({ name: "X", email: "bad", branch: "ABC", cgpa: 11 });
    } catch (err) {
        console.log("❌", err.name);
        Object.values(err.errors).forEach(e => console.log("  -", e.message));
    }

    // 3) duplicate email
    try {
        await Student.create({ name: "Rahul2", email: "rahul@example.com", branch: "CSE" });
    } catch (err) {
        console.log("❌ duplicate code:", err.code);   // 11000
    }

    // 4) static + lean
    const cse = await Student.findByBranch("CSE").lean();
    console.log("CSE count:", cse.length);
} catch (err) {
    console.error(err);
} finally {
    await disconnectDB();
}
```

What you should observe:

```
name trimmed         → "Rahul"
email lowercased     → "rahul@example.com"
grade virtual        → "A"
invalid doc          → ValidationError, nothing stored
duplicate email      → error code 11000 (needs the unique index, hence syncIndexes)
```

## 21. Native driver vs Mongoose — final comparison

| Feature                  | Native `mongodb` driver          | Mongoose                              |
|----------------------------|--------------------------------------|-------------------------------------------|
| Schema                        | None (flexible)                          | Defined in code                              |
| Validation                      | You write it                               | Built in                                        |
| Learning curve                    | Lower                                        | Higher (more concepts)                            |
| Speed / overhead                    | Minimal                                        | Slight overhead (use `lean()`)                       |
| Joins                                 | `$lookup`                                        | `populate()` and `$lookup`                              |
| Middleware / hooks                      | No                                                 | Yes                                                       |
| Best for                                  | Scripts, analytics, max control                      | Typical web apps / APIs with structured data                  |

```
Need structure + validation + productivity   → Mongoose
Need raw speed, flexibility, or pure scripts → native driver
```

Neither is "better" — they are tools for different jobs.

## 22. Common traps 🚨

### Trap 1 — Thinking `unique` is a validator

It creates a **unique index**; errors are code `11000`.

### Trap 2 — Forgetting `await`

`Student.find()` returns a Query/Promise-like object; without `await` you don't get data.

### Trap 3 — Arrow functions in methods/virtuals/hooks

Arrow functions break `this`. Use `function () {}`.

### Trap 4 — Unknown fields vanish

Strict mode silently drops fields not in the schema.

### Trap 5 — Update validators

By default, validators run on `save()`/`create()`, **not** on update queries. For updates you must pass `runValidators: true` (we do this in Part 3).

```js
await Student.findByIdAndUpdate(id, { cgpa: 15 }, { runValidators: true });
```

### Trap 6 — Mixed type everywhere

`Schema.Types.Mixed` turns off structure and change tracking. Use sparingly.

### Trap 7 — Querying virtuals

Virtuals aren't stored, so MongoDB can't filter on them.

### Trap 8 — Model name vs collection name

`"Student"` → `students`. Look for the wrong collection name when your data "disappears".

### Trap 9 — `lean()` then calling methods

Lean results are plain objects: no `.save()`, no virtuals.

### Trap 10 — Thinking Mongoose makes MongoDB "schema-enforced"

The **database** is still schemaless; Mongoose enforces rules in **your application**. Another program writing directly to the database bypasses them. (For database-level rules MongoDB has its own JSON Schema validation — a separate feature.)

## 24. 🔥 PART 2 — WHAT YOU MUST REMEMBER

**What is Mongoose?**

> An ODM library for MongoDB and Node.js that provides schemas, validation, middleware and query helpers.

**Schema vs Model vs Document?**

> Schema = blueprint; Model = interface to a collection; Document = one record.

**How do you create a model?**

```js
const Student = mongoose.model("Student", studentSchema);
```

**Name five validators.**

> `required`, `min`, `max`, `enum`, `match` (also `minlength`, `maxlength`, custom `validate`).

**Is `unique` a validator?**

> No — it creates a unique index; duplicate violations return error code 11000.

**What is a virtual?**

> A computed property not stored in MongoDB.

**What are `pre`/`post` hooks?**

> Middleware that runs before/after operations such as `save`.

**What does `populate()` do?**

> Replaces a referenced `ObjectId` with the actual referenced document (by running another query).

**What does `lean()` do?**

> Returns plain JavaScript objects instead of full Mongoose documents — faster, lighter.

**How do you add `createdAt`/`updatedAt`?**

> `{ timestamps: true }` in the schema options.
