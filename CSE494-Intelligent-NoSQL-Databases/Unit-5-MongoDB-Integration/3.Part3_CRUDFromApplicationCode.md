## 1. CRUD — the four verbs

You learned CRUD in the shell (Unit II). In an application it connects to the web like this:

| CRUD     | MongoDB method (shell/driver)         | HTTP verb  | Example route            |
|-------------|--------------------------------------------|--------------|------------------------------|
| **C**reate     | `insertOne`, `insertMany`                     | `POST`          | `POST /students`                |
| **R**ead        | `find`, `findOne`                               | `GET`            | `GET /students`, `GET /students/:id` |
| **U**pdate       | `updateOne`, `updateMany`, `replaceOne`           | `PUT` / `PATCH`    | `PATCH /students/:id`              |
| **D**elete        | `deleteOne`, `deleteMany`                          | `DELETE`            | `DELETE /students/:id`               |

```
Browser/App  →  HTTP request  →  Express route  →  CRUD call  →  MongoDB
```

We'll first learn CRUD **calls** (sections 2–10), then wrap them in a **web API** (section 12 onward).

# 🟢 C — CREATE

## 3. Insert one document

### 🔵 Native driver

```js
const db = await getDb();
const students = db.collection("students");

const result = await students.insertOne({
    name: "Rahul", branch: "CSE", cgpa: 8.7, year: 4
});

console.log(result.acknowledged);   // true
console.log(result.insertedId);     // ObjectId(...)
```

### 🟢 Mongoose

```js
const student = await Student.create({
    name: "Rahul", email: "rahul@example.com", branch: "CSE", cgpa: 8.7, year: 4
});
console.log(student._id);
```

Alternative — build, then save:

```js
const student = new Student({ name: "Rahul", email: "rahul@example.com", branch: "CSE" });
student.cgpa = 8.7;           // you can modify before saving
await student.save();
```

```
Student.create(obj)  =  new Student(obj) + save()
```

Both run **validation** first. The native driver runs none.

## 4. Insert many

### 🔵 Native

```js
const result = await students.insertMany([
    { name: "Priya", branch: "ECE", cgpa: 9.1, year: 4 },
    { name: "Arjun", branch: "CSE", cgpa: 7.8, year: 3 },
    { name: "Sneha", branch: "CSE", cgpa: 8.9, year: 4 }
]);

console.log(result.insertedCount);   // 3
console.log(result.insertedIds);     // { '0': ObjectId, '1': ..., '2': ... }
```

### 🟢 Mongoose

```js
const docs = await Student.insertMany([
    { name: "Priya", email: "priya@x.com", branch: "ECE", cgpa: 9.1 },
    { name: "Arjun", email: "arjun@x.com", branch: "CSE", cgpa: 7.8 }
]);
console.log(docs.length);
```

### Ordered vs unordered

By default inserts are **ordered**: if document #2 fails (e.g. duplicate key), the rest are not inserted. To continue past failures:

```js
await students.insertMany(list, { ordered: false });
```

```
ordered: true  (default) → stop at first error
ordered: false           → try all, report errors afterwards
```

# 🟢 R — READ

## 5. Find one / find many

### 🔵 Native

```js
// one document or null
const one = await students.findOne({ name: "Rahul" });

// many → cursor → array
const cse = await students.find({ branch: "CSE" }).toArray();

// all
const all = await students.find({}).toArray();
```

### 🟢 Mongoose

```js
const one   = await Student.findOne({ name: "Rahul" });
const byId  = await Student.findById("6650f1a2b3c4d5e6f7a8b9c0");   // string id is fine!
const cse   = await Student.find({ branch: "CSE" });
const all   = await Student.find();
```

Nice Mongoose perk: `findById` accepts a **string** and casts it to an ObjectId for you. In the native driver you must write `new ObjectId(id)` yourself.

```
Native:    findOne({ _id: new ObjectId(idString) })
Mongoose:  findById(idString)
```

If nothing matches, `findOne`/`findById` return **`null`** — always check:

```js
if (!one) console.log("Not found");
```

## 6. Query operators in code

Exactly the Unit II operators — now inside JavaScript objects.

```js
// comparison
await Student.find({ cgpa: { $gte: 8.5 } });
await Student.find({ year: { $in: [3, 4] } });
await Student.find({ branch: { $ne: "ME" } });

// logical
await Student.find({ $or: [{ branch: "CSE" }, { cgpa: { $gt: 9 } }] });
await Student.find({ branch: "CSE", cgpa: { $gte: 8 } });      // implicit AND

// arrays
await Student.find({ skills: "MongoDB" });                      // array contains
await Student.find({ skills: { $all: ["Python", "MongoDB"] } });
await Student.find({ skills: { $size: 3 } });

// nested field
await Student.find({ "address.city": "Amritsar" });

// existence / type
await Student.find({ phone: { $exists: true } });

// regex (pattern, not text index)
await Student.find({ name: { $regex: /^ra/i } });
```

Every one of these also works unchanged with `students.find(...)` in the native driver.

## 7. Projection, sort, limit, skip

### 🟢 Mongoose

```js
const top3 = await Student
    .find({ branch: "CSE" })
    .select("name cgpa -_id")      // include name & cgpa, exclude _id
    .sort({ cgpa: -1 })            // highest first
    .limit(3);
```

String-style `select`: `"name cgpa"` = include, `"-password"` = exclude. Object style also works: `.select({ name: 1, cgpa: 1, _id: 0 })`.

### 🔵 Native

```js
const top3 = await students
    .find({ branch: "CSE" })
    .project({ name: 1, cgpa: 1, _id: 0 })
    .sort({ cgpa: -1 })
    .limit(3)
    .toArray();
```

| Task        | Native           | Mongoose                  |
|----------------|---------------------|-------------------------------|
| Choose fields    | `.project({...})`      | `.select(...)`                    |
| Sort                | `.sort({ f: -1 })`       | `.sort({ f: -1 })` or `.sort("-f")` |
| First N               | `.limit(n)`                | `.limit(n)`                           |
| Skip N                  | `.skip(n)`                   | `.skip(n)`                              |

🔗 **Unit IV link:** a compound index `{ branch: 1, cgpa: -1 }` (ESR!) is exactly what makes this query efficient — equality on `branch`, sort on `cgpa`.

```js
// native
const n = await students.countDocuments({ branch: "CSE" });
const branches = await students.distinct("branch");

// mongoose
const n2 = await Student.countDocuments({ branch: "CSE" });

```

```
countDocuments(filter)      → exact count matching a filter
estimatedDocumentCount()    → fast approximate total (no filter, uses metadata)
```

## 9. Pagination — a must-know real-world pattern

Never return 1,000,000 documents to a web page. Return **pages**.

### Skip/limit pagination

```js
const page = 2;
const limit = 10;

const list = await Student.find({ branch: "CSE" })
    .sort({ cgpa: -1, _id: 1 })        // add _id for a stable, repeatable order
    .skip((page - 1) * limit)
    .limit(limit);
```

```
page 1 → skip 0
page 2 → skip 10
page 3 → skip 20
```

🚨 Always combine pagination with a **deterministic sort** (add `_id` as a tie-breaker), otherwise pages can overlap or miss documents.

### The weakness

`skip(100000)` still has to walk past 100,000 entries — slow for deep pages.

### Better for big data: range-based ("keyset") pagination

```js
// first page
let page1 = await Student.find().sort({ _id: 1 }).limit(10);

// next page: continue AFTER the last _id we saw
const lastId = page1[page1.length - 1]._id;
let page2 = await Student.find({ _id: { $gt: lastId } }).sort({ _id: 1 }).limit(10);
```

This uses the `_id` index to jump straight to the right spot (🔗 Unit IV: indexes!).

# 🟢 U — UPDATE

## 10. The update operators (recap from Unit II)

| Operator        | Meaning                              |
|--------------------|-----------------------------------------|
| `$set`                 | set / change fields                        |
| `$unset`                 | remove a field                               |
| `$inc`                     | increment a number                             |
| `$mul`                       | multiply                                          |
| `$push`                        | add to array (duplicates allowed)                    |
| `$addToSet`                      | add to array only if absent                             |
| `$pull`                            | remove matching items from array                           |
| `$rename`                            | rename a field                                                |
| `$currentDate`                         | set field to current date                                         |

🚨 Biggest beginner mistake:

```js
// ❌ replaces the ENTIRE document with { cgpa: 9 }
await students.replaceOne({ name: "Rahul" }, { cgpa: 9 });

// ✅ changes only cgpa
await students.updateOne({ name: "Rahul" }, { $set: { cgpa: 9 } });
```

`updateOne` **requires** update operators (like `$set`). `replaceOne` swaps the whole document (keeping only `_id`).

## 11. updateOne / updateMany

### 🔵 Native

```js
const r = await students.updateOne(
    { name: "Rahul" },
    { $set: { cgpa: 9.0 } }
);

console.log(r.matchedCount);    // how many docs matched the filter
console.log(r.modifiedCount);   // how many actually changed
```

```js
// increment CGPA of all CSE students (silly, but shows updateMany)
const r2 = await students.updateMany({ branch: "CSE" }, { $inc: { year: 0 } });

// arrays
await students.updateOne({ name: "Rahul" }, { $push:     { skills: "Docker" } });
await students.updateOne({ name: "Rahul" }, { $addToSet: { skills: "Python" } });
await students.updateOne({ name: "Rahul" }, { $pull:     { skills: "C++" } });
```

### Understanding the result object

```
{
    acknowledged: true,
    matchedCount: 1,      ← documents that matched your filter
    modifiedCount: 1,     ← documents actually changed
    upsertedCount: 0,
    upsertedId: null
}
```

Important subtlety:

```
matchedCount = 1, modifiedCount = 0
   → the document existed but the new value was the SAME as the old one.
     Not an error!
matchedCount = 0
   → no document matched: wrong filter / wrong id / wrong type.
```

### 🟢 Mongoose

```js
const r = await Student.updateOne({ name: "Rahul" }, { $set: { cgpa: 9.0 } });
console.log(r.matchedCount, r.modifiedCount);

await Student.updateMany({ branch: "CSE" }, { $set: { placed: false } });
```

Mongoose lets you drop `$set` for simple changes (it adds it for you), but being explicit is a good habit.

## 12. find-and-update in one step: `findOneAndUpdate`

Sometimes you want the **updated document back** (e.g. to return it in an API response).

### 🟢 Mongoose

```js
const updated = await Student.findByIdAndUpdate(
    id,
    { $set: { cgpa: 9.2 } },
    { new: true, runValidators: true }
);
```

The two options are critical:

```
new: true            → return the document AFTER the update
                       (default returns the OLD version!)
runValidators: true  → run schema validators on the update
                       (default: validators DON'T run on updates!)
```

Newer Mongoose also accepts `returnDocument: "after"` as the equivalent of `new: true`.

If no document matches, the result is `null`.

### 🔵 Native

```js
const updated = await students.findOneAndUpdate(
    { name: "Rahul" },
    { $set: { cgpa: 9.2 } },
    { returnDocument: "after" }
);
```

In recent Node.js driver versions this returns the document itself (or `null`); older versions returned a wrapper object with a `.value` field. If your lab's driver is older, check `updated.value`.

```
Mongoose: { new: true }               ↔   Native: { returnDocument: "after" }
```

## 13. Upsert — "update, or insert if missing"

```js
await students.updateOne(
    { email: "new@x.com" },
    { $set: { name: "New Student", branch: "ECE" } },
    { upsert: true }
);
```

```
Filter matches a doc?
   YES → update it
   NO  → INSERT a new doc built from the filter equality fields + the update
```

`result.upsertedId` is set if an insert happened. Mongoose uses the same option: `{ upsert: true }`.

🔗 Use with a **unique index** on the filter field, or two parallel requests may both insert.

## 14. replaceOne

```js
await students.replaceOne(
    { name: "Rahul" },
    { name: "Rahul", branch: "CSE", cgpa: 9.0, year: 4 }   // new complete document
);
```

```
updateOne  → surgical change with operators
replaceOne → throw away the old body, keep _id, write this new body
```

In REST terms (rule of thumb): `PUT` ≈ replace whole resource, `PATCH` ≈ partial update.

## 15. The "load, modify, save" pattern (Mongoose only)

```js
const s = await Student.findById(id);
if (!s) return null;

s.cgpa = 9.3;
s.skills.push("Docker");
await s.save();
```

Pros: runs validation **and** `pre("save")` hooks automatically; easy to read.
Cons: two round-trips (find, then save), and a small race window if two requests edit simultaneously.

```
Quick single-field change   → updateOne / findByIdAndUpdate
Complex logic, hooks needed → load, modify, save()
```

# 🟢 D — DELETE

## 16. deleteOne / deleteMany

### 🔵 Native

```js
const r = await students.deleteOne({ name: "Rahul" });
console.log(r.deletedCount);        // 1 or 0

const r2 = await students.deleteMany({ cgpa: { $lt: 5 } });
console.log(r2.deletedCount);
```

### 🟢 Mongoose

```js
await Student.deleteOne({ name: "Rahul" });
await Student.deleteMany({ cgpa: { $lt: 5 } });

const removed = await Student.findByIdAndDelete(id);   // returns the deleted doc or null
```

🚨 **The deadly mistake:**

```js
await students.deleteMany({});     // deletes EVERYTHING in the collection
```

An empty filter matches all documents. Always double-check filters, and in real systems prefer **soft delete**:

```js
await Student.updateOne({ _id: id }, { $set: { isDeleted: true, deletedAt: new Date() } });
```

Then your normal reads filter `{ isDeleted: { $ne: true } }`.

## 17. Bulk operations

Many different writes in **one** network round-trip:

```js
await students.bulkWrite([
    { insertOne: { document: { name: "A", branch: "CSE", cgpa: 7 } } },
    { updateOne: { filter: { name: "Priya" }, update: { $set: { cgpa: 9.5 } } } },
    { deleteOne: { filter: { name: "Arjun" } } }
]);
```

Mongoose: `Student.bulkWrite([...])` with the same shape.

```
Many separate calls → many round trips (slow)
bulkWrite           → one batch (fast)
```

| Operation        | Native driver                               | Mongoose                                  |
|--------------------|------------------------------------------------|----------------------------------------------|

## 20. `routes/students.js`

```js
import express from "express";
import mongoose from "mongoose";
import Student from "../models/Student.js";

const router = express.Router();

// helper: reject malformed ids early
function checkId(req, res, next) {
    if (!mongoose.isValidObjectId(req.params.id)) {
        return res.status(400).json({ error: "Invalid id" });
    }
    next();
}

// CREATE ─ POST /students
router.post("/", async (req, res, next) => {
    try {
        const student = await Student.create(req.body);
        res.status(201).json(student);
    } catch (err) {
        next(err);
    }
});

// READ ALL ─ GET /students?branch=CSE&minCgpa=8&page=1&limit=5
router.get("/", async (req, res, next) => {
    try {
        const { branch, minCgpa } = req.query;
        const page  = Math.max(parseInt(req.query.page)  || 1, 1);
        const limit = Math.min(parseInt(req.query.limit) || 10, 100);

        const filter = {};
        if (branch)  filter.branch = branch;
        if (minCgpa) filter.cgpa = { $gte: Number(minCgpa) };

        const [items, total] = await Promise.all([
            Student.find(filter)
                .sort({ cgpa: -1, _id: 1 })
                .skip((page - 1) * limit)
                .limit(limit)
                .lean(),
            Student.countDocuments(filter)
        ]);

        res.json({ page, limit, total, items });
    } catch (err) {
        next(err);
    }
});

// READ ONE ─ GET /students/:id
router.get("/:id", checkId, async (req, res, next) => {
    try {
        const student = await Student.findById(req.params.id);
        if (!student) return res.status(404).json({ error: "Student not found" });
        res.json(student);
    } catch (err) {
        next(err);
    }
});

// UPDATE ─ PATCH /students/:id
router.patch("/:id", checkId, async (req, res, next) => {
    try {
        const student = await Student.findByIdAndUpdate(
            req.params.id,
            { $set: req.body },
            { new: true, runValidators: true }
        );
        if (!student) return res.status(404).json({ error: "Student not found" });
        res.json(student);
    } catch (err) {
        next(err);
    }
});

// DELETE ─ DELETE /students/:id
router.delete("/:id", checkId, async (req, res, next) => {
    try {
        const student = await Student.findByIdAndDelete(req.params.id);
        if (!student) return res.status(404).json({ error: "Student not found" });
        res.status(204).send();
    } catch (err) {
        next(err);
    }
});

export default router;
```

### Why each piece exists

```
express.Router()          → groups related routes
req.body                  → JSON sent by the client (needs express.json() middleware)
req.params.id             → the :id part of the URL
req.query                 → the ?key=value part of the URL
res.status(201).json(...) → send status code + JSON
next(err)                 → hand the error to the central error handler
Promise.all([...])        → run the two independent queries in parallel
lean()                    → plain objects (read-only list, faster)
```

## 21. `server.js`

```js
import "dotenv/config";
import express from "express";
import { connectDB } from "./connect.js";
import studentsRouter from "./routes/students.js";

const app = express();
app.use(express.json());              // parse JSON request bodies

app.use("/students", studentsRouter);

// ── central error handler (must have 4 parameters) ──
app.use((err, req, res, next) => {
    if (err.name === "ValidationError") {
        const messages = Object.values(err.errors).map(e => e.message);
        return res.status(400).json({ error: "Validation failed", details: messages });
    }
    if (err.name === "CastError") {
        return res.status(400).json({ error: `Invalid value for ${err.path}` });
    }
    if (err.code === 11000) {
        return res.status(409).json({ error: "Duplicate value", fields: err.keyValue });
    }
    console.error(err);
    res.status(500).json({ error: "Internal server error" });
});

const PORT = process.env.PORT || 3000;

await connectDB();
app.listen(PORT, () => console.log(`🚀 API running on http://localhost:${PORT}`));
```

Start it:

```bash
node server.js
```

### Order matters in Express

```
1. express.json()       ← before routes (so req.body exists)
2. routes
3. error handler        ← LAST (so it catches errors from everything above)
```

## 24. Full dry run — one request, end to end

Request:

```
PATCH /students/6650f1a2b3c4d5e6f7a8b9c0     body: { "cgpa": 9.1 }
```

```
1. Express receives request, express.json() parses body → req.body = { cgpa: 9.1 }
2. Route matches "/students/:id" → req.params.id = "6650..."
3. checkId → isValidObjectId? yes → next()
4. findByIdAndUpdate(id, {$set:{cgpa:9.1}}, {new:true, runValidators:true})
5. Mongoose casts id to ObjectId, validates cgpa (0 ≤ 9.1 ≤ 10 ✔)
6. Driver sends update to MongoDB over the pooled connection
7. MongoDB uses the _id index (🔗 Unit IV: IXSCAN), updates the document
8. Updated document comes back
9. Route sends res.json(student) with status 200
```

Had cgpa been 99: step 5 throws `ValidationError` → `next(err)` → error handler → `400` JSON.

## 25. 🔒 A word on security (exam-worthy awareness)

Putting `req.body` straight into a query/update is dangerous:

```js
await Student.find(req.body);                         // ❌ risky
await Student.findByIdAndUpdate(id, { $set: req.body }); // ⚠ client can set ANY field
```

### NoSQL injection

If a login route does:

```js
User.findOne({ email: req.body.email, password: req.body.password })
```

and an attacker sends JSON:

```json
{ "email": "admin@x.com", "password": { "$ne": null } }
```

then `password: { $ne: null }` matches any password. Defences:

```
1. Validate input types (ensure email/password are strings).
2. Never pass raw req.body as a filter.
3. Whitelist updatable fields.
4. Store hashed passwords (bcrypt) and compare hashes, don't query by password.
5. Mongoose's schema casting helps: a Number/String field will reject objects
   — but don't rely on it as your only defence.
```

Whitelist example:

```js
const allowed = ["name", "cgpa", "year", "skills"];
const updates = Object.fromEntries(
    Object.entries(req.body).filter(([k]) => allowed.includes(k))
);
```

## 26. Common traps 🚨

### Trap 1 — `findByIdAndUpdate` without `{ new: true }`

You get the **old** document back, and think the update failed.

### Trap 2 — Updates skip validators

Use `runValidators: true`, otherwise `cgpa: 99` goes straight in.

### Trap 3 — `updateOne` without `$set` (native driver)

The native driver throws an error if the update document has no operators; `replaceOne` is the method for full replacement.

### Trap 4 — `deleteMany({})`

Deletes everything. Double-check filters.

### Trap 5 — `matchedCount` vs `modifiedCount`

`matched 1 / modified 0` is not an error; it means "already had that value."

### Trap 6 — Not handling `null`

`findById` returns `null` for "not found". Calling `.name` on `null` crashes your server. Return 404.

### Trap 7 — Forgetting `await` in routes

The response is sent before the DB finishes, or errors escape the `try/catch`.

### Trap 8 — Error handler placed before routes

Express error handlers must come **after** the routes they protect.

### Trap 9 — Invalid ObjectId crashes

`findById("abc")` throws a `CastError`. Validate with `mongoose.isValidObjectId()` or handle `CastError`.

### Trap 10 — Skip/limit without stable sort

Add `_id` as tie-breaker to the sort.

### Trap 11 — Returning passwords/hashes

Use `.select("-password")` or schema `select: false`.

## 28. 🔥 PART 3 — WHAT YOU MUST REMEMBER

**What is CRUD?**

> Create, Read, Update, Delete — the four basic data operations.

**Which methods?**

> `insertOne/insertMany`, `find/findOne`, `updateOne/updateMany/replaceOne`, `deleteOne/deleteMany`.

**What does `find()` return in the native driver?**

> A cursor (use `.toArray()`).

**Difference between `updateOne` and `replaceOne`?**

> `updateOne` applies operators like `$set` to specific fields; `replaceOne` replaces the entire document body.

**Why `{ new: true }`?**

> So `findByIdAndUpdate` returns the updated document instead of the old one.

**Why `runValidators: true`?**

> Validators don't run on update queries by default.

**What do `matchedCount` and `modifiedCount` tell you?**

> How many documents matched the filter and how many were actually changed.

**What is upsert?**

> Update if a document matches, otherwise insert a new one.

**Which HTTP verbs map to CRUD?**

> POST, GET, PUT/PATCH, DELETE.
