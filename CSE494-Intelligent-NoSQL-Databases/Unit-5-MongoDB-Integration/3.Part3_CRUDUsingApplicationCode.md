## 1. The command translation table

This table is your bridge from Unit II to Unit V.

| Operation | Shell (Unit II) | Native driver | Mongoose |
|--------------|------------------------|---------------------|--------------------|
| Insert one | `insertOne()` | `insertOne()` | `Model.create()` / `new Model().save()` |
| Insert many | `insertMany()` | `insertMany()` | `Model.insertMany()` / `Model.create([...])` |
| Find many | `find()` | `find().toArray()` | `Model.find()` |
| Find one | `findOne()` | `findOne()` | `Model.findOne()` |
| Find by id | `find({_id})` | `findOne({_id})` | `Model.findById()` |
| Update one | `updateOne()` | `updateOne()` | `Model.updateOne()` / `findByIdAndUpdate()` |
| Update many | `updateMany()` | `updateMany()` | `Model.updateMany()` |
| Delete one | `deleteOne()` | `deleteOne()` | `Model.deleteOne()` / `findByIdAndDelete()` |
| Delete many | `deleteMany()` | `deleteMany()` | `Model.deleteMany()` |
| Count | `countDocuments()` | `countDocuments()` | `Model.countDocuments()` |
| Aggregate | `aggregate()` | `aggregate().toArray()` | `Model.aggregate()` |

The ideas are identical. Only the wrapper changes.

# 🟢 C — CREATE

## 3. `Model.create()`

```js
const s = await Student.create({
    name: "Rahul",
    email: "rahul@gmail.com",
    branch: "CSE",
    year: 4,
    cgpa: 8.7,
    skills: ["Python", "MongoDB"]
});
console.log(s);
```

`create()` builds the document, validates it, saves it and returns it.

## 4. `new` + `save()`

Same result in two steps:

```js
const s = new Student({ name: "Priya", email: "priya@gmail.com", branch: "ECE", cgpa: 9.1 });
// you can modify s here
await s.save();
```

Use this style when you want to adjust the object before saving.

## 5. `insertMany()`

```js
await Student.insertMany([
    { name: "Arjun", email: "arjun@gmail.com", branch: "CSE", year: 3, cgpa: 7.8 },
    { name: "Sneha", email: "sneha@gmail.com", branch: "CSE", year: 4, cgpa: 8.9 },
    { name: "Karan", email: "karan@gmail.com", branch: "EEE", year: 2, cgpa: 8.1 }
]);
```

`insertMany()` validates each document and inserts them in bulk, which is much faster than a loop of single inserts.

Important:

```
By default, if one document is invalid, insertMany may stop partway.
Use { ordered: false } to continue past errors where appropriate.
```

# 🔵 R — READ

## 6. `find()` — all matches

```js
const all = await Student.find();                         // every document
const cse = await Student.find({ branch: "CSE" });        // filter
```

`find()` returns an **array** of documents (empty array if none match).

## 7. `findOne()` and `findById()`

```js
const one = await Student.findOne({ name: "Rahul" });     // first match or null
const byId = await Student.findById("6650a1b2c3d4e5f607182930");
```

Notice: Mongoose **casts the string to ObjectId for you** in `findById` and in filters on `_id`. (In the native driver you had to write `new ObjectId(...)`.) A small but nice convenience.

If nothing matches, you get `null`, so always check:

```js
if (!one) { console.log("Not found"); }
```

## 8. Filters with operators (same as Unit II)

```js
// CGPA >= 8.5
await Student.find({ cgpa: { $gte: 8.5 } });

// CSE AND year 4
await Student.find({ branch: "CSE", year: 4 });

// CSE OR ECE
await Student.find({ branch: { $in: ["CSE", "ECE"] } });

// $or
await Student.find({ $or: [{ branch: "ECE" }, { cgpa: { $gt: 9 } }] });

// array contains
await Student.find({ skills: "MongoDB" });

// nested field
await Student.find({ "address.city": "Amritsar" });
```

Exactly the operators you learned: `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`, `$ne`, `$or`, `$and`, `$exists`, `$regex`.

## 9. `sort`, `limit`, `skip`, `select`

Chain them:

```js
const top3 = await Student.find({ branch: "CSE" })
    .sort({ cgpa: -1 })      // highest first
    .limit(3)                // only 3
    .select("name cgpa -_id"); // return only name and cgpa, exclude _id
```

```
sort    → order (1 ascending, -1 descending)
limit   → max documents
skip    → skip the first N (pagination)
select  → projection
```

`select` syntax:

```
"name cgpa"      → include only these (plus _id)
"-password"      → exclude this field
"name -_id"      → include name, exclude _id
```

Or object style: `.select({ name: 1, cgpa: 1, _id: 0 })`.

### Pagination pattern

```js
const page = 2;
const pageSize = 10;

const students = await Student.find()
    .sort({ createdAt: -1 })
    .skip((page - 1) * pageSize)
    .limit(pageSize);
```

(For very large collections, `skip` gets slow. Range-based pagination using an indexed field is better. Link to Unit IV: sorting field should be indexed.)

## 10. Counting

```js
const total = await Student.countDocuments({ branch: "CSE" });
```

## 11. `lean()` — plain objects for speed

Normally Mongoose returns full Mongoose documents (with methods, virtuals, change tracking).

If you only need to **read and send** data, use `lean()`:

```js
const students = await Student.find({ branch: "CSE" }).lean();
```

`lean()` returns plain JavaScript objects, which uses less memory and is faster. But you lose Mongoose features (`save()`, virtuals by default, methods).

```
Need to modify and save()  → normal document
Only reading/sending JSON  → lean()
```

# 🟠 U — UPDATE

## 12. Update operators from Unit II still apply

| Operator | Meaning |
|------------|------------|
| `$set` | set field values |
| `$inc` | increment/decrement |
| `$unset` | remove a field |
| `$push` | add to array |
| `$pull` | remove from array |
| `$addToSet` | add unique element to array |

## 13. `updateOne()`

```js
const result = await Student.updateOne(
    { name: "Rahul" },
    { $set: { cgpa: 8.9 } }
);
console.log(result.matchedCount, result.modifiedCount);
```

```
matchedCount   → how many documents matched the filter
modifiedCount  → how many were actually changed
```

If `matchedCount` is 0, nothing matched.

## 14. `updateMany()`

Promote everyone in year 3 to year 4:

```js
await Student.updateMany({ year: 3 }, { $inc: { year: 1 } });
```

## 15. `findByIdAndUpdate()` — update and get the document back

```js
const updated = await Student.findByIdAndUpdate(
    id,
    { $set: { cgpa: 9.0 } },
    { new: true, runValidators: true }
);
```

Two critical options:

```
new: true            → return the document AFTER the update
                       (default returns the OLD one)
runValidators: true  → run schema validators on the update
```

Why `runValidators`? By default, update operations skip many schema validators. Without it:

```js
await Student.updateOne({ name: "Rahul" }, { $set: { cgpa: 99 } });   // may succeed even though max is 10 ⚠️
```

With `{ runValidators: true }` the update is checked against the schema. 🔥 This is a classic exam/interview trap.

## 16. Array updates

```js
// add a skill (duplicates allowed)
await Student.updateOne({ name: "Rahul" }, { $push: { skills: "Docker" } });

// add only if not already present
await Student.updateOne({ name: "Rahul" }, { $addToSet: { skills: "Docker" } });

// remove a skill
await Student.updateOne({ name: "Rahul" }, { $pull: { skills: "C++" } });
```

## 17. Updating via `save()`

```js
const s = await Student.findOne({ name: "Priya" });
s.cgpa = 9.3;
await s.save();
```

`save()` runs full validation and works on a hydrated document. This is often the safest way for important updates where validation matters.

```
updateOne / findByIdAndUpdate → direct DB update (efficient, fewer checks unless runValidators)
find + modify + save()        → full validation + middleware (two steps)
```

## 18. Upsert

Update if exists, otherwise insert:

```js
await Student.updateOne(
    { email: "new@gmail.com" },
    { $set: { name: "New Student", branch: "CSE" } },
    { upsert: true }
);
```

# 🔴 D — DELETE

## 19. Deleting

```js
// first match
await Student.deleteOne({ name: "Karan" });

// many
await Student.deleteMany({ year: 1 });

// by id, returning the deleted document
const deleted = await Student.findByIdAndDelete(id);
```

Result of `deleteOne` / `deleteMany`:

```js
{ acknowledged: true, deletedCount: 1 }
```

## 20. Delete safely 🚨

```js
await Student.deleteMany({});     // ❌ deletes EVERYTHING
```

Habits:

```
1. Run find(filter) first to see what matches
2. Check deletedCount afterward
3. Consider "soft delete" (isDeleted: true) for important data
4. Never build a filter directly from unchecked user input
```

Soft delete pattern:

```js
await Student.updateOne({ _id: id }, { $set: { isDeleted: true } });
// queries then use { isDeleted: { $ne: true } }
```

# 🟣 POPULATE — REFERENCES

## 21. `populate()`

Remember the `department` reference from Part 2:

```js
const students = await Student.find().populate("department");
```

Without populate:

```json
{ "name": "Rahul", "department": "6650aa11bb22cc33dd44ee55" }
```

With populate:

```json
{
    "name": "Rahul",
    "department": { "_id": "6650aa11bb22cc33dd44ee55", "name": "Computer Science" }
}
```

Select only certain fields of the referenced document:

```js
await Student.find().populate("department", "name");
```

How it works (important for viva):

```
1. Run the main query
2. Collect the referenced IDs
3. Run a SECOND query on the other collection
4. Replace IDs with documents in the results
```

So `populate()` is **done by Mongoose in the application with extra queries**, whereas `$lookup` is **done inside MongoDB in one aggregation**.

# 🟤 AGGREGATION FROM NODE

## 22. `Model.aggregate()`

Unit IV pipelines work as is:

```js
const result = await Student.aggregate([
    { $match: { year: 4 } },
    { $group: {
        _id: "$branch",
        studentCount: { $sum: 1 },
        averageCgpa: { $avg: "$cgpa" }
    } },
    { $sort: { averageCgpa: -1 } }
]);

console.log(result);
```

Key difference to remember:

> In `aggregate()`, Mongoose does **not** cast or validate your pipeline against the schema. If you match on an `_id`, you must convert strings to ObjectId yourself.

```js
const mongoose = require("mongoose");
{ $match: { department: new mongoose.Types.ObjectId(deptId) } }
```

This ties Unit IV and Unit V together: your aggregation knowledge is directly usable in app code. 🔥

## 24. CRUD ↔ HTTP mapping

## 26. Complete working server

`server.js`:

```js
require("dotenv").config();
const express = require("express");
const mongoose = require("mongoose");
const connectDB = require("./db");
const Student = require("./models/Student");

const app = express();
app.use(express.json());          // lets Express read JSON request bodies

// CREATE
app.post("/students", async (req, res) => {
    try {
        const student = await Student.create(req.body);
        res.status(201).json(student);
    } catch (err) {
        if (err.name === "ValidationError") {
            return res.status(400).json({ error: err.message });
        }
        if (err.code === 11000) {
            return res.status(409).json({ error: "Duplicate value", details: err.keyValue });
        }
        res.status(500).json({ error: "Server error" });
    }
});

// READ ALL (with optional filters)
app.get("/students", async (req, res) => {
    try {
        const filter = {};
        if (req.query.branch) filter.branch = req.query.branch;
        if (req.query.minCgpa) filter.cgpa = { $gte: Number(req.query.minCgpa) };

        const students = await Student.find(filter).sort({ cgpa: -1 }).lean();
        res.json(students);
    } catch (err) {
        res.status(500).json({ error: "Server error" });
    }
});

// READ ONE
app.get("/students/:id", async (req, res) => {
    try {
        if (!mongoose.isValidObjectId(req.params.id)) {
            return res.status(400).json({ error: "Invalid id" });
        }
        const student = await Student.findById(req.params.id);
        if (!student) return res.status(404).json({ error: "Student not found" });
        res.json(student);
    } catch (err) {
        res.status(500).json({ error: "Server error" });
    }
});

// UPDATE
app.put("/students/:id", async (req, res) => {
    try {
        if (!mongoose.isValidObjectId(req.params.id)) {
            return res.status(400).json({ error: "Invalid id" });
        }
        const updated = await Student.findByIdAndUpdate(
            req.params.id,
            { $set: req.body },
            { new: true, runValidators: true }
        );
        if (!updated) return res.status(404).json({ error: "Student not found" });
        res.json(updated);
    } catch (err) {
        if (err.name === "ValidationError") {
            return res.status(400).json({ error: err.message });
        }
        res.status(500).json({ error: "Server error" });
    }
});

// DELETE
app.delete("/students/:id", async (req, res) => {
    try {
        if (!mongoose.isValidObjectId(req.params.id)) {
            return res.status(400).json({ error: "Invalid id" });
        }
        const deleted = await Student.findByIdAndDelete(req.params.id);
        if (!deleted) return res.status(404).json({ error: "Student not found" });
        res.json({ message: "Deleted", id: deleted._id });
    } catch (err) {
        res.status(500).json({ error: "Server error" });
    }
});

// ANALYTICS (aggregation from Unit IV)
app.get("/stats/branch", async (req, res) => {
    try {
        const stats = await Student.aggregate([
            { $group: {
                _id: "$branch",
                studentCount: { $sum: 1 },
                averageCgpa: { $avg: "$cgpa" }
            } },
            { $sort: { averageCgpa: -1 } }
        ]);
        res.json(stats);
    } catch (err) {
        res.status(500).json({ error: "Server error" });
    }
});

const PORT = process.env.PORT || 3000;

connectDB().then(() => {
    app.listen(PORT, () => console.log(`🚀 Server running on port ${PORT}`));
});
```

Run:

```

🚀 Server running on port 3000
```

## 28. HTTP status codes you must know

| Code | Meaning | Used when |
|--------|-----------|--------------|
| 200 | OK | successful read/update |
| 201 | Created | successful create |
| 400 | Bad Request | invalid input / validation error |
| 404 | Not Found | no such document |
| 409 | Conflict | duplicate key |
| 500 | Server Error | unexpected failure |

## 29. Dry run: `POST /students`

```
1. Client sends JSON body
2. express.json() parses it into req.body
3. Route handler runs Student.create(req.body)
4. Mongoose: defaults → casting → validation
5. Validation OK → driver inserts into MongoDB
6. MongoDB checks unique index on email
7. Success → 201 + JSON of new student
   Failure → 400 (validation) or 409 (duplicate)
```

## 30. Security awareness (brief but important) 🚨

1. **Never trust request data.** `req.body` can contain anything.
2. **NoSQL injection:** if you pass `req.query` or `req.body` straight into a filter, an attacker may send operators such as `{"$ne": null}`. Build filters explicitly from known fields, as in the example above.
3. **Do not return secrets** (password hashes) in responses; use `select("-password")`.
4. **Keep credentials in `.env`.**
5. **Mass assignment:** `{ $set: req.body }` lets a client change any field. In real apps, whitelist allowed fields.

You are not expected to build full security here, but you should recognize these risks.

## 31. Native driver version of one CRUD cycle (for comparison)

```js
const { MongoClient, ObjectId } = require("mongodb");

const client = new MongoClient(process.env.MONGODB_URI);

async function run() {
    await client.connect();
    const students = client.db("collegeDB").collection("students");

    const { insertedId } = await students.insertOne({ name: "Rahul", cgpa: 8.7 });
    const one = await students.findOne({ _id: insertedId });
    await students.updateOne({ _id: insertedId }, { $set: { cgpa: 9.0 } });
    const all = await students.find({ cgpa: { $gte: 8 } }).toArray();
    await students.deleteOne({ _id: new ObjectId(insertedId) });

    console.log(one, all.length);
    await client.close();
}
run();
```

Differences to notice:

```
find() returns a cursor → call .toArray()
No schema, no validation, no defaults
ObjectId must be handled manually for string ids
```

## 33. 🔥 PART 3 — WHAT YOU MUST REMEMBER

**Mongoose create?**

> `Model.create()` or `new Model().save()`.

**Return value of `find()` vs `findOne()`?**

> `find()` → array; `findOne()` → one document or `null`.

**What does `{ new: true }` do?**

> Returns the updated document instead of the old one.

**Why `runValidators: true`?**

> Update operations skip many schema validators unless it is set.

**What does `lean()` do?**

> Returns plain JavaScript objects for faster read-only use.

**`populate()` vs `$lookup`?**

> `populate()` runs extra queries from Mongoose; `$lookup` joins inside MongoDB in one aggregation.

**CRUD ↔ HTTP?**

> POST create, GET read, PUT/PATCH update, DELETE delete.

**Aggregation in Mongoose?**

> `Model.aggregate([...])`; no automatic casting, so convert `ObjectId` yourself.

## 🚨 Common traps

1. Forgetting `await`, then sending a Promise instead of data.
2. Not checking for `null` from `findOne`/`findById`.
3. Updating without `runValidators` and assuming validation ran.
4. Forgetting `{ new: true }` and returning stale data.
5. `deleteMany({})` deleting everything.
6. Passing `req.body` / `req.query` directly into filters (NoSQL injection, mass assignment).
7. Using string IDs in `aggregate()` `$match` without converting to `ObjectId`.
8. Forgetting `express.json()`, so `req.body` is `undefined`.
9. Using `skip()` for deep pagination on huge collections.
10. Opening a new connection inside each route.
