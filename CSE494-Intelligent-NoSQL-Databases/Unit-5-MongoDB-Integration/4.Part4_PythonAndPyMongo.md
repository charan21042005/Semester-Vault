## 5. `MongoClient` in Python

```python
from pymongo import MongoClient

client = MongoClient("mongodb://localhost:27017")
```

Then the chain you already know:

```
client  →  database  →  collection  →  operations
```

Two equivalent syntaxes:

```python
# Dictionary style (always works — even for names with dashes/spaces)
db = client["collegeDB"]
students = db["students"]

# Attribute style (shorter; only for "simple" names)
db = client.collegeDB
students = db.students
```

Compare all three worlds:

| Step                    | mongosh              | Node.js                          | Python                          |
|---------------------------|--------------------------|-------------------------------------|-------------------------------------|
| Pick DB                      | `use collegeDB`              | `client.db("collegeDB")`                | `client["collegeDB"]`                  |
| Pick collection                | `db.students`                  | `db.collection("students")`                | `db["students"]`                          |
| Insert                           | `insertOne({...})`               | `await insertOne({...})`                      | `insert_one({...})`                         |

🚨 Notice the **naming style**: PyMongo uses Python's `snake_case` (`insert_one`, `find_one`, `update_many`), while Node and the shell use `camelCase` (`insertOne`, `findOne`, `updateMany`). Same operations, different spelling.

## 6. Python has no `await` here (PyMongo is synchronous)

PyMongo's normal API is **synchronous (blocking)**: the line runs, waits for MongoDB, then continues.

```python
result = students.insert_one({"name": "Rahul"})   # waits here until done
print(result.inserted_id)
```

No `async`, no `await`, no Promises. That's one reason many beginners find PyMongo gentler than Node.

> MongoDB also offers an official asynchronous Python driver for `asyncio` applications (an async API in PyMongo for frameworks like FastAPI). For your syllabus and labs, the classic synchronous PyMongo is what matters.

```
Node.js driver → async (Promises, await)
PyMongo        → synchronous by default
```

## 7. The ping test

`ping.py`:

```python
import os
from dotenv import load_dotenv
from pymongo import MongoClient
from pymongo.errors import PyMongoError

load_dotenv()

client = MongoClient(os.getenv("MONGODB_URI"), serverSelectionTimeoutMS=5000)

try:
    client.admin.command("ping")
    print("✅ Connected to MongoDB")
except PyMongoError as e:
    print("❌ Connection failed:", e)
finally:
    client.close()
```

Run:

```bash
python ping.py
```

### Dry run

```
MongoClient(uri, ...)     → client object created (lazy: connects in the background)
admin.command("ping")     → first real network request → forces server selection
except PyMongoError       → catches ALL PyMongo-related errors
finally: client.close()   → release connections
```

### Lazy connection — important!

```python
client = MongoClient("mongodb://wrong-host:27017")
print("No error yet!")          # this line STILL prints
```

`MongoClient(...)` does **not** fail for a bad host — PyMongo connects lazily in the background. The error appears at your **first operation**. That's why we use `ping` to test.

### `serverSelectionTimeoutMS`

By default PyMongo waits about 30 seconds trying to find a server before raising `ServerSelectionTimeoutError`. Lowering it to 5000 ms makes failures show up faster while you're developing.

## 9. Closing the client cleanly: the `with` pattern

```python
from pymongo import MongoClient

with MongoClient("mongodb://localhost:27017") as client:
    db = client["collegeDB"]
    print(db.students.count_documents({}))
# client.close() is called automatically here, even if an error happened
```

```
with-block  =  try/finally that you don't have to write yourself
```

For scripts, this is the cleanest style. For web apps, create **one** client at startup and keep it (next section).

## 10. Connection pooling in PyMongo

Same idea as Node:

> `MongoClient` maintains a connection pool and is **thread-safe**. You should create one `MongoClient` per process and reuse it.

```
✅ ONE client for the whole program
❌ A new MongoClient inside every function call or every web request
```

A tidy shared module — `db.py`:

```python
import os
from dotenv import load_dotenv
from pymongo import MongoClient

load_dotenv()

_client = MongoClient(os.getenv("MONGODB_URI"))
db = _client[os.getenv("DB_NAME", "collegeDB")]
```

Now any file can do:

```python
from db import db
students = db["students"]
```

Python caches modules after the first import, so `db.py` runs **once** and everyone shares the same client.

🚨 Special advanced warning: if a program uses `fork()` (e.g. certain multiprocessing or pre-fork web servers), create the client **after** forking, in each child process — a `MongoClient` must not be shared across forked processes.

## 11. `ObjectId` in Python

```python
from bson import ObjectId

new_id = ObjectId()
print(new_id)                      # 6650f1a2b3c4d5e6f7a8b9c0
print(str(new_id))                 # as a plain string
```

(`bson` ships with PyMongo — you do **not** install a separate package. Do not `pip install bson`; that is a different, unrelated library that can conflict.)

Find by id — the same trap as Node:

```python
# ❌ WRONG: _id stored as ObjectId, you passed a str
students.find_one({"_id": "6650f1a2b3c4d5e6f7a8b9c0"})

# ✅ RIGHT
students.find_one({"_id": ObjectId("6650f1a2b3c4d5e6f7a8b9c0")})
```

If the string isn't a valid 24-character hex id, `ObjectId(...)` raises `bson.errors.InvalidId`.

Useful: an ObjectId contains a creation timestamp.

```python
print(new_id.generation_time)       # datetime when the id was created
```

## 12. Dates and time zones — a real-world trap

```python
from datetime import datetime, timezone

students.insert_one({
    "name": "Rahul",
    "joined": datetime.now(timezone.utc)      # ✅ timezone-aware UTC
})
```

MongoDB stores dates as **UTC**. If you pass a *naive* `datetime.now()` (no timezone), PyMongo treats it as UTC without converting from your local time (India = UTC+5:30), so stored values can be off by hours.

By default, PyMongo returns datetimes as **naive UTC** datetimes. To get timezone-aware ones, connect with:

```python
client = MongoClient(uri, tz_aware=True)
```

```
Rule: always store timezone-aware UTC datetimes: datetime.now(timezone.utc)
```

## 13. First complete script — insert then read

`first.py`:

```python
from db import db
from pprint import pprint

students = db["students"]

# CREATE
result = students.insert_one({
    "name": "Rahul",
    "branch": "CSE",
    "cgpa": 8.7
})
print("Inserted _id:", result.inserted_id)

# READ
found = students.find_one({"name": "Rahul"})
pprint(found)
```

Run `python first.py`. Output (conceptually):

```
Inserted _id: 6650f1a2b3c4d5e6f7a8b9c0
{'_id': ObjectId('6650f1a2b3c4d5e6f7a8b9c0'),
 'branch': 'CSE',
 'cgpa': 8.7,
 'name': 'Rahul'}
```

(`pprint` = "pretty print", sorts keys alphabetically for display only.)

### Dry run

```
insert_one({...})  → returns InsertOneResult; .inserted_id holds the new _id
find_one({...})    → returns ONE dict, or None if nothing matches
```

Also remember:

```
insert_one() mutates your dict: PyMongo adds "_id" to the dict you passed in!
```

```python
doc = {"name": "Priya"}
students.insert_one(doc)
print(doc)          # {'name': 'Priya', '_id': ObjectId('...')}
```

That surprises beginners. And inserting the **same dict object** twice raises a duplicate-key error (same `_id`), because it now carries its `_id`.

## 14. Cursors in Python

`find()` returns a **cursor**, same idea as Node:

```python
cursor = students.find({"branch": "CSE"})
print(cursor)                        # <pymongo.cursor.Cursor object ...>
```

Consume it:

```python
# loop one by one (memory-friendly)
for doc in students.find({"branch": "CSE"}):
    print(doc["name"])

# all at once into a list
cse_list = list(students.find({"branch": "CSE"}))
```

🚨 A cursor can be consumed **only once**:

```python
cur = students.find()
a = list(cur)
b = list(cur)       # b is [] — the cursor is already exhausted
```

Chaining (Unit II/IV ideas again):

```python
from pymongo import DESCENDING

top3 = (
    students
    .find({"branch": "CSE"}, {"name": 1, "cgpa": 1, "_id": 0})   # filter, projection
    .sort("cgpa", DESCENDING)
    .limit(3)
)
for s in top3:
    print(s)
```

Note the **different shape from JavaScript**:

```
JS:      .find(filter).project({...}).sort({ cgpa: -1 }).limit(3)
Python:  .find(filter, projection).sort("cgpa", -1).limit(3)
```

- Projection is the **2nd argument** of `find()` in Python.
- `sort` takes `(field, direction)` — or a **list** of tuples for several fields: `.sort([("branch", 1), ("cgpa", -1)])`.
- `pymongo.ASCENDING` = `1`, `pymongo.DESCENDING` = `-1`.

(Reason: Python dicts are ordered in modern Python, but PyMongo's sort API still takes lists of tuples to make field order explicit.)

## 15. Errors in PyMongo

All PyMongo errors inherit from `pymongo.errors.PyMongoError`.

| Exception                         | Meaning                                            |
|--------------------------------------|--------------------------------------------------------|
| `ServerSelectionTimeoutError`           | Can't find/reach a server (down, bad host, Atlas IP block) |
| `ConnectionFailure`                       | Network-level connection problem                          |
| `OperationFailure`                          | Server rejected the operation (e.g. authentication, bad command) |
| `DuplicateKeyError`                           | Unique index violated (error code 11000)                     |
| `BulkWriteError`                                | Some operations in a bulk/many insert failed                    |
| `bson.errors.InvalidId`                           | Bad ObjectId string                                              |

Pattern:

```python
from pymongo.errors import DuplicateKeyError, PyMongoError

try:
    students.insert_one(doc)
except DuplicateKeyError:
    print("Already exists")
except PyMongoError as e:
    print("Database problem:", e)
```

Order matters: put **specific** exceptions first, the general `PyMongoError` last.

## 16. Node.js vs Python — the big comparison

| Feature                     | Node.js (`mongodb`)              | Python (PyMongo)                      |
|--------------------------------|--------------------------------------|-------------------------------------------|
| Install                           | `npm install mongodb`                    | `pip install pymongo`                         |
| Import                              | `import { MongoClient } from "mongodb"`    | `from pymongo import MongoClient`                |
| Style of method names                 | `insertOne`, `findOne` (camelCase)            | `insert_one`, `find_one` (snake_case)               |
| Sync/async                              | Always Promises → `await`                        | Synchronous by default                                |
| Find result                               | Cursor → `.toArray()`                             | Cursor → `list(cursor)` / `for`                          |
| Documents                                   | JS objects                                          | Python dicts                                                |
| Null                                          | `null`                                                | `None`                                                        |
| ObjectId                                        | `new ObjectId(str)`                                     | `ObjectId(str)` from `bson`                                     |
| Result id                                         | `result.insertedId`                                        | `result.inserted_id`                                              |
| Error class                                         | `MongoServerError` (check `err.code`)                        | `PyMongoError` family (`DuplicateKeyError`)                         |
| Optional schema layer                                 | Mongoose                                                        | ODMs exist (e.g. MongoEngine, Beanie) but are optional               |
| Typical use                                             | Web APIs, real-time apps                                          | Data science, ML, scripting, APIs                                      |

Memory trick:

```
camelCase  → JavaScript, Java, mongosh
snake_case → Python
```

## 17. Python has no "Mongoose" built in — what do people do?

PyMongo is like the **native driver**: flexible, no schema. If you need validation:

```
Option 1: validate manually in Python (plain functions)
Option 2: use a data-validation library such as Pydantic in the app layer
Option 3: use a Python ODM (MongoEngine, Beanie, etc.)
Option 4: use MongoDB's own JSON Schema validation on the collection (database-level)
```

For your syllabus, PyMongo + manual checks is enough. A simple validation function:

```python
def validate_student(s: dict) -> list[str]:
    errors = []
    if not isinstance(s.get("name"), str) or len(s["name"].strip()) < 2:
        errors.append("name must be a string of at least 2 characters")
    if s.get("branch") not in {"CSE", "ECE", "EEE", "ME"}:
        errors.append("branch must be CSE, ECE, EEE or ME")
    cgpa = s.get("cgpa")
    if not isinstance(cgpa, (int, float)) or not (0 <= cgpa <= 10):
        errors.append("cgpa must be a number between 0 and 10")
    return errors
```

Usage:

```python
problems = validate_student(student)
if problems:
    print("Rejected:", problems)
else:
    students.insert_one(student)
```

## 19. Common traps 🚨

### Trap 1 — `pip install bson`

Don't. `bson` comes **inside PyMongo**. The separate PyPI package named `bson` clashes with it.

### Trap 2 — Thinking `MongoClient()` fails immediately

It connects lazily. Use `client.admin.command("ping")` to test.

### Trap 3 — Creating a client per function/request

One `MongoClient` per process.

### Trap 4 — String vs ObjectId

`find_one({"_id": "..."})` finds nothing. Convert with `ObjectId(...)`.

### Trap 5 — Reusing an exhausted cursor

A cursor is consumed once. Wrap in `list()` if you need to reuse.

### Trap 6 — Naive datetimes

Use `datetime.now(timezone.utc)`.

### Trap 7 — Passing the same dict to `insert_one` twice

PyMongo adds `_id` to it; the second insert raises `DuplicateKeyError`.

### Trap 8 — Wrong Python capitalization

`true`, `false`, `null` are JavaScript. Python uses `True`, `False`, `None`.

### Trap 9 — Committing `.env` or `venv/`

Add both to `.gitignore`.

### Trap 10 — Forgetting the virtual environment

"ModuleNotFoundError: No module named 'pymongo'" usually means you installed PyMongo in one environment and ran the script in another.
