# 🟢 C — CREATE

## 3. `insert_one()`

```python
result = students.insert_one({
    "name": "Rahul",
    "email": "rahul@gmail.com",
    "branch": "CSE",
    "year": 4,
    "cgpa": 8.7,
    "skills": ["Python", "MongoDB"]
})

print(result.inserted_id)
print(result.acknowledged)
```

The function returns an `InsertOneResult`:

```
inserted_id   → the new _id
acknowledged  → True if the server confirmed the write
```

If you don't provide `_id`, MongoDB generates an `ObjectId`.

Also useful:

> PyMongo adds the `_id` to your original dictionary in memory after insert. If you reuse the same dict for another insert, you'll get a duplicate key error. Create a fresh dict each time.

## 4. `insert_many()`

```python
result = students.insert_many([
    {"name": "Priya", "email": "priya@gmail.com", "branch": "ECE", "year": 4, "cgpa": 9.1},
    {"name": "Arjun", "email": "arjun@gmail.com", "branch": "CSE", "year": 3, "cgpa": 7.8},
    {"name": "Sneha", "email": "sneha@gmail.com", "branch": "CSE", "year": 4, "cgpa": 8.9},
    {"name": "Karan", "email": "karan@gmail.com", "branch": "EEE", "year": 2, "cgpa": 8.1}
])

print(len(result.inserted_ids), "documents inserted")
```

By default it is **ordered**: if one fails, later documents are not inserted. For independent documents, use:

```python
students.insert_many(docs, ordered=False)
```

# 🔵 R — READ

## 5. `find_one()`

```python
doc = students.find_one({"name": "Rahul"})
if doc is None:
    print("Not found")
else:
    print(doc["cgpa"])
```

Returns a dict or `None`.

## 6. `find()` returns a CURSOR, not a list

```python
cursor = students.find({"branch": "CSE"})
```

Key concept:

```
find()  →  Cursor (lazy iterator)
          documents are fetched in batches as you loop
```

Ways to use it:

```python
# loop
for s in cursor:
    print(s["name"], s["cgpa"])

# convert to list (loads everything into memory)
all_cse = list(students.find({"branch": "CSE"}))
```

Trap 🚨: a cursor can be consumed only once. Looping a second time gives nothing. Re-run `find()` or convert to a list first.

Also, never `list()` a huge collection casually. That may exhaust memory.

## 7. Filters with operators

```python
students.find({"cgpa": {"$gte": 8.5}})
students.find({"branch": {"$in": ["CSE", "ECE"]}})
students.find({"$or": [{"branch": "ECE"}, {"cgpa": {"$gt": 9}}]})
students.find({"skills": "MongoDB"})                    # array contains
students.find({"address.city": "Amritsar"})             # nested field
students.find({"name": {"$regex": "^R", "$options": "i"}})
```

Same operator language as Unit II.

## 8. Projection

Second argument:

```python
students.find({"branch": "CSE"}, {"name": 1, "cgpa": 1, "_id": 0})
```

Same projection rules as the shell:

```
1 → include
0 → exclude
Don't mix include and exclude (except _id)
```

## 9. `sort`, `limit`, `skip`

```python
from pymongo import ASCENDING, DESCENDING

top3 = students.find({"branch": "CSE"}) \
               .sort("cgpa", DESCENDING) \
               .limit(3)

for s in top3:
    print(s["name"], s["cgpa"])
```

Sorting syntax differs slightly from JavaScript:

```
JavaScript:  .sort({ cgpa: -1 })
Python:      .sort("cgpa", -1)         or .sort("cgpa", DESCENDING)
Multi-key:   .sort([("branch", 1), ("cgpa", -1)])
```

Trap 🚨: in PyMongo, multi-field sort needs a **list of tuples** (dictionaries don't preserve intent in older Python versions).

Pagination:

```python
page, size = 2, 10
cursor = students.find().sort("name", 1).skip((page - 1) * size).limit(size)
```

## 10. Counting and distinct

```python
total = students.count_documents({"branch": "CSE"})
branches = students.distinct("branch")
print(total, branches)
```

`count_documents({})` counts all documents. (There is an older `count()` that is deprecated; use `count_documents`.)

## 11. Converting for display or JSON

```python
for s in students.find():
    s["_id"] = str(s["_id"])     # make it printable/JSON-friendly
    print(s)
```

or use `bson.json_util`:

```python
from bson import json_util
import json

docs = list(students.find({"branch": "CSE"}))
print(json.dumps(docs, default=json_util.default, indent=2))
```

# 🟠 U — UPDATE

## 12. `update_one()`

```python
result = students.update_one(
    {"name": "Rahul"},
    {"$set": {"cgpa": 8.9}}
)

print(result.matched_count, result.modified_count)
```

```
matched_count   → documents that matched the filter
modified_count  → documents actually changed
```

If you set a field to the value it already has, `matched_count` is 1 but `modified_count` is 0. 🔥 A classic viva question.

## 13. `update_many()`

```python
students.update_many({"year": 3}, {"$inc": {"year": 1}})
```

## 14. Update operators

| Operator | Use |
|-------------|--------|
| `$set` | set field |
| `$unset` | remove field |
| `$inc` | add/subtract numbers |
| `$mul` | multiply |
| `$rename` | rename field |
| `$push` | append to array |
| `$addToSet` | append if absent |
| `$pull` | remove matching elements |
| `$pop` | remove first/last |

Examples:

```python
students.update_one({"name": "Rahul"}, {"$push": {"skills": "Docker"}})
students.update_one({"name": "Rahul"}, {"$addToSet": {"skills": "Docker"}})
students.update_one({"name": "Rahul"}, {"$pull": {"skills": "C++"}})
students.update_one({"name": "Rahul"}, {"$unset": {"hobby": ""}})
```

Trap 🚨:

```python
students.update_one({"name": "Rahul"}, {"cgpa": 9.0})   # ❌ error: update needs operators
```

Without an update operator PyMongo raises an error. Use `$set`, or use `replace_one` to replace the whole document.

## 15. `replace_one()`

```python
students.replace_one(
    {"name": "Karan"},
    {"name": "Karan", "branch": "EEE", "year": 3, "cgpa": 8.3}
)
```

```
update_one  + $set → change specific fields
replace_one        → swap the entire document (keeps _id)
```

## 16. Upsert

```python
students.update_one(
    {"email": "new@gmail.com"},
    {"$set": {"name": "New Student", "branch": "CSE"}},
    upsert=True
)
```

Update if it exists, otherwise insert. Check `result.upserted_id` to see whether it inserted.

## 17. `find_one_and_update()` — update and get the document back

```python
from pymongo import ReturnDocument

updated = students.find_one_and_update(
    {"name": "Priya"},
    {"$set": {"cgpa": 9.3}},
    return_document=ReturnDocument.AFTER
)
print(updated)
```

```
ReturnDocument.AFTER  → the updated document
ReturnDocument.BEFORE → the original (default)
```

Same idea as `{ new: true }` in Mongoose.

# 🟣 INDEXES FROM PYTHON (Unit IV connection)

## 20. Create, list, drop

```python
from pymongo import ASCENDING, DESCENDING

# single-field, unique
students.create_index([("email", ASCENDING)], unique=True)

# compound
students.create_index([("branch", ASCENDING), ("cgpa", DESCENDING)])

# text
students.create_index([("name", "text"), ("skills", "text")])

# list
for idx in students.list_indexes():
    print(idx["name"], idx["key"])

# drop by name
students.drop_index("branch_1_cgpa_-1")
```

Note the Python syntax: index keys are a **list of `(field, direction)` tuples**, which preserves field order for compound indexes. Order matters in compound indexes (Unit IV Part 3), so this form makes it explicit. 🔥

`create_index` is safe to call repeatedly if the same index already exists.

## 21. `explain()` from Python

```python
plan = students.find({"branch": "CSE"}).explain()
print(plan["queryPlanner"]["winningPlan"])
```

PyMongo's cursor `.explain()` returns the plan information as a dictionary. To get execution statistics like in Unit IV:

```python
stats = db.command(
    "explain",
    {"find": "students", "filter": {"branch": "CSE"}},
    verbosity="executionStats"
)

es = stats["executionStats"]
print("nReturned:", es["nReturned"])
print("totalKeysExamined:", es["totalKeysExamined"])
print("totalDocsExamined:", es["totalDocsExamined"])
print("executionTimeMillis:", es["executionTimeMillis"])
```

Same four numbers from Unit IV Part 5/6. Now they're in code, which becomes important for Part 7 (automated optimization). 🔥

Useful helper to see the stage type:

```python
def stage_of(plan):
    node = plan["queryPlanner"]["winningPlan"]
    while "inputStage" in node:
        node = node["inputStage"]
    return node["stage"]          # e.g. "IXSCAN" or "COLLSCAN"
```

(This simple helper follows single-input plans; real plans can branch.)

# 🟤 AGGREGATION FROM PYTHON

## 22. `aggregate()`

Pipelines are lists of dictionaries.

```python
pipeline = [
    {"$match": {"year": 4}},
    {"$group": {
        "_id": "$branch",
        "studentCount": {"$sum": 1},
        "averageCgpa": {"$avg": "$cgpa"}
    }},
    {"$sort": {"averageCgpa": -1}}
]

for row in students.aggregate(pipeline):
    print(row)
```

Output (shape):

```
{'_id': 'ECE', 'studentCount': 1, 'averageCgpa': 9.1}
{'_id': 'CSE', 'studentCount': 2, 'averageCgpa': 8.8}
```

Everything you wrote in Unit IV Parts 7 to 9 works unchanged. The only conversions:

```
JavaScript   →  Python
{ $sum: 1 }  →  {"$sum": 1}        (keys quoted)
true / null  →  True / None
```

### Top skills example (`$unwind`)

```python
pipeline = [
    {"$unwind": "$skills"},
    {"$group": {"_id": "$skills", "count": {"$sum": 1}}},
    {"$sort": {"count": -1}},
    {"$limit": 5}
]
print(list(students.aggregate(pipeline)))
```

### E-commerce revenue example

```python
orders = db["orders"]

pipeline = [
    {"$match": {"status": "completed"}},
    {"$unwind": "$items"},
    {"$set": {"revenue": {"$multiply": ["$items.price", "$items.quantity"]}}},
    {"$group": {"_id": "$items.product", "totalRevenue": {"$sum": "$revenue"}}},
    {"$sort": {"totalRevenue": -1}},
    {"$limit": 3}
]

for r in orders.aggregate(pipeline):
    print(r)
```

Same pipeline you saw in Unit IV Part 9, now running from Python. 🔥

# ⚡ BULK WRITES

## 23. `bulk_write()`

Mix different operations in one round trip:

```python
from pymongo import InsertOne, UpdateOne, DeleteOne

ops = [
    InsertOne({"name": "Zoya", "branch": "CSE", "cgpa": 8.0}),
    UpdateOne({"name": "Rahul"}, {"$inc": {"cgpa": 0.1}}),
    DeleteOne({"name": "Karan"})
]

result = students.bulk_write(ops)
print(result.inserted_count, result.modified_count, result.deleted_count)
```

Fewer network round trips means better performance for large batches.

# 🛡️ VALIDATION IN PYTHON

## 24. There is no built-in schema in PyMongo

Unlike Mongoose, PyMongo is schema-less on the client side. Options:

1. **Database-side validation** (Unit III): `$jsonSchema` validators on the collection.
2. **Your own validation function** in Python.
3. A validation library (for example Pydantic) in larger projects.

Simple custom validator:

```python
ALLOWED_BRANCHES = {"CSE", "ECE", "EEE", "ME", "CE"}

def validate_student(s):
    errors = []
    if not s.get("name"):
        errors.append("name is required")
    if s.get("branch") not in ALLOWED_BRANCHES:
        errors.append("branch must be one of " + ", ".join(sorted(ALLOWED_BRANCHES)))
    cgpa = s.get("cgpa")
    if cgpa is not None and not (isinstance(cgpa, (int, float)) and 0 <= cgpa <= 10):
        errors.append("cgpa must be a number between 0 and 10")
    return errors
```

Server-side validator from Python (Unit III link):

```python
db.create_collection("employees", validator={
    "$jsonSchema": {
        "bsonType": "object",
        "required": ["name", "salary"],
        "properties": {
            "name": {"bsonType": "string"},
            "salary": {"bsonType": ["int", "long", "double"], "minimum": 0}
        }
    }
})
```

Invalid inserts then raise `pymongo.errors.WriteError`.

# 🚨 ERROR HANDLING

## 25. Important exceptions

```python
from pymongo.errors import (
    PyMongoError, DuplicateKeyError, BulkWriteError, ServerSelectionTimeoutError
)
```

| Exception | When |
|--------------|---------|
| `DuplicateKeyError` | unique index violated (error code 11000) |
| `BulkWriteError` | a bulk/`insert_many` operation had failures |
| `ServerSelectionTimeoutError` | cannot reach a server |
| `WriteError` | write rejected (e.g., validator failed) |
| `PyMongoError` | base class for all PyMongo errors |

Pattern:

```python
try:
    students.insert_one({"name": "Dup", "email": "rahul@gmail.com"})
except DuplicateKeyError:
    print("A student with this email already exists")
except PyMongoError as e:
    print("Database error:", e)
```

Order matters: catch specific exceptions **before** the general `PyMongoError`.

# 🧩 COMPLETE CRUD MODULE

## 26. `crud.py`

```python
from bson.objectid import ObjectId
from bson.errors import InvalidId
from pymongo import ReturnDocument, DESCENDING
from pymongo.errors import DuplicateKeyError
from db import students

students.create_index("email", unique=True)

def to_oid(id_str):
    try:
        return ObjectId(id_str)
    except (InvalidId, TypeError):
        return None

def create_student(data):
    try:
        res = students.insert_one(data)
        return {"ok": True, "id": str(res.inserted_id)}
    except DuplicateKeyError:
        return {"ok": False, "error": "duplicate email"}

def get_student(id_str):
    oid = to_oid(id_str)
    if oid is None:
        return None
    return students.find_one({"_id": oid})

def list_students(branch=None, min_cgpa=None, limit=20):
    flt = {}
    if branch:
        flt["branch"] = branch
    if min_cgpa is not None:
        flt["cgpa"] = {"$gte": float(min_cgpa)}
    return list(students.find(flt).sort("cgpa", DESCENDING).limit(limit))

def update_cgpa(id_str, new_cgpa):
    oid = to_oid(id_str)
    if oid is None or not (0 <= new_cgpa <= 10):
        return None
    return students.find_one_and_update(
        {"_id": oid},
        {"$set": {"cgpa": new_cgpa}},
        return_document=ReturnDocument.AFTER
    )

def delete_student(id_str):
    oid = to_oid(id_str)
    if oid is None:
        return 0
    return students.delete_one({"_id": oid}).deleted_count

def branch_stats():
    return list(students.aggregate([
        {"$group": {"_id": "$branch",
                    "count": {"$sum": 1},
                    "avgCgpa": {"$avg": "$cgpa"}}},
        {"$sort": {"avgCgpa": -1}}
    ]))
```

Test script `app.py`:

```python
from crud import *

print(create_student({"name": "Rahul", "email": "rahul@gmail.com",
                      "branch": "CSE", "year": 4, "cgpa": 8.7}))
print(create_student({"name": "Rahul2", "email": "rahul@gmail.com",
                      "branch": "CSE", "year": 4, "cgpa": 8.0}))   # duplicate

for s in list_students(branch="CSE"):
    print(s["name"], s["cgpa"])

print(branch_stats())
```

Dry run:

```
1st create_student → inserted, returns id
2nd create_student → unique index violated → DuplicateKeyError → {"ok": False}
list_students     → filter by branch, sort by CGPA descending
branch_stats      → aggregation pipeline from Unit IV
```

## 27. Tiny menu-driven app (lab style)

```python
from crud import create_student, list_students, update_cgpa, delete_student

def menu():
    while True:
        print("\n1.Add  2.List  3.Update CGPA  4.Delete  5.Exit")
        choice = input("Choose: ").strip()

        if choice == "1":
            name = input("Name: ")
            email = input("Email: ")
            branch = input("Branch: ")
            cgpa = float(input("CGPA: "))
            print(create_student({"name": name, "email": email,
                                  "branch": branch, "cgpa": cgpa}))
        elif choice == "2":
            for s in list_students():
                print(s["_id"], s["name"], s["branch"], s["cgpa"])
        elif choice == "3":
            sid = input("Student id: ")
            new = float(input("New CGPA: "))
            print(update_cgpa(sid, new))
        elif choice == "4":
            print("Deleted:", delete_student(input("Student id: ")))
        elif choice == "5":
            break
        else:
            print("Invalid choice")

menu()
```

This is a typical lab/practical shape: Python app + MongoDB, CRUD through a menu.

## 28. Node.js vs Python — full CRUD comparison

| Task | Node.js (Mongoose) | Python (PyMongo) |
|--------|------------------------|----------------------|
| Insert one | `await Student.create({...})` | `students.insert_one({...})` |
| Find all | `await Student.find()` | `list(students.find())` |
| Find one | `await Student.findOne({...})` | `students.find_one({...})` |
| Update | `await Student.updateOne(f, {$set:{}})` | `students.update_one(f, {"$set": {}})` |
| Return updated | `{ new: true }` | `ReturnDocument.AFTER` |
| Delete | `await Student.deleteOne(f)` | `students.delete_one(f)` |
| Validation | Schema validators | Own code / `$jsonSchema` |
| Sort | `.sort({cgpa:-1})` | `.sort("cgpa", -1)` |
| Async | Required (`await`) | Not needed (sync) |
| ObjectId | auto-cast in Mongoose | convert manually |

## 30. 🔥 PART 5 — WHAT YOU MUST REMEMBER

**What does `find()` return?**

> A cursor (lazy iterator), not a list. Use a loop or `list(...)`.

**`find_one()` with no match?**

> Returns `None`.

**`matched_count` vs `modified_count`?**

> Matched = documents that matched the filter; modified = documents that actually changed.

**Update without `$set`?**

> Error. Updates need operators; `replace_one` replaces the whole document.

**How to get the updated document back?**

> `find_one_and_update(..., return_document=ReturnDocument.AFTER)`.

**Index key syntax in PyMongo?**

> A list of `(field, direction)` tuples, e.g. `[("branch", 1), ("cgpa", -1)]`.

**Duplicate unique-key error?**

> `DuplicateKeyError` (code 11000).

**Aggregation in Python?**

> `collection.aggregate(list_of_stage_dicts)`; same Unit IV pipelines with Python syntax.

---

## 🚨 Common traps

1. Looping over a cursor twice (second loop is empty).
2. Using `list(find())` on a huge collection.
3. `update_one(filter, {"field": value})` without `$set`.
4. Reusing an inserted dictionary (it now contains `_id`).
5. Querying `_id` with a string.
6. Multi-field sort with a dict instead of a list of tuples.
7. Catching `PyMongoError` before specific exceptions.
8. Using the deprecated `count()`.
9. `delete_many({})` by accident.
10. Trying to JSON-dump documents with `ObjectId`/`datetime` directly.
