## 2. `insert_one`

```python
result = students.insert_one({
    "name": "Rahul",
    "branch": "CSE",
    "cgpa": 8.7,
    "year": 4,
    "skills": ["Python", "MongoDB"]
})

print(result.acknowledged)      # True
print(result.inserted_id)       # ObjectId('...')
```

Compare with Node: `await students.insertOne({...})` → `result.insertedId`.

```
Node:    insertOne   → insertedId
Python:  insert_one  → inserted_id
```

## 3. `insert_many`

```python
result = students.insert_many([
    {"name": "Priya", "branch": "ECE", "cgpa": 9.1, "year": 4},
    {"name": "Arjun", "branch": "CSE", "cgpa": 7.8, "year": 3},
    {"name": "Sneha", "branch": "CSE", "cgpa": 8.9, "year": 4},
])

print(len(result.inserted_ids))     # 3
print(result.inserted_ids)          # [ObjectId, ObjectId, ObjectId]
```

### Ordered vs unordered

```python
students.insert_many(docs, ordered=False)
```

```
ordered=True  (default) → stops at the first failing document
ordered=False           → tries all; raises BulkWriteError at the end listing failures
```

An important Part 4 reminder: `insert_one`/`insert_many` **add `_id` to your dicts**. If you need to re-insert the same data, build fresh dicts or `copy()` them.

```python
# one document (dict) or None
one = students.find_one({"name": "Rahul"})

for s in students.find({"branch": "CSE"}):

```

By `_id`:

```python
from bson import ObjectId

```

## 5. Query operators in Python

Identical to Unit II — they're just strings inside dicts.

```python
students.find({"cgpa": {"$gte": 8.5}})
students.find({"year": {"$in": [3, 4]}})
students.find({"branch": {"$ne": "ME"}})

# logical
students.find({"$or": [{"branch": "CSE"}, {"cgpa": {"$gt": 9}}]})
students.find({"branch": "CSE", "cgpa": {"$gte": 8}})           # implicit AND

# arrays
students.find({"skills": "MongoDB"})
students.find({"skills": {"$all": ["Python", "MongoDB"]}})

# nested field (dot notation, in quotes)
students.find({"address.city": "Amritsar"})

# existence
students.find({"phone": {"$exists": True}})                      # True, not true!

# regex
students.find({"name": {"$regex": "^ra", "$options": "i"}})
```

🚨 In Python write `True`, `False`, `None` — not `true`, `false`, `null`.

## 6. Projection, sort, limit, skip

```python
from pymongo import ASCENDING, DESCENDING

cursor = (
    students
    .find({"branch": "CSE"}, {"name": 1, "cgpa": 1, "_id": 0})   # filter + projection
    .sort("cgpa", DESCENDING)
    .skip(0)
    .limit(3)
)
print(list(cursor))
```

Multi-field sort:

```python
students.find().sort([("branch", ASCENDING), ("cgpa", DESCENDING)])
```

| Task        | Node.js                   | PyMongo                                    |
|----------------|------------------------------|------------------------------------------------|
| Projection        | `.project({...})`               | 2nd argument of `find()`                          |
| Sort one field      | `.sort({ cgpa: -1 })`             | `.sort("cgpa", -1)`                                  |
| Sort many fields      | `.sort({ a: 1, b: -1 })`           | `.sort([("a", 1), ("b", -1)])`                         |
| Materialise              | `.toArray()`                         | `list(cursor)`                                           |

🔗 **Unit IV link:** `{branch: "CSE"}` + `sort cgpa -1` is a perfect fit for the compound index `{branch: 1, cgpa: -1}` — Equality, then Sort (ESR).

## 7. Counting and distinct

```python
n = students.count_documents({"branch": "CSE"})
total_estimate = students.estimated_document_count()    # fast, ignores filters
branches = students.distinct("branch")
```

Don't use the removed old `cursor.count()` — current PyMongo uses `count_documents()`.

## 8. Pagination

```python
def get_page(branch, page=1, limit=10):
    skip = (page - 1) * limit
    return list(
        students.find({"branch": branch})
        .sort([("cgpa", DESCENDING), ("_id", ASCENDING)])   # stable order
        .skip(skip)
        .limit(limit)
    )
```

Keyset version for large data:

```python
def next_page(last_id=None, limit=10):
    query = {"_id": {"$gt": last_id}} if last_id else {}
    return list(students.find(query).sort("_id", ASCENDING).limit(limit))
```

Use the last document's `_id` of one page as `last_id` for the next. Fast because `_id` is indexed.

# 🟢 U — UPDATE

## 9. `update_one` and `update_many`

```python
r = students.update_one(
    {"name": "Rahul"},
    {"$set": {"cgpa": 9.0}}
)
print(r.matched_count)      # docs that matched the filter
print(r.modified_count)     # docs actually changed
```

```python
students.update_many({"branch": "CSE"}, {"$set": {"placed": False}})
```

Update operators (same as Node, same as the shell):

```python
students.update_one({"name": "Rahul"}, {"$inc": {"year": 1}})
students.update_one({"name": "Rahul"}, {"$push": {"skills": "Docker"}})
students.update_one({"name": "Rahul"}, {"$addToSet": {"skills": "Python"}})
students.update_one({"name": "Rahul"}, {"$pull": {"skills": "C++"}})
students.update_one({"name": "Rahul"}, {"$unset": {"placed": ""}})
students.update_one({"name": "Rahul"}, {"$currentDate": {"lastModified": True}})
```

🚨 `update_one` **requires** update operators. `students.update_one({"name":"Rahul"}, {"cgpa": 9})` raises `ValueError` — PyMongo refuses to send an update document without `$` operators. For full replacement use `replace_one`.

Reading the result:

```
matched_count = 1, modified_count = 1  → updated ✔
matched_count = 1, modified_count = 0  → document existed, value was already that (not an error)
matched_count = 0                      → nothing matched (wrong filter/type)
```

## 10. `replace_one`

```python
students.replace_one(
    {"name": "Rahul"},
    {"name": "Rahul", "branch": "CSE", "cgpa": 9.0, "year": 4}
)
```

Replaces the whole body, keeps `_id`.

## 11. `find_one_and_update` — update and get the document back

```python
from pymongo import ReturnDocument

updated = students.find_one_and_update(
    {"name": "Rahul"},
    {"$set": {"cgpa": 9.2}},
    return_document=ReturnDocument.AFTER
)
print(updated)
```

```
ReturnDocument.BEFORE (default) → the old version
ReturnDocument.AFTER            → the new version
```

(Mongoose analogue: `{ new: true }`; Node analogue: `{ returnDocument: "after" }`.)

Great for **atomic counters**:

```python
counter = db["counters"].find_one_and_update(
    {"_id": "studentRoll"},
    {"$inc": {"seq": 1}},
    upsert=True,
    return_document=ReturnDocument.AFTER
)
next_roll = counter["seq"]
```

## 12. Upsert

```python
r = students.update_one(
    {"email": "new@x.com"},
    {"$set": {"name": "New Student", "branch": "ECE"}},
    upsert=True
)
print(r.upserted_id)        # ObjectId if a new document was inserted, else None
```

```
match found    → update it
no match       → insert new doc (filter equality fields + update)
```

Pair upsert with a **unique index** on the filter field so parallel runs can't create duplicates.

# 🟢 D — DELETE

## 13. `delete_one` and `delete_many`

```python
r = students.delete_one({"name": "Arjun"})
print(r.deleted_count)          # 1 or 0

r2 = students.delete_many({"cgpa": {"$lt": 5}})
print(r2.deleted_count)
```

🚨 `students.delete_many({})` deletes **everything**. Check filters twice; prefer soft-delete in real systems:

```python
students.update_one({"_id": sid}, {"$set": {"is_deleted": True}})
students.find({"is_deleted": {"$ne": True}})
```

To remove an entire collection (including indexes): `students.drop()`.

## 14. Bulk writes

Many different operations in one round-trip:

```python
from pymongo import InsertOne, UpdateOne, DeleteOne

ops = [
    InsertOne({"name": "Kiran", "branch": "ME", "cgpa": 7.2}),
    UpdateOne({"name": "Priya"}, {"$set": {"cgpa": 9.5}}),
    DeleteOne({"name": "Arjun"}),
]
res = students.bulk_write(ops)
print(res.inserted_count, res.modified_count, res.deleted_count)
```

```
Many separate calls → many network round trips
bulk_write          → one batch (fast)
```

## 15. Aggregation from Python (Unit IV link 🔗)

An aggregation pipeline is just a **list of dicts**:

```python
pipeline = [
    {"$match": {"year": 4}},
    {"$group": {
        "_id": "$branch",
        "count": {"$sum": 1},
        "avg_cgpa": {"$avg": "$cgpa"}
    }},
    {"$sort": {"avg_cgpa": -1}},
]

for row in students.aggregate(pipeline):
    print(row)
```

Output (conceptually):

```
{'_id': 'ECE', 'count': 1, 'avg_cgpa': 9.1}
{'_id': 'CSE', 'count': 2, 'avg_cgpa': 8.8}
```

Everything you learned in Unit IV transfers **unchanged**: `$match`, `$unwind`, `$group`, `$lookup`, `$set`, `$sort`, `$limit`. The only change is Python syntax.

Example — most popular skills (Part 9, Unit IV):

```python
popular_skills = students.aggregate([
    {"$unwind": "$skills"},
    {"$group": {"_id": "$skills", "students": {"$sum": 1}}},
    {"$sort": {"students": -1}},
    {"$limit": 3},
])
print(list(popular_skills))
```

Example — `$lookup` join:

```python
orders = db["orders"]
report = orders.aggregate([
    {"$lookup": {
        "from": "customers",
        "localField": "customer_id",
        "foreignField": "_id",
        "as": "customer"
    }},
    {"$unwind": "$customer"},
    {"$project": {"_id": 0, "order_no": 1, "total": 1, "customer": "$customer.name"}},
])
```

`aggregate()` returns a cursor — loop it or `list()` it. Remember: `aggregate()` doesn't modify your data (unless the pipeline ends in `$out`/`$merge`).

Tip: put the pipeline in a variable and build it step by step — easier to debug than one giant expression.

## 16. Indexes from Python (Unit IV link 🔗)

```python
from pymongo import ASCENDING, DESCENDING

# single-field
students.create_index("email", unique=True)

# compound  (ESR: equality field first, sort field next)
students.create_index([("branch", ASCENDING), ("cgpa", DESCENDING)])

# text index
db["books"].create_index([("title", "text"), ("description", "text")])

# list / drop
for idx in students.list_indexes():
    print(idx["name"], idx["key"])

students.drop_index("email_1")
```

Generated names follow the same convention as Unit IV: `branch_1_cgpa_-1`.

`create_index` is **idempotent** — running it again with the same definition does nothing harmful, so putting index creation in an "init" function that runs at startup is common.

Text search from Python:

```python
for b in db["books"].find({"$text": {"$search": "mongodb"}}):
    print(b["title"])
```

## 17. `explain` from Python — the Unit IV X-ray 🔥

The most reliable way to get **execution statistics** is to run the `explain` command:

```python
plan = db.command({
    "explain": {
        "find": "students",
        "filter": {"branch": "CSE", "cgpa": {"$gte": 8}},
        "sort": {"cgpa": -1},
    },
    "verbosity": "executionStats",
})

stats = plan["executionStats"]
print("nReturned:        ", stats["nReturned"])
print("totalKeysExamined:", stats["totalKeysExamined"])
print("totalDocsExamined:", stats["totalDocsExamined"])
print("time (ms):        ", stats["executionTimeMillis"])

winning = plan["queryPlanner"]["winningPlan"]
print("winning stage:", winning.get("stage"), "→", winning.get("inputStage", {}).get("stage"))
```

(You can also call `students.find({...}).explain()` — it returns the query plan as a dict, but for the numbers from Unit IV Part 5/6 the `executionStats` form above is the one to use.)

Reading it (exactly Unit IV):

```
COLLSCAN                 → no useful index
IXSCAN (under FETCH)     → index used
IXSCAN, no FETCH, docsExamined 0 → covered query
nReturned vs totalDocsExamined   → efficiency ratio
```

Try the experiment yourself:

```
1. Insert ~50,000 random students with a loop (insert_many in batches).
2. Run explain with NO index    → expect COLLSCAN, totalDocsExamined ≈ 50,000.
3. create_index([("branch",1),("cgpa",-1)]).
4. Run explain again            → expect IXSCAN, far fewer docs examined.
```

Data generator for step 1:

```python
import random

branches = ["CSE", "ECE", "EEE", "ME"]
batch = [
    {
        "name": f"Student{i}",
        "branch": random.choice(branches),
        "cgpa": round(random.uniform(5, 10), 2),
        "year": random.randint(1, 4),
    }
    for i in range(50_000)
]
students.insert_many(batch)
```

This is exactly the "optimization loop" of Unit IV, executed by a Python program. 🔥

## 18. Error handling in PyMongo

```python
from pymongo.errors import (
    DuplicateKeyError, BulkWriteError, ServerSelectionTimeoutError, PyMongoError
)
from bson.errors import InvalidId
from bson import ObjectId

# 1. duplicate key
try:
    students.insert_one({"email": "rahul@x.com"})
except DuplicateKeyError as e:
    print("Duplicate:", e.details.get("keyValue"))

# 2. bulk failures
try:
    students.insert_many(docs, ordered=False)
except BulkWriteError as e:
    print("Some inserts failed:", len(e.details["writeErrors"]))

# 3. bad id
try:
    oid = ObjectId("not-a-valid-id")
except InvalidId:
    print("Invalid id")

# 4. server down
try:
    students.find_one()
except ServerSelectionTimeoutError:
    print("Cannot reach MongoDB")
except PyMongoError as e:
    print("Other database error:", e)
```

Rule: **specific exceptions first, `PyMongoError` last.**

## 19. Transactions — awareness only

MongoDB supports **multi-document ACID transactions** on replica sets and sharded clusters (Atlas clusters are replica sets; a plain standalone local `mongod` is **not**).

```python
with client.start_session() as session:
    with session.start_transaction():
        accounts.update_one({"_id": "A"}, {"$inc": {"balance": -500}}, session=session)
        accounts.update_one({"_id": "B"}, {"$inc": {"balance": +500}}, session=session)
    # leaving the inner with-block commits; an exception aborts
```

Use cases: money transfers, stock decrement + order creation. 🔗 Unit III reminder: good modelling (embedding related data in **one** document) often removes the need for transactions, since single-document writes are already atomic.

(For exams: know *what* a transaction is and that it needs a replica set; the exact code isn't usually required.)

# 🚀 MINI PROJECT — STUDENT MANAGEMENT (CLI)

A menu-driven program using everything from Parts 4–5. Save as `student_cli.py` (next to `db.py`).

```python
from datetime import datetime, timezone
from pprint import pprint

from bson import ObjectId
from bson.errors import InvalidId
from pymongo import ASCENDING, DESCENDING, ReturnDocument
from pymongo.errors import DuplicateKeyError, PyMongoError

from db import db

students = db["students"]
students.create_index("roll_no", unique=True)
students.create_index([("branch", ASCENDING), ("cgpa", DESCENDING)])

VALID_BRANCHES = {"CSE", "ECE", "EEE", "ME"}


def read_float(prompt, low, high):
    while True:
        try:
            value = float(input(prompt))
            if low <= value <= high:
                return value
        except ValueError:
            pass
        print(f"  ✗ Enter a number between {low} and {high}")


def add_student():
    roll_no = input("Roll no: ").strip()
    name = input("Name: ").strip()
    branch = input("Branch (CSE/ECE/EEE/ME): ").strip().upper()
    if not roll_no or len(name) < 2 or branch not in VALID_BRANCHES:
        print("✗ Invalid input")
        return
    cgpa = read_float("CGPA (0-10): ", 0, 10)
    skills = [s.strip() for s in input("Skills (comma separated): ").split(",") if s.strip()]

    try:
        res = students.insert_one({
            "roll_no": roll_no,
            "name": name,
            "branch": branch,
            "cgpa": cgpa,
            "skills": skills,
            "created_at": datetime.now(timezone.utc),
        })
        print("✓ Added with _id", res.inserted_id)
    except DuplicateKeyError:
        print("✗ Roll number already exists")


def list_students():
    branch = input("Filter by branch (blank = all): ").strip().upper()
    query = {"branch": branch} if branch else {}
    for s in students.find(query, {"_id": 0, "roll_no": 1, "name": 1, "branch": 1, "cgpa": 1}) \
                     .sort("cgpa", DESCENDING):
        print(f"  {s['roll_no']:<8} {s['name']:<15} {s['branch']:<4} {s['cgpa']}")


def search_student():
    roll_no = input("Roll no: ").strip()
    doc = students.find_one({"roll_no": roll_no})
    pprint(doc) if doc else print("✗ Not found")


def update_cgpa():
    roll_no = input("Roll no: ").strip()
    cgpa = read_float("New CGPA (0-10): ", 0, 10)
    updated = students.find_one_and_update(
        {"roll_no": roll_no},
        {"$set": {"cgpa": cgpa, "updated_at": datetime.now(timezone.utc)}},
        return_document=ReturnDocument.AFTER,
    )
    print(f"✓ {updated['name']} now has CGPA {updated['cgpa']}") if updated else print("✗ Not found")


def add_skill():
    roll_no = input("Roll no: ").strip()
    skill = input("Skill to add: ").strip()
    res = students.update_one({"roll_no": roll_no}, {"$addToSet": {"skills": skill}})
    if res.matched_count == 0:
        print("✗ Not found")
    elif res.modified_count == 0:
        print("• Student already had that skill")
    else:
        print("✓ Skill added")


def delete_student():
    roll_no = input("Roll no: ").strip()
    if input(f"Delete {roll_no}? (y/n): ").lower() != "y":
        return
    res = students.delete_one({"roll_no": roll_no})
    print("✓ Deleted" if res.deleted_count else "✗ Not found")


def branch_stats():
    pipeline = [
        {"$group": {
            "_id": "$branch",
            "count": {"$sum": 1},
            "avg_cgpa": {"$avg": "$cgpa"},
            "best": {"$max": "$cgpa"},
        }},
        {"$sort": {"avg_cgpa": -1}},
    ]
    for r in students.aggregate(pipeline):
        print(f"  {r['_id']:<4} count={r['count']:<3} avg={r['avg_cgpa']:.2f} best={r['best']}")


def top_skills():
    pipeline = [
        {"$unwind": "$skills"},
        {"$group": {"_id": "$skills", "students": {"$sum": 1}}},
        {"$sort": {"students": -1}},
        {"$limit": 5},
    ]
    for r in students.aggregate(pipeline):
        print(f"  {r['_id']:<12} {r['students']}")


MENU = {
    "1": ("Add student", add_student),
    "2": ("List students", list_students),
    "3": ("Search by roll no", search_student),
    "4": ("Update CGPA", update_cgpa),
    "5": ("Add a skill", add_skill),
    "6": ("Delete student", delete_student),
    "7": ("Branch statistics (aggregation)", branch_stats),
    "8": ("Top skills (aggregation)", top_skills),
    "0": ("Exit", None),
}


def main():
    while True:
        print("\n=== Student Management ===")
        for key, (label, _) in MENU.items():
            print(f" {key}. {label}")
        choice = input("Choose: ").strip()
        if choice == "0":
            print("Bye 👋")
            break
        action = MENU.get(choice)
        if not action:
            print("✗ Invalid choice")
            continue
        try:
            action[1]()
        except PyMongoError as e:
            print("Database error:", e)


if __name__ == "__main__":
    main()
```

Run: `python student_cli.py`

## 20. Node.js vs PyMongo CRUD cheat-sheet

| Operation          | Node.js driver                                 | PyMongo                                           |
|----------------------|--------------------------------------------------|------------------------------------------------------|
| Insert one             | `await c.insertOne(doc)`                            | `c.insert_one(doc)`                                      |
| Insert many              | `await c.insertMany(arr)`                             | `c.insert_many(list)`                                       |
| Find one                   | `await c.findOne(f)`                                    | `c.find_one(f)`                                                |
| Find many                    | `await c.find(f).toArray()`                               | `list(c.find(f))`                                                 |
| Projection                     | `.project({a:1})`                                           | `c.find(f, {"a": 1})`                                                |
| Sort                             | `.sort({a:-1})`                                               | `.sort("a", -1)`                                                        |
| Update one                         | `await c.updateOne(f,{$set:{}})`                                | `c.update_one(f, {"$set": {}})`                                           |
| Update many                          | `await c.updateMany(f,u)`                                         | `c.update_many(f, u)`                                                        |
| Replace                                | `await c.replaceOne(f,doc)`                                         | `c.replace_one(f, doc)`                                                         |
| Update + return                          | `findOneAndUpdate(f,u,{returnDocument:"after"})`                      | `find_one_and_update(f,u,return_document=ReturnDocument.AFTER)`                     |
| Delete one                                 | `await c.deleteOne(f)`                                                  | `c.delete_one(f)`                                                                      |
| Delete many                                  | `await c.deleteMany(f)`                                                   | `c.delete_many(f)`                                                                        |
| Count                                          | `await c.countDocuments(f)`                                                 | `c.count_documents(f)`                                                                       |
| Aggregate                                        | `await c.aggregate([...]).toArray()`                                          | `list(c.aggregate([...]))`                                                                      |
| Create index                                       | `await c.createIndex({a:1})`                                                    | `c.create_index([("a", 1)])`                                                                       |
| Result fields                                        | `insertedId`, `matchedCount`, `modifiedCount`, `deletedCount`                     | `inserted_id`, `matched_count`, `modified_count`, `deleted_count`                                     |

## 21. Common traps 🚨

### Trap 1 — `update_one` without `$set`

PyMongo raises `ValueError`; use `$set` or `replace_one`.

### Trap 2 — `True/False` vs `true/false`

Python uses capitalised booleans.

### Trap 3 — Reusing an exhausted cursor

`list(cursor)` twice gives an empty second list.

### Trap 4 — Forgetting `None` checks

`find_one` returns `None`; `None["name"]` crashes.

### Trap 5 — Using the old `cursor.count()`

Use `count_documents(filter)`.

### Trap 6 — Sort argument shape

`sort("cgpa", -1)` or `sort([("a",1),("b",-1)])` — not `sort({"cgpa": -1})` (a dict is rejected).

### Trap 7 — `matched_count` vs `modified_count`

`1/0` means "no change needed", not failure.

### Trap 8 — `delete_many({})`

Deletes everything.

### Trap 9 — Same dict inserted twice

Carries `_id` → `DuplicateKeyError`.

### Trap 10 — Mutating while iterating

Updating the same documents you are currently looping over in a cursor can cause them to be seen twice or skipped. Collect `_id`s first, or use `update_many` instead of a loop.

### Trap 11 — Giant `list(find())`

Loading millions of documents into memory. Iterate the cursor, use projection, `limit`, or aggregation.

### Trap 12 — Building index inside every request

Create indexes once at startup/migration time, not per request.
