# 🟢 STAGE 1 — CONNECTION + HELPERS

## 6. `src/db.js`

```js
import mongoose from "mongoose";

export async function connectDB(uri) {
  if (!uri) throw new Error("MONGODB_URI is missing. Check your .env file.");
  await mongoose.connect(uri, { serverSelectionTimeoutMS: 5000 });
  console.log("✅ MongoDB connected:", mongoose.connection.name);
}

export async function disconnectDB() {
  await mongoose.disconnect();
  console.log("🔌 MongoDB disconnected");
}
```

- `serverSelectionTimeoutMS: 5000` → if MongoDB isn't reachable, fail after 5 seconds with a clear error instead of hanging for a long time.
- `mongoose.connect` creates the **one shared connection pool** (Unit V Part 1 rule: one client per app).

## 7. `src/httpError.js` — an error that carries a status code

```js
export class HttpError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}
```

So anywhere in the code: `throw new HttpError(404, "Student not found")` and the error handler knows to reply 404.

## 8. `src/middleware/asyncHandler.js`

```js
// Wraps an async route so any thrown error goes to the error handler
export const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);
```

Without this, every route would need its own `try/catch`. (Newer Express versions forward async errors automatically, but this wrapper works on all versions and makes the flow explicit.)

## 9. `src/middleware/checkId.js`

```js
import { HttpError } from "../httpError.js";

const OBJECT_ID = /^[0-9a-fA-F]{24}$/;

export const isObjectId = (v) => typeof v === "string" && OBJECT_ID.test(v);

export function checkId(req, res, next) {
  if (!isObjectId(req.params.id)) {
    return next(new HttpError(400, "Invalid id format"));
  }
  next();
}
```

> Strict 24-hex check → a clean 400 instead of an ugly `CastError`. (Rule 9.)

## 10. `src/grade.js`

```js
export function gradeFor(total) {
  if (total >= 90) return "O";
  if (total >= 80) return "A";
  if (total >= 70) return "B";
  if (total >= 60) return "C";
  if (total >= 50) return "D";
  return "F";
}
```

Marks are out of **100** (internal ≤ 40 + final ≤ 60). Plain `if`-chain: easy to read, easy to test. (Rule 6.)

## 11. `src/middleware/errorHandler.js`

```js
export function notFound(req, res) {
  res.status(404).json({ error: `Route not found: ${req.method} ${req.originalUrl}` });
}

export function errorHandler(err, req, res, next) {
  // 1. Our own errors
  if (err.status) {
    return res.status(err.status).json({ error: err.message });
  }
  // 2. Mongoose validation failed → 400
  if (err.name === "ValidationError") {
    const details = Object.values(err.errors).map((e) => e.message);
    return res.status(400).json({ error: "Validation failed", details });
  }
  // 3. Bad type / bad id cast → 400
  if (err.name === "CastError") {
    return res.status(400).json({ error: `Invalid value for '${err.path}'` });
  }
  // 4. Unique index violation (E11000) → 409
  if (err.code === 11000) {
    const fields = Object.keys(err.keyValue || {}).join(", ");
    return res.status(409).json({ error: `Duplicate value for: ${fields}` });
  }
  // 5. Anything else → 500 (don't leak internals to the client)
  console.error("💥 Unexpected error:", err);
  res.status(500).json({ error: "Internal server error" });
}
```

> **Five buckets** → every failure becomes the right status code. Notice the `500` case **logs** the real error but tells the client nothing sensitive. (Production best practice, Part 4.)

## 14. `src/models/Enrollment.js`

```js
import mongoose from "mongoose";

const enrollmentSchema = new mongoose.Schema(
  {
    student: { type: mongoose.Schema.Types.ObjectId, ref: "Student", required: true },
    course: { type: mongoose.Schema.Types.ObjectId, ref: "Course", required: true },
    status: {
      type: String, enum: ["enrolled", "completed", "dropped"], default: "enrolled",
    },
    attendance: { type: Number, min: 0, max: 100, default: null },
    marks: {
      internal: { type: Number, min: 0, max: 40, default: null },
      final: { type: Number, min: 0, max: 60, default: null },
    },
    total: { type: Number, default: null },
    grade: { type: String, default: null },
  },
  { timestamps: true }
);

// Q5 + Q7: one student, one course, only once — and fast "my courses" lookup
enrollmentSchema.index({ student: 1, course: 1 }, { unique: true });
// Q6: class list by status
enrollmentSchema.index({ course: 1, status: 1 });
// Q8: reports sorted by total
enrollmentSchema.index({ status: 1, total: -1 });

export const Enrollment = mongoose.model("Enrollment", enrollmentSchema);
```

> **Why `default: null` for marks/attendance?** A fresh enrollment has *no result yet*. Defaulting to `0` would make every new enrollment look like "0% attendance" and flood the at-risk report. `null` honestly means "not recorded".

# 🟢 STAGE 3 — STUDENTS + COURSES ROUTES

## 15. `src/routes/students.js`

```js
import { Router } from "express";
import { Student } from "../models/Student.js";
import { Enrollment } from "../models/Enrollment.js";
import { asyncHandler } from "../middleware/asyncHandler.js";
import { checkId } from "../middleware/checkId.js";
import { HttpError } from "../httpError.js";

const router = Router();

// Only these fields may come from the client (whitelisting)
const FIELDS = ["rollNo", "name", "email", "branch", "year", "skills", "address"];
const pick = (body) =>
  Object.fromEntries(FIELDS.filter((f) => f in body).map((f) => [f, body[f]]));

const escapeRegex = (s) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
const SORTABLE = ["name", "rollNo", "year", "createdAt"];

// CREATE
router.post("/", asyncHandler(async (req, res) => {
  const student = await Student.create(pick(req.body));
  res.status(201).json(student);
}));

// LIST  /api/students?branch=CSE&year=2&q=aar&sort=name&page=1&limit=10
router.get("/", asyncHandler(async (req, res) => {
  const filter = {};
  if (typeof req.query.branch === "string") filter.branch = req.query.branch.toUpperCase();
  if (typeof req.query.year === "string") filter.year = Number(req.query.year);
  if (typeof req.query.q === "string" && req.query.q.trim()) {
    filter.name = { $regex: escapeRegex(req.query.q.trim()), $options: "i" };
  }

  const sortKey = SORTABLE.includes(req.query.sort) ? req.query.sort : "name";
  const page = Math.max(parseInt(req.query.page) || 1, 1);
  const limit = Math.min(Math.max(parseInt(req.query.limit) || 10, 1), 50);

  const [data, total] = await Promise.all([
    Student.find(filter).sort({ [sortKey]: 1 }).skip((page - 1) * limit).limit(limit).lean(),
    Student.countDocuments(filter),
  ]);

  res.json({ page, limit, total, pages: Math.ceil(total / limit), data });
}));

// READ ONE
router.get("/:id", checkId, asyncHandler(async (req, res) => {
  const student = await Student.findById(req.params.id);
  if (!student) throw new HttpError(404, "Student not found");
  res.json(student);
}));

// UPDATE
router.patch("/:id", checkId, asyncHandler(async (req, res) => {
  const student = await Student.findByIdAndUpdate(req.params.id, pick(req.body), {
    new: true,
    runValidators: true,
  });
  if (!student) throw new HttpError(404, "Student not found");
  res.json(student);
}));

// DELETE (Rule 7: refuse if the student has enrollments)
router.delete("/:id", checkId, asyncHandler(async (req, res) => {
  if (await Enrollment.exists({ student: req.params.id })) {
    throw new HttpError(409, "Student has enrollments; cannot delete");
  }
  const student = await Student.findByIdAndDelete(req.params.id);
  if (!student) throw new HttpError(404, "Student not found");
  res.status(204).end();
}));

export default router;
```

### What's happening, in plain English

| Piece | Why |
|---|---|
| `pick()` | **whitelist** — a client cannot sneak `_id`, `createdAt` or unknown fields in |
| `typeof ... === "string"` | blocks **NoSQL injection** like `?branch[$ne]=x` turning into an operator object (Unit V Part 3 §25) |
| `escapeRegex` | a user typing `.*` must search for literal `.*`, not run a wildcard regex |
| `SORTABLE` whitelist | client can't sort by arbitrary/unindexed fields |
| `Math.min(... , 50)` | caps `limit` so nobody asks for 10 million rows |
| `Promise.all([find, count])` | both queries run together, not one after another |
| `.lean()` | plain JS objects — faster for read-only lists (Unit V Part 2) |
| `{ new: true, runValidators: true }` | return the updated doc **and** run schema validators on updates |

> **Note on regex search:** a case-insensitive regex like `/aar/i` cannot use an index efficiently. For a mini project that's fine; for real search on large data you'd use a text index or Atlas Search (Part 4 / Part 7).

## 16. `src/routes/courses.js`

```js
import { Router } from "express";
import { Course } from "../models/Course.js";
import { asyncHandler } from "../middleware/asyncHandler.js";
import { checkId } from "../middleware/checkId.js";
import { HttpError } from "../httpError.js";

const router = Router();

// enrolledCount is NOT client-editable: only the enrollment logic changes it
const FIELDS = ["code", "title", "credits", "department", "semester",
                "topics", "maxSeats", "isActive"];
const pick = (body) =>
  Object.fromEntries(FIELDS.filter((f) => f in body).map((f) => [f, body[f]]));

// CREATE
router.post("/", asyncHandler(async (req, res) => {
  const course = await Course.create(pick(req.body));
  res.status(201).json(course);
}));

// LIST  /api/courses?department=CSE&semester=5&active=true
router.get("/", asyncHandler(async (req, res) => {
  const filter = {};
  if (typeof req.query.department === "string") filter.department = req.query.department.toUpperCase();
  if (typeof req.query.semester === "string") filter.semester = Number(req.query.semester);
  if (req.query.active === "true") filter.isActive = true;
  if (req.query.active === "false") filter.isActive = false;

  const courses = await Course.find(filter).sort({ code: 1 }).lean();
  res.json({ total: courses.length, data: courses });
}));

// READ ONE
router.get("/:id", checkId, asyncHandler(async (req, res) => {
  const course = await Course.findById(req.params.id);
  if (!course) throw new HttpError(404, "Course not found");
  res.json(course);
}));

// UPDATE  (cannot shrink maxSeats below the students already enrolled)
router.patch("/:id", checkId, asyncHandler(async (req, res) => {
  const update = pick(req.body);
  const filter = { _id: req.params.id };

  if (update.maxSeats !== undefined) {
    // only match if the new capacity still fits current enrollments
    filter.enrolledCount = { $lte: Number(update.maxSeats) };
  }

  const course = await Course.findOneAndUpdate(filter, update, {
    new: true,
    runValidators: true,
  });

  if (!course) {
    const exists = await Course.exists({ _id: req.params.id });
    if (!exists) throw new HttpError(404, "Course not found");
    throw new HttpError(409, "maxSeats cannot be lower than current enrolledCount");
  }
  res.json(course);
}));

export default router;
```

> **Same atomic idea again:** instead of "read the course, compare, then update", we put the rule **inside the filter** (`enrolledCount <= newMaxSeats`). The check and the update happen as one operation. If nothing matched, we find out *why* (404 or 409). This pattern — **"conditional update, then diagnose"** — is the heart of safe MongoDB application code.

# 🟢 STAGE 4 — ENROLLMENTS (the clever part 🔥)

## 17. The enroll algorithm (before the code)

```
POST /api/enrollments   { studentId, courseId }

 1. Validate both ids (400 if malformed)
 2. Does the student exist?                  no → 404
 3. ATOMIC: findOneAndUpdate on course
        filter : _id, isActive:true, enrolledCount < maxSeats
        update : $inc enrolledCount +1
      → matched?  yes → we now OWN one seat
                  no  → diagnose: 404 (no course) / 409 inactive / 409 full
 4. Create the enrollment document
      → unique index on (student, course) catches duplicates (E11000)
 5. If step 4 fails → GIVE THE SEAT BACK ($inc −1), then rethrow
 6. 201 Created
```

Look at step 3 and step 5 carefully:

- **Reserve first, create second** → we can never exceed the seat limit.
- **Compensate on failure** → if the enrollment insert fails (duplicate), we return the seat. This pattern ("do, and undo if the next step fails") is called a **compensating action**.

> **Why not a transaction?** Multi-document transactions need a replica set and add cost. Here a single-document atomic update + a compensating step is simpler and enough. (Part 4 explains when to reach for transactions.) The small remaining risk — the server crashing exactly between step 3 and step 5 — is why production systems also run a periodic **reconciliation** job that recomputes `enrolledCount` from the enrollments (we write one in Part 3's exercises).

## 18. `src/routes/enrollments.js`

```js
import { Router } from "express";
import { Enrollment } from "../models/Enrollment.js";
import { Student } from "../models/Student.js";
import { Course } from "../models/Course.js";
import { asyncHandler } from "../middleware/asyncHandler.js";
import { checkId, isObjectId } from "../middleware/checkId.js";
import { HttpError } from "../httpError.js";
import { gradeFor } from "../grade.js";

const router = Router();

// ───────────────────────── ENROLL ─────────────────────────
router.post("/", asyncHandler(async (req, res) => {
  const { studentId, courseId } = req.body;

  if (!isObjectId(studentId) || !isObjectId(courseId)) {
    throw new HttpError(400, "studentId and courseId must be valid ids");
  }
  if (!(await Student.exists({ _id: studentId }))) {
    throw new HttpError(404, "Student not found");
  }

  // ATOMIC: check "active and not full" AND take a seat in ONE operation
  const course = await Course.findOneAndUpdate(
    { _id: courseId, isActive: true, $expr: { $lt: ["$enrolledCount", "$maxSeats"] } },
    { $inc: { enrolledCount: 1 } },
    { new: true }
  );

  if (!course) {
    // We got nothing — find out why, to give a precise error
    const c = await Course.findById(courseId).lean();
    if (!c) throw new HttpError(404, "Course not found");
    if (!c.isActive) throw new HttpError(409, "Course is not active");
    throw new HttpError(409, "Course is full");
  }

  try {
    const enrollment = await Enrollment.create({ student: studentId, course: courseId });
    res.status(201).json(enrollment);
  } catch (err) {
    // Enrollment failed (e.g. duplicate) → give the seat back
    await Course.updateOne({ _id: courseId }, { $inc: { enrolledCount: -1 } });
    if (err.code === 11000) {
      throw new HttpError(409, "Student already has an enrollment record for this course");
    }
    throw err;
  }
}));

// ───────────────────────── LIST ─────────────────────────
// /api/enrollments?student=<id>&course=<id>&status=enrolled
router.get("/", asyncHandler(async (req, res) => {
  const filter = {};
  const { student, course, status } = req.query;

  if (student !== undefined) {
    if (!isObjectId(student)) throw new HttpError(400, "Invalid student id");
    filter.student = student;
  }
  if (course !== undefined) {
    if (!isObjectId(course)) throw new HttpError(400, "Invalid course id");
    filter.course = course;
  }
  if (typeof status === "string") filter.status = status;

  const data = await Enrollment.find(filter)
    .populate("student", "rollNo name")
    .populate("course", "code title")
    .sort({ createdAt: -1 })
    .limit(100)
    .lean();

  res.json({ total: data.length, data });
}));

// ───────────────────────── RESULT (marks + attendance) ─────────────────────────
router.patch("/:id/result", checkId, asyncHandler(async (req, res) => {
  const e = await Enrollment.findById(req.params.id);
  if (!e) throw new HttpError(404, "Enrollment not found");
  if (e.status === "dropped") throw new HttpError(409, "Enrollment was dropped");

  const { internal, final, attendance } = req.body;
  if (internal !== undefined) e.marks.internal = internal;
  if (final !== undefined) e.marks.final = final;
  if (attendance !== undefined) e.attendance = attendance;

  // Rule 6: derive total + grade only when BOTH marks exist
  if (e.marks.internal !== null && e.marks.final !== null) {
    e.total = e.marks.internal + e.marks.final;
    e.grade = gradeFor(e.total);
    e.status = "completed";
  }

  await e.save();            // runs validators (Rules 4 and 5)
  res.json(e);
}));

// ───────────────────────── DROP ─────────────────────────
router.patch("/:id/drop", checkId, asyncHandler(async (req, res) => {
  // conditional update: only an 'enrolled' record can be dropped
  const e = await Enrollment.findOneAndUpdate(
    { _id: req.params.id, status: "enrolled" },
    { status: "dropped" },
    { new: true }
  );

  if (!e) {
    if (!(await Enrollment.exists({ _id: req.params.id }))) {
      throw new HttpError(404, "Enrollment not found");
    }
    throw new HttpError(409, "Only an 'enrolled' record can be dropped");
  }

  await Course.updateOne({ _id: e.course }, { $inc: { enrolledCount: -1 } });
  res.json(e);
}));

export default router;
```

### Walk through the tricky bits

**1. `$expr: { $lt: ["$enrolledCount", "$maxSeats"] }`**
Normal filters compare a field to a *constant*. `$expr` lets us compare **two fields of the same document** (aggregation expression inside a query). `"$enrolledCount"` means "the value of that field".

**2. `{ new: true }`**
Return the **updated** document (Unit V Part 3 §12).

**3. Why `findById` AFTER the failed update?**
The atomic update returned `null` — it can't tell us *which* condition failed. A second, read-only query diagnoses it. Reads are cheap, and this only runs on the failure path.

**4. Why `e.save()` in the result route instead of `findByIdAndUpdate`?**
`save()` runs **all validators on the whole document** (marks 0–40 / 0–60, attendance 0–100) and lets us derive `total` from the *combined* old+new marks. This is the "load → modify → save" pattern (Unit V Part 3 §15).

**5. A subtle thing about `status = "completed"`**
Once both marks exist the enrollment is "completed". Editing marks again recalculates total/grade, which is what we want for corrections.

**6. The drop route's counter update** is a second operation after the status change. If the process died between them, the seat count would drift by one — the same reconciliation idea as before.

# 🟢 STAGE 5 — REPORTS (Aggregation, Unit IV applied)

## 19. `src/routes/reports.js`

```js
import { Router } from "express";
import { Enrollment } from "../models/Enrollment.js";
import { Student } from "../models/Student.js";
import { Course } from "../models/Course.js";
import { asyncHandler } from "../middleware/asyncHandler.js";

const router = Router();

// ── Report A: average marks per course ──
router.get("/course-averages", asyncHandler(async (req, res) => {
  const data = await Enrollment.aggregate([
    { $match: { status: "completed" } },
    { $group: {
        _id: "$course",
        avgTotal: { $avg: "$total" },
        students: { $sum: 1 },
        best: { $max: "$total" },
    } },
    { $lookup: { from: Course.collection.name, localField: "_id",
                 foreignField: "_id", as: "course" } },
    { $unwind: "$course" },
    { $project: {
        _id: 0,
        code: "$course.code",
        title: "$course.title",
        students: 1,
        best: 1,
        avgTotal: { $round: ["$avgTotal", 1] },
    } },
    { $sort: { avgTotal: -1 } },
  ]);
  res.json({ total: data.length, data });
}));

// ── Report B: top students  /api/reports/top-students?limit=5 ──
router.get("/top-students", asyncHandler(async (req, res) => {
  const limit = Math.min(Math.max(parseInt(req.query.limit) || 5, 1), 50);

  const data = await Enrollment.aggregate([
    { $match: { status: "completed" } },
    { $group: { _id: "$student", avgTotal: { $avg: "$total" }, courses: { $sum: 1 } } },
    { $sort: { avgTotal: -1 } },
    { $limit: limit },
    { $lookup: { from: Student.collection.name, localField: "_id",
                 foreignField: "_id", as: "student" } },
    { $unwind: "$student" },
    { $project: {
        _id: 0,
        rollNo: "$student.rollNo",
        name: "$student.name",
        branch: "$student.branch",
        courses: 1,
        avgTotal: { $round: ["$avgTotal", 1] },
    } },
  ]);
  res.json({ total: data.length, data });
}));

// ── Report C: at-risk (attendance < 75 OR total < 50) ──
router.get("/at-risk", asyncHandler(async (req, res) => {
  const rows = await Enrollment.aggregate([
    { $match: {
        status: { $in: ["enrolled", "completed"] },
        $or: [ { attendance: { $lt: 75 } }, { total: { $lt: 50 } } ],
    } },
    { $lookup: { from: Student.collection.name, localField: "student",
                 foreignField: "_id", as: "student" } },
    { $lookup: { from: Course.collection.name, localField: "course",
                 foreignField: "_id", as: "course" } },
    { $unwind: "$student" },
    { $unwind: "$course" },
    { $project: {
        _id: 0,
        rollNo: "$student.rollNo",
        name: "$student.name",
        course: "$course.code",
        attendance: 1,
        total: 1,
    } },
    { $sort: { rollNo: 1 } },
  ]);

  // Reasons are added in JS (safe with null values — see trap below)
  const data = rows.map((r) => {
    const reasons = [];
    if (r.attendance !== null && r.attendance < 75) reasons.push("low attendance");
    if (r.total !== null && r.total < 50) reasons.push("low marks");
    return { ...r, reasons };
  });

  res.json({ total: data.length, data });
}));

export default router;
```

### Why each stage is where it is (Unit IV pipeline thinking)

| Stage | Reason |
|---|---|
| `$match` first | filters early; can use index `{status:1,total:-1}` |
| `$group` before `$lookup` | we join **only the few grouped rows**, not every enrollment |
| `$sort` + `$limit` together | MongoDB can optimise the "top N" case |
| `$lookup` then `$unwind` | `$lookup` always returns an **array**; `$unwind` flattens it to one object |
| `$project` last | shape the final output cleanly |
| `$round` | tidy decimals like 77.3333 → 77.3 |
| `Course.collection.name` | uses the real collection name instead of guessing the plural |

### 🚨 The `null` trap inside the at-risk report

In a **query** filter (`$match`), `{ attendance: { $lt: 75 } }` only matches **numbers** less than 75 — `null` is **not** matched (query comparison is type-bracketed).

But inside an **aggregation expression** (like `$cond` / `$lt: ["$attendance", 75]`), BSON's sort order puts `null` **below every number**, so `null < 75` would be **true**!

That's why we:
1. let `$match` do the filtering (safe), and
2. build the human-readable `reasons` in JavaScript with explicit `!== null` checks.

> If your viva asks *"how does MongoDB compare null with numbers?"* — **query operators and aggregation expressions treat it differently.** Remember this one.

```js
import "dotenv/config";
import app from "./src/app.js";
import { connectDB, disconnectDB } from "./src/db.js";
import { Student } from "./src/models/Student.js";
import { Course } from "./src/models/Course.js";
import { Enrollment } from "./src/models/Enrollment.js";

async function main() {
  await connectDB(process.env.MONGODB_URI);

  // Wait until all declared indexes exist BEFORE taking traffic.
  // (The unique indexes are what really stop duplicates!)
  await Promise.all([Student.init(), Course.init(), Enrollment.init()]);
  console.log("📚 Indexes ready");

  const server = app.listen(PORT, () =>
    console.log(`🚀 CourseHub running on http://localhost:${PORT}`)
  );

  // Graceful shutdown: stop accepting requests, then close DB

    console.log(`\n${signal} received — shutting down`);
    server.close(async () => {
      await disconnectDB();
      process.exit(0);
    });
  };
  process.on("SIGINT", () => shutdown("SIGINT"));
  process.on("SIGTERM", () => shutdown("SIGTERM"));
}

main().catch((err) => {

  process.exit(1);
});
```

- `Model.init()` waits for index creation → so the unique indexes **exist** before the first request.
- **Graceful shutdown** (Ctrl+C) closes the HTTP server, then the DB connection — no half-finished requests.
- If the DB can't connect → clear message and exit code `1` (don't run a broken server).

## 27. One request, end to end

`POST /api/enrollments` with `{ studentId: S, courseId: C }`, where C has `maxSeats 6`, `enrolledCount 5`, `isActive true`, and S is not yet enrolled.

```
1. express.json()        parses body → req.body = { studentId, courseId }
2. isObjectId × 2        both pass
3. Student.exists(S)     → found
4. Course.findOneAndUpdate
      filter : _id=C, isActive=true, 5 < 6  ✔ matches
      update : enrolledCount 5 → 6          (atomic)
      returns: updated course
5. Enrollment.create({S, C})
      unique index (student, course): no clash ✔
6. res.status(201).json(enrollment)
```

Now the **next** student S2 asks for the same course:

```
4. findOneAndUpdate filter: 6 < 6 ✘  → no match → returns null
   findById(C) → exists, isActive → 409 "Course is full"
```

And when S **repeats** the same request:

```
4. findOneAndUpdate → seat taken (enrolledCount +1)
5. Enrollment.create → E11000 duplicate key
   catch → Course.updateOne $inc −1   (seat returned)
   throw HttpError(409, "already has an enrollment record")
```

Every path ends in a **correct status code** and a **correct seat count**. ✅

## 28. Common traps 🚨

### Trap 1: Forgetting `"type": "module"`
`import` statements fail with `Cannot use import statement outside a module`.

### Trap 2: Loading `dotenv` too late
`process.env.MONGODB_URI` is `undefined` if `dotenv/config` is imported after code that reads it. Import it **first**.

### Trap 3: `app.use(errorHandler)` placed before routes
Express runs in order. Error handler and 404 must be **last**.

### Trap 4: Error handler with 3 parameters
Express recognises an error handler by its **4 parameters** `(err, req, res, next)`. Drop one and it's treated as a normal middleware.

### Trap 5: `findByIdAndUpdate` without `runValidators`
Update queries skip validators by default. Marks of 999 would be saved silently.

### Trap 6: Check-then-write for seats
The race condition. Use the conditional atomic update.

### Trap 7: Trusting `req.query`/`req.body` types
`?branch[$ne]=x` can become an object. Check `typeof`, whitelist fields.

### Trap 8: Defaulting "not recorded" values to 0
`attendance: 0` flags everyone at risk. Use `null`.

### Trap 9: Using `null < 75` inside aggregation expressions
BSON ordering makes it `true`. Filter with a query `$match`, or check `$type`/`!== null`.

### Trap 10: Not waiting for index builds
Without `Model.init()`, the first requests can run before the unique index exists, and duplicates slip in.

### Trap 11: Running `seed` against a real database
`deleteMany({})` wipes collections. Seed scripts are for **development** databases only — double-check `MONGODB_URI`.

## 30. 🔥 PART 2 — WHAT YOU MUST REMEMBER

**How do you stop two users taking the last seat?**

> One atomic `findOneAndUpdate` with the capacity check inside the filter (`$expr` + `$inc`).

**Why reserve first and create second?**

> The seat is the scarce resource; reserving first guarantees the limit, and we give it back if the next step fails.

**What is a compensating action?**

> An "undo" step run when a later step fails, because we did not use a transaction.

**What guarantees no duplicate enrollments?**

> The unique compound index `{student, course}` — E11000 → HTTP 409.

**Why whitelist fields?**

> So clients can't set protected fields (like `enrolledCount`) or inject unknown data.

**Why `{ new: true, runValidators: true }`?**

> Return the updated document, and run schema validation on updates.

**`$lookup` then `$unwind` — why?**

> `$lookup` returns an array; `$unwind` turns it into a single object.

**Why default marks to `null`, not `0`?**

> `null` means "not recorded"; `0` would be a real score and distort reports.

**Where does the error handler go?**

> Last, with four parameters.
