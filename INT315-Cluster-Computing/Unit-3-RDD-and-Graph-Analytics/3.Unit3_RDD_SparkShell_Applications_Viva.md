# PART 7 — 🖥️ Spark Shell + Complete RDD Workflow

> This part is especially important for the practical, because knowing RDD theory is one thing, but being able to sit in front of `spark-shell` and actually perform the operations is what matters.

## 1. What is Spark Shell?

`spark-shell` is an interactive **Scala shell** provided with Apache Spark.

It allows us to execute Spark commands interactively rather than writing a complete application first.

Instead of:

```
Write program
    ↓
Compile
    ↓
Package
    ↓
Submit
    ↓
Run
```

we can do:

```
spark-shell
     ↓
   scala>
     ↓
Type Spark commands
     ↓
See results immediately
```

This makes it extremely useful for:

- learning Spark
- testing RDD operations
- debugging
- experimenting with transformations
- practical examinations

## 7. The Practical Exam Pattern

Most RDD questions can be approached using:

```
STEP 1 → Create RDD
STEP 2 → Apply transformation(s)
STEP 3 → Apply action
STEP 4 → Observe result
```

**Example:** Create numbers → select even → multiply by 5 → display.

```scala
val nums = sc.parallelize(1 to 10)

val result = nums
  .filter(_ % 2 == 0)
  .map(_ * 5)

result.collect()
```

```
Array(10,20,30,40,50)
```

---

## 8. Don't Create Unnecessary Intermediate Variables

You can also write it as one chain:

```scala
sc.parallelize(1 to 10)
  .filter(_ % 2 == 0)
  .map(_ * 5)
  .collect()
```

This is perfectly valid. But for a **practical exam**, prefer the step-by-step version:

```scala
val nums = sc.parallelize(1 to 10)

val result = nums
  .filter(_ % 2 == 0)
  .map(_ * 5)

result.collect()
```

**Why?** Because it's easier to:

- explain to the examiner
- debug
- inspect intermediate RDDs
- demonstrate transformations vs actions

## 13. 🔥 Exam Debugging Technique

Suppose the examiner asks:

> "Find all even numbers greater than 20 and multiply them by 2."

**Don't** immediately write a huge one-liner. **Build it up:**

```scala
val nums = sc.parallelize(1 to 50)

val even = nums.filter(_ % 2 == 0)
even.take(10)          // check

val greater = even.filter(_ > 20)
greater.collect()      // check

val result = greater.map(_ * 2)
result.collect()       // final
```

This is much easier to debug.

## 23. Sort Students by Marks

```scala
val parsed = students.map { line =>
  val parts = line.split(",")
```

> `_._2` means: **sort using the second field — the marks.**

## 24. `sortByKey()` vs Sorting by Value

Given `("Alice",85) ("Bob",72) ("Charlie",91)`:

```scala
parsed.sortByKey()      // sorts by KEY  → Alice, Bob, Charlie
parsed.sortBy(_._2)     // sorts by VALUE → 72, 85, 91
```

```
sortByKey()   → key
sortBy(_._2)  → value
```

## 25. 🔥 Complete Word-Count Practical in Spark Shell

> This is one you should be able to type almost automatically.

```scala
val lines = sc.parallelize(
  List(
    "hello spark",
    "hello scala",
    "spark is fast"
  )
)

val words = lines.flatMap(_.split(" "))
val pairs = words.map(word => (word, 1))
val counts = pairs.reduceByKey(_ + _)

counts.collect()
```

```
(hello,2)
(spark,2)
(scala,1)
(is,1)
(fast,1)
```

> Ordering may vary.

## 26. Explain This Word Count to the Examiner

If examiner asks: *"Explain your program."*

## 29. ⚠️ Output Directory Already Exists

If you run `saveAsTextFile()` again with the same path, Spark may report that the output path **already exists**.

> This is a very common practical issue. Use a different output directory, or remove the previous one before rerunning.

## 33. Caching in a Practical Workflow

```scala
val nums = sc.parallelize(1 to 1000000)

```

## 34. ⚠️ Practical Mistake — Forgetting the Action

```scala
val result = nums
  .filter(_ % 2 == 0)
  .map(_ * 10)
```

"Why didn't I get the final array?"

```
filter → transformation
map    → transformation
```

Neither is an action! Use:

```scala
result.collect()
// or
result.take(10)
```

---

## 35. ⚠️ Practical Mistake — Wrong Type for `reduceByKey()`

```scala
val nums = sc.parallelize(List(1,2,3,4))
nums.reduceByKey(_ + _)   // ❌ wrong
```

Wrong conceptually because `nums` contains plain integers, not key-value pairs. You need:

```scala
val pairs = sc.parallelize(
  List(("A",1), ("B",2), ("A",3))
)

pairs.reduceByKey(_ + _)   // ✅
```

---

## 36. ⚠️ Practical Mistake — Forgetting `toInt`

Suppose file data is `Alice,85`. After `val parts = line.split(",")`, `parts(1)` is a **String** `"85"`.

If you want an integer:

```scala
parts(1).toInt
```

So `(name, parts(1).toInt)` creates `(Alice,85)` rather than `(Alice,"85")`.

> This connects directly to your Unit II type-conversion knowledge.

---

## 37. ⚠️ Practical Mistake — Windows Path

Prefer:

```scala
sc.textFile("C:/sparkdata/data.txt")
```

rather than backslashes, because `\` has special meaning inside Scala strings.

## 38. ⚠️ Practical Mistake — Collecting Huge Data

Don't blindly do `rdd.collect()` on enormous data. Instead:

```scala
rdd.take(10)                              // for inspection
rdd.saveAsTextFile("C:/sparkoutput/result") // distributed output
```

## 46. If Transformation Result Looks Missing

```scala

```

You don't immediately see `2 4 6 8...` — that's expected, because `map()` is **lazy**. Use `result.collect()`.

# PART 8 — 🚀 RDD Applications & Problem-Solving Patterns

> We've already learned what each RDD operation does. Now the important step is learning how to **combine them** when the examiner gives you an unseen problem.
>
> The goal: **Read the problem → identify the required RDD operations → build the pipeline → execute it in spark-shell.**

## 1. How to Think About Any RDD Problem

Almost every beginner-level RDD practical can be converted into this pattern:

```
                 INPUT
                   ↓
            Create / Read RDD
                   ↓
            TRANSFORM DATA
                   ↓
       ┌───────────┼───────────┐
       ↓           ↓           ↓
     filter()     map()      flatMap()
       │           │           │
       └───────────┼───────────┘
                   ↓
          Aggregate / Sort
                   ↓
              ACTION
                   ↓
                OUTPUT
```

The trick is identifying what the question is asking.

---

## 2. 🔥 Keyword → RDD Operation

> This table is worth memorizing.

| Question says... | Think of... |
|---|---|
| Convert/change every element | `map()` |
| Select/keep records | `filter()` |
| Split records into many elements | `flatMap()` |
| Remove duplicates | `distinct()` |
| Combine two RDDs | `union()` |
| Common elements | `intersection()` |
| Elements in first but not second | `subtract()` |
| Sort values | `sortBy()` |
| Same key → aggregate | `reduceByKey()` |
| Same key → group | `groupByKey()` |
| Sort according to key | `sortByKey()` |
| Get number of records | `count()` |
| Get all results | `collect()` |
| Get first result | `first()` |
| Get limited results | `take()` |
| Sum | `sum()` / `reduce()` |
| Average | `mean()` |
| Highest | `max()` |
| Lowest | `min()` |
| Save result | `saveAsTextFile()` |

> 🔥 If you understand this table, unseen questions become much easier.

## 30. ⭐ Part 8 Viva Checkpoint

**Q1. How do you approach an RDD problem?**
Identify the input, create/read the RDD, apply the required transformations, and finally use an action to obtain or store the result.

**Q2. Which operation is used for filtering?**
`filter()`

**Q3. Which operation transforms every element?**
`map()`

**Q4. When do you use `flatMap()`?**
When one input element may produce multiple output elements and the resulting collections need to be flattened.

**Q5. How do you calculate word frequency?**
Split lines using `flatMap()`, create `(word,1)` pairs using `map()`, aggregate with `reduceByKey(_ + _)`, and use an action such as `collect()`.

**Q6. How do you calculate total sales per product?**
Represent records as `(product, amount)` and use `reduceByKey(_ + _)`.

**Q7. How do you group students by department?**
Use a pair RDD such as `(department, student)` and apply `groupByKey()`.

**Q8. How do you remove duplicates?**
Use `distinct()`.

**Q9. How do you find common elements between two RDDs?**
Use `intersection()`.

**Q10. Does `union()` remove duplicates?**
No. `union()` combines the RDDs; duplicates remain unless explicitly removed, for example using `distinct()`.

**Q11. How do you find the highest value?**
Use `max()` or an appropriate `reduce()`.

**Q12. How do you sort an RDD?**
Use `sortBy()`; for pair RDDs, `sortByKey()` can sort by key.

**Q13. Why is `collect()` normally used carefully?**
Because it transfers all elements to the driver, which can cause memory problems for large datasets.

**Q14. What is the difference between `count()` and `getNumPartitions()`?**
`count()` returns the number of elements, while `getNumPartitions()` returns the number of partitions.

**Q15. What is the most common RDD aggregation pattern?**
Convert records into key-value pairs and use `reduceByKey()` when values with the same key need to be combined.

| 5 | Using `collect()` blindly on huge data | Use `take(10)` for inspection |
| 6 | Forgetting `.toInt` on file-parsed strings | Use `parts(1).toInt` for numeric ops |
| 7 | Using wrong Windows path | Prefer `"C:/sparkdata/data.txt"` |
| 8 | Reusing an existing output path | `saveAsTextFile()` expects a non-existing destination |
| 9 | Assuming output order | For `reduceByKey()` etc. don't assume order unless explicitly sorted |
| 10 | Thinking Spark executes transformations immediately | An action like `.collect()` triggers computation |

# PART 10 — 🎤 Exactly 30 Final RDD Viva Questions & Strong Answers

> These are the final 30 viva questions for the portion we're studying tonight.
>
> **Boundary reminder:** RDD only. Not covering Shared Variables or GraphX here.

---

**1. What is an RDD?**

> RDD stands for **Resilient Distributed Dataset**. It is Spark's fundamental distributed data abstraction, representing a fault-tolerant collection of elements divided into partitions that can be processed in parallel. RDDs are immutable and use lineage information for fault recovery.

If examiner asks *"Why is it called RDD?"*

```
Resilient   → can recover lost partitions.
Distributed → data is distributed across partitions/nodes.
Dataset     → collection of data elements.
```

---

**2. What are the main characteristics of RDD?**

- Immutable
- Distributed
- Partitioned
- Fault tolerant
- Lazy
- Parallel processing
- Lineage based recovery
- Can be cached/persisted

> "The key characteristics are immutability, partitioning, distributed processing, fault tolerance through lineage, lazy evaluation, and the ability to cache or persist data."

---

**3. What is a partition in RDD?**

A partition is a logical division of an RDD's data. Partitions are the basic units on which Spark performs parallel processing.

```
RDD
 |
 +-- Partition 1
 +-- Partition 2
 +-- Partition 3
```

Each partition can be processed by a task.

---

**4. Is an RDD mutable or immutable?**

An RDD is **immutable**. Once created, its contents cannot be modified. Transformations create a new RDD instead of changing the existing one.

```scala
val rdd1 = sc.parallelize(1 to 5)
val rdd2 = rdd1.map(_ * 2)
```

Here `rdd1` remains unchanged.

---

**5. Why is RDD immutability useful?**

> Immutability makes distributed computation easier to reason about and supports fault tolerance because Spark can reconstruct derived RDD partitions from their lineage rather than relying on in-place modifications.

> 🔥 This is a better answer than simply saying "because Spark uses functional programming."

---

**6. How do you create an RDD from a Scala collection?**

```scala
sc.parallelize(collection)
// e.g.
val rdd = sc.parallelize(List(10,20,30,40))
```

---

**7. How do you create an RDD from a text file?**

```scala
sc.textFile("C:/sparkdata/data.txt")
// e.g.
val lines = sc.textFile("C:/sparkdata/data.txt")
```

> A text-file RDD generally represents each input line as an element.

---

**8. What is SparkContext and what is `sc`?**

SparkContext is the entry point to Spark's core functionality for RDD-based applications. In spark-shell, a SparkContext is already available through the variable `sc`.

```
SparkContext
     ↓
     sc
     ↓
RDD creation / Spark operations
```

---

**9. What is a transformation?**

A transformation is an operation that creates a new RDD from an existing RDD. Transformations are generally evaluated lazily.

Examples: `map()`, `filter()`, `flatMap()`, `distinct()`, `union()`, `reduceByKey()`

---

**10. What is an action?**

An action triggers the execution of the required RDD computation and returns a result to the driver or performs an output side effect.

Examples: `collect()`, `count()`, `first()`, `take()`, `reduce()`, `saveAsTextFile()`

---

**11. What is lazy evaluation in Spark?**

Lazy evaluation means Spark does not immediately execute transformations when they are called. It records the required computation and executes it when an action is invoked.

```scala
val even = nums.filter(_ % 2 == 0)   // doesn't immediately produce the final result
even.collect()                        // triggers the computation
```

---

**12. Why does Spark use lazy evaluation?**

> It allows Spark to avoid unnecessary computation, optimize the execution plan, and combine multiple transformations into an efficient execution pipeline.

```
Transformation → Build plan → Build dependency/DAG information → Action → Execute required work
```

---

**13. What is the difference between `map()` and `filter()`?**

| | `map()` | `filter()` |
|---|---|---|
| Behavior | Transforms every element | Selects elements satisfying a condition |
| Example | `rdd.map(_ * 2)` → `1 2 3 → 2 4 6` | `rdd.filter(_ % 2 == 0)` → `1 2 3 4 → 2 4` |

**One-line viva answer:** "`map()` transforms elements, whereas `filter()` selects elements based on a condition."

---

**14. What is the difference between `map()` and `flatMap()`?**

> This is very commonly asked.

- **`map()`** — one input produces one output.
  `List("hello world").map(_.split(" "))` → conceptually `["hello","world"]` but **nested**.
- **`flatMap()`** — one input can produce multiple outputs and the results are **flattened**.
  `List("hello world").flatMap(_.split(" "))` → `hello`, `world`

**Strong answer:** "`map()` preserves the output structure produced by each input, while `flatMap()` maps and then flattens the resulting collections."

---

**15. What is a Pair RDD?**

A Pair RDD is an RDD whose elements are key-value pairs, generally represented as `RDD[(K,V)]`.

```scala
val data = sc.parallelize(List(("A",10),("B",20),("A",30)))
```

```
Key   Value
 A     10
 B     20
 A     30
```

Useful for: `reduceByKey()`, `groupByKey()`, `sortByKey()`

---

**16. What is `reduceByKey()`?**

`reduceByKey()` combines or aggregates values belonging to the same key using a specified reduction function.

```scala
val pairs = sc.parallelize(List(("A",10),("B",20),("A",30)))
pairs.reduceByKey(_ + _).collect()
```

```
(A,40)
(B,20)
```

```
A → 10
A → 30
    ↓
    +
    ↓
A → 40
```

---

**17. What is `groupByKey()`?**

`groupByKey()` groups all values belonging to the same key.

```
("A",10) ("A",30) ("B",20)
      ↓ group
A → [10,30]
B → [20]
```

> It does not automatically calculate a sum.

---

**18. `reduceByKey()` vs `groupByKey()`?** 🔥 Very important viva question.

| `reduceByKey()` | `groupByKey()` |
|---|---|
| Combines values | Groups values |
| Produces one aggregated value per key | Produces grouped values |
| Useful for sum/count/max etc. | Useful when actual grouping is required |
| Can perform local combining before shuffle | Generally transfers grouped values for the key |

**Input:** `(A,10) (A,20) (A,30)`

```
reduceByKey(_ + _) → (A,60)
groupByKey()       → (A,[10,20,30])
```

**Strong answer:** "If I need aggregation, I generally prefer `reduceByKey()`; if I actually need all values grouped together, I use `groupByKey()`."

---

**19. What is `reduce()`?**

`reduce()` combines all elements of an RDD using a reduction function and returns a single result.

```scala
val nums = sc.parallelize(List(1,2,3,4))
nums.reduce(_ + _)   // 10

nums.reduce((a,b) => if (a > b) a else b)   // finds max
```

---

**20. `reduce()` vs `reduceByKey()`?**

> This is a classic confusion.

- **`reduce()`** — works on the entire RDD: `1,2,3,4 → 10`
- **`reduceByKey()`** — works separately for each key: `(A,10)(A,20)(B,5)(B,15) → (A,30)(B,20)`

**Strong answer:** "`reduce()` produces one reduction over the RDD, whereas `reduceByKey()` performs reductions independently for each key in a pair RDD."

---

**21. What is `collect()`?**

`collect()` is an action that retrieves all elements of an RDD to the driver.

```scala
rdd.collect()
```

> ⚠️ Important warning: It should be used carefully with large datasets because all returned data must fit in driver memory. 🔥 Examiner-impressing answer.

---

**22. `collect()` vs `take()`?**

- **`collect()`** — returns all elements: `rdd.collect()`
- **`take(n)`** — returns up to `n` elements: `rdd.take(5)`

> "`collect()` is suitable for small results, while `take()` is safer for inspecting a limited portion of a large RDD."

---

**23. What is lineage?**

Lineage is the dependency history describing how an RDD was derived from its parent RDDs.

```
Original RDD
     ↓
 filter()
     ↓
 map()
     ↓
 Result RDD
```

Spark can use this dependency information to reconstruct lost partitions. Inspect with `rdd.toDebugString`.

---

**24. How is RDD fault tolerance achieved?** 🔥 Must know.

> RDD fault tolerance is primarily achieved through lineage. If a partition is lost, Spark can recompute that partition from the transformations used to create it rather than requiring the entire dataset to be stored as replicated copies.

```
RDD1 → filter → RDD2 → map → RDD3

If a partition of RDD3 is lost:
Lost partition → Check lineage → Recompute required parent data → Recreate lost partition
```

---

**25. What is the difference between lineage and DAG?**

> This is a slightly tricky one.

- **Lineage** — describes the dependency/history relationship of RDDs: `RDD1 → RDD2 → RDD3`
- **DAG** — Directed Acyclic Graph representing the broader computation/dependency structure that Spark can use for execution planning.

**Strong answer:** "Lineage focuses on how RDDs depend on their parent RDDs and supports fault recovery, while the DAG represents the computation and dependency structure used to organize execution."

> Don't unnecessarily claim: "Lineage is the same thing as the DAG." They are closely related, but the terms emphasize different things.

---

**26. What are narrow and wide transformations?**

**Narrow dependency** — a child partition depends on a small/local set of parent partitions.
Examples: `map()`, `filter()`, `flatMap()`

```
Parent P1 → Child C1
Parent P2 → Child C2
```

**Wide dependency** — a child partition may depend on multiple parent partitions, commonly involving a shuffle.
Examples: `reduceByKey()`, `groupByKey()`, `sortBy()`

```
P1 ──┐
P2 ──┼──→ shuffle → Child partitions
P3 ──┘
```

**Strong answer:** "Narrow transformations avoid a full redistribution of data between partitions, while wide transformations can require data movement or shuffle across partitions."

---

**27. What is a shuffle?**

Shuffle is the redistribution of data across partitions, often required by wide operations when records need to be brought together according to a key or ordering.

```scala
pairs.reduceByKey(_ + _)   // may require values with the same key to be brought together
```

```
Partition 1 ──┐
Partition 2 ──┼──→ Shuffle → Group by key
Partition 3 ──┘
```

Shuffle can involve: network transfer, memory, disk/spill depending on execution conditions.

> ⚠️ Don't say "shuffle happens only in RAM."

---

**28. What is caching an RDD?**

Caching tells Spark to persist an RDD so that if it is reused, Spark may avoid recomputing it from its lineage.

```scala
val even = nums.filter(_ % 2 == 0)
even.cache()
even.count()
even.collect()
```

> Important: `cache()` is an optimization, not a requirement for RDD computation.

> ⚠️ Don't say: "`cache()` permanently stores the RDD in RAM."

**Better answer:** "`cache()` requests persistence using Spark's default storage level; cached data can be evicted and the RDD can be recomputed from lineage."

---

**29. Why might we cache an RDD?**

Suppose an expensive RDD is reused:

```
Large input → expensive transformations → Important RDD
                                              ↓       ↓
                                          action 1  action 2
```

Without caching: `action 1 → recompute`, `action 2 → recompute`

With caching:

```
expensive computation
        ↓
      cache
      ↙   ↘
 action1 action2
```

> We cache an RDD when it is expensive to compute and will be reused by multiple actions or downstream computations.

---

**30. Explain this complete RDD program.** 🔥🔥 Final master viva question.

```scala
val lines = sc.textFile("C:/sparkdata/input.txt")

val counts = lines
  .flatMap(_.split(" "))
  .map(word => (word,1))
  .reduceByKey(_ + _)

counts.collect()
```

**Your answer:** "First, `textFile()` creates an RDD from the input file. `flatMap()` splits each line into individual words. `map()` converts every word into a key-value pair where the word is the key and 1 is the value. `reduceByKey()` aggregates the values for each word to calculate its frequency. Finally, `collect()` is an action that retrieves the results to the driver."

Then examiner may ask:

| Question | Answer |
|---|---|
| Which are transformations? | `flatMap()`, `map()`, `reduceByKey()` |
| Which is the action? | `collect()` |
| Why is execution lazy? | The transformations build the computation plan; execution occurs when `collect()` triggers the job |
| How is fault tolerance provided? | Through RDD lineage and recomputation of lost partitions |

> 🔥 If you can explain this confidently, you understand the core RDD workflow.
