```
Question
   ↓

   ↓

   ↓

   ↓
Action
   ↓

```

**For example:**

```

   ↓

   ↓
```

**In Spark:**


## 2. What is an RDD?

**RDD = Resilient Distributed Dataset**

Remember the three words:

| Word | Meaning |
|---|---|
| **Resilient** | fault recovery |
| **Distributed** | data across partitions |
| **Dataset** | collection of elements |

> **Strong definition:**
> An RDD is Spark's fundamental distributed data abstraction, representing a fault-tolerant collection of elements divided into partitions that can be processed in parallel.

---

## 3. What is a Partition?

An RDD isn't necessarily one giant block. It is divided into **partitions**:

```
RDD
│
├── Partition 1
├── Partition 2
├── Partition 3
└── Partition 4
```

Spark can process these partitions **in parallel**.

**Example:**

```scala
val rdd = sc.parallelize(1 to 20, 4)
```

Here we request 4 partitions.

**Check:**

```scala
rdd.getNumPartitions
```

## 🚨 `collect()` Warning

**This is extremely important.**

```scala
nums.collect()
```

brings **all elements to the driver**.

✅ **Fine for:**
- 10 values
- 100 values
- small practical data

⚠️ **Dangerous for:**
- millions/billions of records

For inspection of a large RDD:

```scala
nums.take(5)
```

is **safer**.

> **Viva answer:**
> "`collect()` returns the complete RDD to the driver, so it should be used carefully with large datasets."

## 7. Transformation vs Action

> This distinction is the heart of RDD practicals.

### Transformation
Creates a **new RDD**.

Examples:
```
map()
filter()
flatMap()
distinct()
union()
intersection()
subtract()
sortBy()
reduceByKey()
groupByKey()
```

### Action
**Triggers execution.**

Examples:
```
collect()
count()
first()
take()
reduce()
sum()
min()
max()
saveAsTextFile()
```

**Mental model:**

```
Transformation
      ↓
New RDD
      ↓
Transformation
      ↓
New RDD
      ↓
ACTION
      ↓
Execution
```

## 8. `map()` — Transform Every Element

**Question:** Multiply every number by 2.

```scala
val nums = sc.parallelize(1 to 5)

val result = nums.map(_ * 2)

result.collect()
```

**Output:**

```
Array(2,4,6,8,10)
```

**Use `map()` when:**
Every input element needs to be transformed into an output element.

## 9. `filter()` — Select Elements

**Question:** Find even numbers.

```scala
val nums = sc.parallelize(1 to 10)

val even = nums.filter(_ % 2 == 0)

even.collect()
```

**Output:**

```
Array(2,4,6,8,10)
```

**Use:**
| Purpose | Function |
|---|---|
| selection | `filter` |
| transformation | `map` |

## 10. `flatMap()` — Split + Flatten

> This is very important for word count.

```scala
val lines = sc.parallelize(
  List(
    "hello world",
    "spark scala"
  )
)
```

Then:

```scala
val words = lines.flatMap(_.split(" "))

words.collect()
```

**Output:**

```
Array(hello,world,spark,scala)
```

**Think:**

```
"hello world"
      ↓
hello
world

"spark scala"
      ↓
spark
scala
```

**Use `flatMap()` when:**
One input can produce multiple outputs and you want the resulting collections flattened.

## 11. `distinct()`

**Question:** Remove duplicate values.

```scala
val nums = sc.parallelize(
  List(1,2,2,3,3,3,4)
)

nums.distinct().collect()
```

**Output conceptually:**

```
Array(1,2,3,4)
```

**Remember:** `distinct` → remove duplicates

---

## 12. `union()`

Combine two RDDs:

```scala
val a = sc.parallelize(List(1,2,3))
val b = sc.parallelize(List(4,5,6))

val result = a.union(b)

result.collect()
```

**Result:**

```
Array(1,2,3,4,5,6)
```

### ⚠️ Important trap

`union()` **doesn't automatically remove duplicates**.

If:
```
A = 1,2,3
B = 3,4,5
```

then:
```
union = 1,2,3,3,4,5
```

If you want unique values:

```scala
a.union(b).distinct().collect()
```

## 13. `intersection()`

Find common elements:

```scala
val a = sc.parallelize(List(1,2,3,4))
val b = sc.parallelize(List(3,4,5,6))

a.intersection(b).collect()
```

**Result:**

```
Array(3,4)
```

## 14. `subtract()`

**Result:**


## 21. Pair RDD

Now the important second level.

A **Pair RDD** contains:

```
(key, value)
```

**Example:**

```scala
val pairs = sc.parallelize(
  List(
    ("A",10),
    ("B",20),
    ("A",30)
  )
)
```

Type conceptually:

```
RDD[(String, Int)]
```

**Access key:**

```scala
pairs.map(_._1).collect()
```

**Access value:**

```scala
pairs.map(_._2).collect()
```

**Remember:**

| Symbol | Meaning |
|---|---|
| `._1` | key |
| `._2` | value |

## 22. `reduceByKey()` 🔥

Suppose:

```
A → 10
A → 30
B → 20
```

**Question:** Find total for each key.

```scala
val pairs = sc.parallelize(
  List(
    ("A",10),
    ("B",20),
    ("A",30)
  )
)

val result = pairs.reduceByKey(_ + _)

result.collect()
```

**Output:**

```
Array((A,40),(B,20))
```

**Use when:**
You need to aggregate values belonging to the same key.

**Examples:**
- sales by product
- marks by student
- word frequency
- salary by department
- count by category

---

## 23. `groupByKey()`

Same input:

```scala
val pairs = sc.parallelize(
  List(
    ("A",10),
    ("B",20),
    ("A",30)
  )
)
```

Then:

```scala
pairs.groupByKey().collect()
```

**Conceptually:**

```
(A, CompactBuffer(10,30))
(B, CompactBuffer(20))
```

### Critical difference

```
reduceByKey
     ↓
A → 40

groupByKey
     ↓
A → [10,30]
```

## 28. The Most Important RDD Practical: Word Count 🔥🔥

> This is the one I'd memorize completely.

**Input**

```scala
val lines = sc.parallelize(
  List(
    "hello spark",
    "hello scala",
    "spark is fast"
  )
)
```

**Step 1 — Split lines into words**

```scala
val words = lines.flatMap(_.split(" "))
```

**Step 2 — Convert each word to `(word,1)`**

```scala
val pairs = words.map(word => (word,1))
```

**Step 3 — Add values for same word**

```scala
val counts = pairs.reduceByKey(_ + _)
```

**Step 4 — Display**

```scala
counts.collect()
```

**Conceptually:**

```
hello → 2
spark → 2
scala → 1
is    → 1
fast  → 1
```

**Entire code**

```scala
val lines = sc.parallelize(
  List(
    "hello spark",
    "hello scala",
    "spark is fast"
  )
)

val counts = lines
  .flatMap(_.split(" "))
  .map(word => (word,1))
  .reduceByKey(_ + _)

counts.collect()
```

## 32. Student Marks — Find Highest

You can do:

```scala
students.max()
```

But for a `(name, marks)` Pair RDD, a clearer approach is:

```scala
students.sortBy(_._2, ascending = false).take(1)
```

This sorts by marks descending and takes the top result.

For a simple exam, if the question only asks for highest marks:

```scala
students.map(_._2).max()
```

gives the highest mark value.

## 37. Lazy Evaluation

Suppose:

```scala
val nums = sc.parallelize(1 to 10)

val even = nums.filter(_ % 2 == 0)

val doubled = even.map(_ * 2)
```

At this point, transformations are generally **lazy**.

Then:

```scala
doubled.collect()
```

triggers execution.

**Think:**

```
filter()
   ↓
map()
   ↓
NOT executed immediately
   ↓
collect()
   ↓
EXECUTE
```

**Why?**

Spark can:
- avoid unnecessary work
- optimize the computation
- pipeline transformations

```scala
val nums = sc.parallelize(1 to 10)

```

## 39. Fault Tolerance

If a partition of an RDD is lost:

```
Lost partition
      ↓
Spark checks lineage
      ↓
Recomputes required partition
```

Therefore:

> RDD fault tolerance is primarily achieved through lineage and recomputation of lost partitions.

> This is one of your **must-answer viva questions**.

## 40. `cache()`

Suppose:

```scala
val nums = sc.parallelize(1 to 100)

val even = nums.filter(_ % 2 == 0)
```

If you reuse `even`:

```scala
even.count()
even.collect()
```

you may want:

```scala
even.cache()
```

Then:

```scala
even.count()
even.collect()
```

**Why cache?**

```
Expensive RDD
      ↓
   cache()
      ↓
Reuse
 ↙       ↘
action1  action2
```

> Without caching, Spark may need to recompute the RDD from lineage for later actions.

**Important:**

`cache()` is **not**:
> "Put it permanently in RAM."

**Correct:**
It requests persistence using Spark's default storage level, and cached data can be evicted/recomputed.

## 42. Narrow vs Wide Transformation

### Narrow

Examples: `map`, `filter`, `flatMap`

Generally:

```
Parent partition
      ↓
Child partition
```

### Wide

Examples: `reduceByKey`, `groupByKey`, `sortBy`

Can require shuffle:

```
P1 ──┐
P2 ──┼──→ Shuffle → new partitions
P3 ──┘
```

> **Viva answer:**
> A narrow dependency doesn't require broad redistribution of parent data, while a wide dependency can require data movement or shuffle between partitions.

---

## 43. Shuffle

Suppose:

```scala
pairs.reduceByKey(_ + _)
```

Records with the same key may need to come together.

```
Partition 1 ──┐
Partition 2 ──┼──→ SHUFFLE → same keys together
Partition 3 ──┘
```

Shuffle can involve:
- Network
- Memory
- Disk/spill

depending on execution conditions.

## 44. DAG

**DAG = Directed Acyclic Graph**

Your transformations form a dependency structure:

```
RDD
 ↓
filter
 ↓
map
 ↓
reduceByKey
 ↓
action
```

Spark uses this computation structure to organize execution.

## 51. 🚨 Most Common Practical Mistakes

### Mistake 1 — Forgetting `sc`

❌ Wrong:
```scala
val rdd = parallelize(List(1,2,3))
```

✅ Correct:
```scala
val rdd = sc.parallelize(List(1,2,3))
```

---

### Mistake 2 — Using `map` for selection

❌ Wrong idea:
```scala
map(_ % 2 == 0)
```

That produces:
```
true false true false...
```

✅ If you want only even numbers:
```scala
filter(_ % 2 == 0)
```

---

### Mistake 3 — Using `groupByKey()` when asked for total

If question says:
> Calculate total sales for each product.

✅ Use:
```scala
reduceByKey(_ + _)
```

❌ not:
```scala
groupByKey()
```

---

### Mistake 4 — Forgetting Pair RDD requirement

This:
```scala
rdd.reduceByKey(_ + _)
```

requires something like:
```
("A",10)
("B",20)
```

not:
```
10
20
30
```

---

### Mistake 5 — Thinking `union()` removes duplicates

It doesn't.

Use:
```scala
a.union(b).distinct()
```

if uniqueness is required.

---

### Mistake 6 — Using `collect()` blindly

For small exam data:
```scala
collect()
```
is perfectly fine.

For huge data:

| Function | Risk |
|---|---|
| `collect()` | potentially dangerous |
| `take(n)` | safer inspection |

---

### Mistake 7 — Calling `cache()` and expecting immediate computation

```scala
rdd.cache()
```

doesn't mean:
> "Compute everything immediately."

The RDD is generally materialized when an action requires it.

## 🎯 Your Unseen-Question Strategy

When you receive any RDD practical, **don't immediately start typing**.

First identify:

### ① Where is the data coming from?

| Source | Function |
|---|---|
| Given numbers/list | `parallelize()` |
| File | `textFile()` |

### ② What happens to each record?

| Action | Function |
|---|---|
| change | `map()` |
| select | `filter()` |
| split | `flatMap()` |

### ③ Is it key-value data? `(key,value)`

If yes:

| Goal | Function |
|---|---|
| aggregate | `reduceByKey()` |
| group | `groupByKey()` |
| sort key | `sortByKey()` |

### ④ What final result do they want?

| Goal | Function |
|---|---|
| display | `collect()` |
| count | `count()` |
| sum | `sum()` |
| maximum | `max()` |
| minimum | `min()` |
| average | `mean()` |
| save | `saveAsTextFile()` |

### ⑤ Put it together

```scala
val result = rdd
  .filter(...)
  .map(...)

result.collect()
```
