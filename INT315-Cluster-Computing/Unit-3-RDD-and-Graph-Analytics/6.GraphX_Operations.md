# PART 3 — Spark GraphX Operations

## 1. First: What Do We Mean by "Graph Operations"?

With normal RDDs, you learned:

```
RDD
 │
 ├── map()
 ├── filter()
 ├── flatMap()
 ├── reduceByKey()
 ├── sortBy()
 └── ...
```

These operate on data elements.

GraphX gives us operations specifically designed for:

```
Graph
 │
 ├── vertices
 ├── edges
 └── relationships
```

So now our thinking becomes:

```
RDD operations
      ↓
operate on records


GraphX operations
      ↓
operate on graph structure,
vertices, edges and relationships
```

## 7. Operation #3 — `mapVertices()`

🔥 This is one of the most important GraphX operations.

You already know:

```scala
rdd.map(...)
```

which transforms elements. GraphX has:

```scala
graph.mapVertices(...)
```

which transforms vertex properties.

**Our current vertices**
```
1 → Alice
2 → Bob
3 → Charlie
4 → David
```

Suppose we want to convert all names to uppercase. Use:

```scala
val upperGraph = graph.mapVertices {
  case (id, name) => name.toUpperCase
}
```

Now:
```
1 → ALICE
2 → BOB
3 → CHARLIE
4 → DAVID
```

Display:

```scala
upperGraph.vertices.collect()
```

Output conceptually:

```
Array(
  (1,ALICE),
  (2,BOB),
  (3,CHARLIE),
  (4,DAVID)
)
```

---

## 8. Understand `mapVertices()` Properly

Syntax:

```scala
graph.mapVertices {
  case (id, attr) =>
    newAttribute
}
```

Where:
```
id
 ↓
vertex ID

attr
 ↓
old vertex property

newAttribute
 ↓
new vertex property
```

For our graph:

```scala
case (id, name) => name.toUpperCase
```

means:
```
id   = vertex ID
name = current vertex property
```

and we return:
```
uppercase name
```

---

## 9. Does `mapVertices()` Change the Original Graph?

**No.**

This is the same immutability idea you've already learned with RDDs.

```scala
val upperGraph = graph.mapVertices(...)
```

creates a **new graph**.

**Original:**
```
graph
1 → Alice
```

**New:**
```
upperGraph
1 → ALICE
```

The original remains unchanged.

**Viva answer**

> `mapVertices()` creates a new graph by transforming the properties of each vertex while preserving the graph's vertex IDs and edge structure.

## 10. `mapVertices()` — Another Example

Suppose vertex property is age:

```scala
val ageVertices = sc.parallelize(Seq(

  (4L, 22)

Create:

val ageGraph = Graph(ageVertices, edges)

Increase every age by 1:

val updatedAgeGraph = ageGraph.mapVertices {

```

Result:
```
1 → 21
2 → 26
3 → 31
4 → 23
```

So:

```
mapVertices()
      ↓
change vertex properties
```

## 11. Operation #4 — `mapEdges()`

Use `mapEdges()`. Remember our edges:

```
1 → 2 : friend
1 → 3 : friend
2 → 3 : friend
2 → 4 : friend
```

Suppose we want all edge properties in uppercase.

```scala
val upperEdgeGraph = graph.mapEdges {
  edge => edge.attr.toUpperCase

```

Then:

```scala
upperEdgeGraph.edges.collect()
```

Conceptually:

```
Edge(1,2,FRIEND)
Edge(1,3,FRIEND)
Edge(2,3,FRIEND)
Edge(2,4,FRIEND)
```

## 12. Understand `mapEdges()`

Syntax:

```scala
graph.mapEdges { edge =>
  newEdgeProperty
}
```

The `edge` object gives us information about the edge. Useful fields include:

```
edge.srcId
edge.dstId
edge.attr
```

For example:

```scala
graph.mapEdges { edge =>
  edge.attr.toUpperCase
}
```

means:

> Take each edge and replace its property with its uppercase version.

## 13. `mapEdges()` Example with Numeric Property

Suppose:

```
1 → 2 : 10
1 → 3 : 20
2 → 3 : 30
2 → 4 : 40
```

where the edge property represents distance. We can double every distance:

```scala
val doubledGraph = distanceGraph.mapEdges {

```

Result:

```
1 → 2 : 20
1 → 3 : 40
2 → 3 : 60
2 → 4 : 80
```

So:

```
mapEdges()
     ↓
transform edge properties
```

## 14. `mapVertices()` vs `mapEdges()`

🔥 Very important viva comparison.

| Operation | Works on | Purpose |
|---|---|---|
| `mapVertices()` | Vertices | Transform vertex properties |
| `mapEdges()` | Edges | Transform edge properties |

Mental shortcut:

```
mapVertices()
      ↓
VERTEX data

mapEdges()
      ↓
EDGE data
```

## 15. Operation #5 — `mapTriplets()`

Now we reach an important GraphX-specific operation. You remember from Part 2:

```
Triplet
```

contains:

```
Source Vertex
      +
Edge
      +
Destination Vertex
```

So:

```
Alice ──friend──→ Bob
```

can be viewed as:

```
Source        Edge        Destination
 Alice      friend             Bob
```

GraphX provides:

```scala
mapTriplets()
```

to transform data based on this complete relationship.

---

## 16. Why Is `mapTriplets()` Useful?

Suppose we have:

```
Alice → Bob
```

and we want to create a new edge property depending on:

```
Alice's data
Bob's data
existing edge data
```

`mapEdges()` only directly focuses on the edge. But `mapTriplets()` gives us:

```
source + edge + destination
```

all together. That's the key difference.

---

## 17. Simple `mapTriplets()` Example

Let's create a graph where vertices contain ages.

```scala
val ageVertices = sc.parallelize(Seq(
  (1L, 20),
  (2L, 25),
  (3L, 30),
  (4L, 22)
))
```

Edges:

```scala
val ageEdges = sc.parallelize(Seq(
  Edge(1L, 2L, "friend"),
  Edge(1L, 3L, "friend"),
  Edge(2L, 3L, "friend"),
  Edge(2L, 4L, "friend")
))
```

Create:

```scala
val ageGraph = Graph(ageVertices, ageEdges)
```

Now use:

```scala
val ageDiffGraph = ageGraph.mapTriplets {
  triplet => math.abs(triplet.srcAttr - triplet.dstAttr)
}
```

This creates an edge property equal to the age difference.

For:
```
Alice age 20
Bob age 25
```
edge property becomes:
```
5
```

For:
```
Alice 20
Charlie 30
```
becomes:
```
10
```

Meaning:

 ↓

## 19. Operation #6 — `subgraph()`

Now suppose our graph has:

```
Alice
Bob
Charlie
David
```

But we only want a graph containing certain vertices/edges. GraphX provides:

```scala
subgraph()
```

This creates a subgraph satisfying specified conditions.

---

## 20. Example: Keep Only Certain Vertices

Suppose we want only vertices whose IDs are less than or equal to 3.

```scala
val smallGraph = graph.subgraph(
  vpred = (id, name) => id <= 3
)
```

Now vertices are:

```
1 → Alice
2 → Bob
3 → Charlie
```

David:

```
4 → David
```

is removed. Display:

```scala
smallGraph.vertices.collect()
```

---

## 21. What About Edges?

This is important. If a vertex is removed, edges connected to invalid vertices cannot remain as valid graph edges. So the resulting subgraph contains only edges that satisfy the resulting graph conditions.

We can also explicitly provide an edge predicate. Example:

```scala
val friendGraph = graph.subgraph(
  epred = edge => edge.attr == "friend"
)
```

Since all our current edges are `"friend"`, they all remain. But imagine:

```
1 → 2 : friend
1 → 3 : follows
2 → 4 : friend
```

Then:

```scala
graph.subgraph(
  epred = edge => edge.attr == "friend"
)
```

keeps only:

```
1 → 2
2 → 4
```

---

## 22. `subgraph()` Syntax

General form:

```scala
graph.subgraph(
  vpred = (id, attr) => condition,
  epred = edge => condition
)
```

You don't necessarily need both.

**Vertex-only filtering**
```scala
graph.subgraph(
  vpred = (id, attr) => condition
)
```

**Edge-only filtering**
```scala
graph.subgraph(
  epred = edge => condition
)
```

**Both**
```scala
graph.subgraph(
  vpred = (id, attr) => condition,
  epred = edge => condition
)
```

## 24. Operation #7 — `degrees`

One very useful graph question is:

> How many connections does each vertex have?

This is called **degree**. Suppose:

```
       Alice
       /   \
      ↓     ↓
    Bob → Charlie
     |
     ↓
   David
```

For our directed graph:

```
1 → 2
1 → 3
2 → 3
2 → 4
```

The number of total incident edges can be obtained with:

```scala
graph.degrees
```

Display:

```scala
graph.degrees.collect()
```

Conceptually:

```
Alice   → 2
Bob     → 3
Charlie → 2
David   → 1
```

Why?

```
Alice:
1→2
1→3
= 2

Bob:
1→2
2→3
2→4
= 3

Charlie:
1→3
2→3
= 2

David:
2→4
= 1
```

---

## 25. `inDegrees`

Because GraphX edges have direction, we can distinguish:

```
incoming
```
and:
```
outgoing
```

`inDegrees` gives the number of incoming edges for each vertex.

```scala
graph.inDegrees.collect()
```

For:

```
1 → 2
1 → 3
2 → 3
2 → 4
```

we get conceptually:

```
Alice   → 0
Bob     → 1
Charlie → 2
David   → 1
```

Because:

```
Alice:
nothing points to Alice → 0

Bob:
Alice → Bob → 1

Charlie:
Alice → Charlie
Bob → Charlie
→ 2

David:
Bob → David
→ 1
```

---

## 26. `outDegrees`

`outDegrees` gives the number of outgoing edges.

```scala
graph.outDegrees.collect()
```

Conceptually:

```
Alice   → 2
Bob     → 2
Charlie → 0
David   → 0
```

Because:

```
Alice → Bob
Alice → Charlie
```

so Alice has 2 outgoing.

```
Bob:

Bob → Charlie
Bob → David
```

so Bob has 2.

---

## 27. Degrees — Important Comparison

| Operation | Meaning |
|---|---|
| `degrees` | Total degree / incident edges |
| `inDegrees` | Incoming edges |
| `outDegrees` | Outgoing edges |

Mental picture:

```
             incoming
                ↓
              Alice
                |
             outgoing
                ↓
               Bob
```

So:

```
inDegrees
    ↓
coming INTO vertex

outDegrees
    ↓
going OUT OF vertex

degrees
    ↓
overall incident connections
```

## 28. Operation #8 — `collectEdges()`

Sometimes we want to access edges grouped by source vertex. GraphX provides:

```scala
graph.collectEdges()
```

The idea is:

> Collect the outgoing edges associated with each vertex.

For example, Alice has:

```
Alice → Bob
Alice → Charlie
```

So Alice's collected outgoing edges would include those edges. Use:

```scala
val collected = graph.collectEdges()
collected.collect()
```

This can be useful when you need to inspect or process the edges associated with vertices.

## 29. Operation #9 — `collectNeighbors()`

GraphX can also retrieve neighbors. There are variants for:

```
outgoing neighbors
incoming neighbors
both directions
```

Conceptually:

```scala
graph.collectNeighbors(EdgeDirection.Out)
```

means:

> Collect outgoing neighbors.

For Alice:

```
Alice → Bob
Alice → Charlie
```

so:

```
Alice's outgoing neighbors:
Bob, Charlie
```

For incoming:

```scala
graph.collectNeighbors(EdgeDirection.In)
```

Alice has no incoming edges in our graph.

For both:

```scala
graph.collectNeighbors(EdgeDirection.Either)
```

considers both directions.

## 34. Operation #11 — `aggregateMessages()`

🔥 This is one of the important GraphX operations. Don't worry if it initially looks complicated.

The idea is simple:

> Allow vertices to send messages to neighboring vertices and aggregate the messages they receive.

Think:

```
Alice
  |
  | message
  ↓
Bob
```

and:

```
Charlie
  |
  | message
  ↓
Bob
```

Bob receives:

```
message from Alice
+
message from Charlie
```

and can aggregate them.

---

## 35. Why `aggregateMessages()`?

Suppose we want to calculate:

> How many incoming connections does every vertex have?

Conceptually:

```
Alice → Bob
Charlie → Bob
```

Bob receives:

```
1 + 1 = 2
```

This kind of neighbor-to-neighbor communication is exactly what graph processing often needs.

---

## 36. Basic `aggregateMessages()` Idea

The general structure is:

```scala
graph.aggregateMessages[MsgType](
  sendMsg = triplet => ...,
  mergeMsg = (a, b) => ...
)
```

There are two main pieces:

```
sendMsg
   ↓
What message should an edge send?

mergeMsg
   ↓
How should messages received by a vertex be combined?
```

---

## 37. Simple Example — Count Incoming Neighbors

We can send `1` to each destination vertex:

```scala
val incomingCounts = graph.aggregateMessages[Int](
  triplet => triplet.sendToDst(1),
  (a, b) => a + b
)
```

Now:

```scala
incomingCounts.collect()
```

Conceptually:

```
Alice   → 0 / absent
Bob     → 1
Charlie → 2
David   → 1
```

Why?

```
Alice → Bob
         ↑
         1 message

Alice → Charlie
Bob   → Charlie
         ↑
      2 messages

Bob → David
      ↑
      1 message
```

This is essentially computing incoming-neighbor counts.

---

## 38. Understand the Two Functions

This:

```scala
triplet => triplet.sendToDst(1)
```

means:

> Send the value 1 to the destination vertex of each edge.

Then:

```scala
(a, b) => a + b
```

means:

> If a vertex receives multiple messages, add them together.

So:

```
Every edge
   ↓
send 1 to destination
   ↓
destination receives messages
   ↓
add messages
   ↓
incoming count
```

---

## 39. `sendToSrc()` vs `sendToDst()`

This is important. Given:

```
Alice ─────→ Bob
```

**`sendToSrc()`**

Sends a message toward:

```
Alice
```

the source.

**`sendToDst()`**

Sends a message toward:

```
Bob
```

the destination.

Visual:

```
        sendToDst()
Alice ─────────────→ Bob
        sendToSrc()
Bob ←────────────── Alice
```

> Don't get confused by the arrow in the visualization — the key is which endpoint **receives** the message.

---

It lets us express computations based on:

```

```

```

**Step 4 — Graph**

val graph = Graph(vertices, edges)
```

graph.vertices.collect()

## 46. 🔥 GraphX vs RDD Operations

This distinction will help you massively.

You learned:

```scala
rdd.map(...)
```

Now:

```scala
graph.mapVertices(...)
```

They're related in spirit, but not identical.

**RDD**
```
RDD
 ↓
map()
 ↓
transform every RDD element
```

**GraphX**
```
Graph
 ↓
mapVertices()
 ↓
transform vertex properties
```

and:

```
Graph
 ↓
mapEdges()
 ↓
transform edge properties
```

and:

```
Graph
 ↓
mapTriplets()
 ↓
use source + edge + destination information
```

## 49. 🎤 Viva — Part 3

**Q1. What is `mapVertices()`?**

> `mapVertices()` transforms the properties of vertices and returns a new graph while preserving the vertex IDs and graph structure.

**Q2. What is `mapEdges()`?**

> `mapEdges()` transforms the properties of edges and returns a new graph.

**Q3. Difference between `mapVertices()` and `mapEdges()`?**

> `mapVertices()` operates on vertex properties, while `mapEdges()` operates on edge properties.

**Q4. What is `mapTriplets()`?**

> `mapTriplets()` allows transformation using information from the source vertex, edge, and destination vertex together.

**Q5. What is a triplet?**

> A triplet represents a source vertex, an edge, and a destination vertex together.

**Q6. What are `srcId` and `dstId`?**

> `srcId` is the source vertex ID and `dstId` is the destination vertex ID of an edge.

**Q7. What are `srcAttr` and `dstAttr`?**

> They represent the properties of the source and destination vertices.

**Q8. What is `subgraph()`?**

> `subgraph()` creates a new graph containing vertices and/or edges that satisfy specified predicates.

**Q9. What does `degrees` give?**

> It gives the degree of each vertex, representing its total incident connections.

**Q10. What does `inDegrees` give?**

> The number of incoming edges for each vertex.

**Q11. What does `outDegrees` give?**

> The number of outgoing edges for each vertex.

**Q12. What does `aggregateMessages()` do?**

> It allows messages to be sent along graph edges to vertices and provides a way to aggregate messages received by each vertex.

**Q13. Why is `aggregateMessages()` useful?**

> It is useful for neighbor-based and iterative graph computations where vertices need to exchange information.

**Q14. Does `mapVertices()` modify the original graph?**

> No. GraphX transformations produce a new graph; the original graph remains unchanged.

**Q15. How do you access all triplets?**

```scala
graph.triplets
```

and to retrieve them:

```scala
graph.triplets.collect()
```

## 50. ⚠️ Common Mistakes

### Mistake 1 — Using `mapEdges()` to change vertex data

❌ Wrong:
```scala
graph.mapEdges(...)
```
when the question says:
> Change student names.

✅ Correct:
```scala
graph.mapVertices(...)
```

### Mistake 2 — Using `mapVertices()` for edge weights

If question says:
> Increase edge weights by 10%.

Use:
```scala
graph.mapEdges(...)
```

### Mistake 3 — Not knowing triplet fields

Memorize:
```
srcId
dstId
srcAttr
dstAttr
attr
```

### Mistake 4 — Confusing degrees

```
degrees
```
is **not** simply:
> number of outgoing edges.

That's:
```
outDegrees
```

Incoming:
```
inDegrees
```

### Mistake 5 — Forgetting `collect()`

This:
```scala
graph.vertices
```
gives the distributed vertex RDD-like view.

For a small practical, to display:
```scala
graph.vertices.collect()
```

Same principle you learned with RDDs.
