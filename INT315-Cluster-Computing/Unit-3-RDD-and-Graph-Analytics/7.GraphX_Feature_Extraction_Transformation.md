# PART 4 — Feature Extraction

## 1. First — What Is a "Feature"?

Forget GraphX for a moment.

> A **feature** is simply a useful piece of information that describes something.

For a student:

```
Student
   |
   ├── age
   ├── marks
   ├── attendance
   └── CGPA
```

These are features.

For a graph, we can extract useful information about:

```
Vertices
Edges
Relationships
Neighborhoods
```

For example:

```
Person
 ↓
number of friends
```

That number is a graph feature.

---

## 2. Graph Feature — Simple Example

Consider:

```
             Alice
            /     \
           ↓       ↓
         Bob → Charlie
          |
          ↓
        David
```

We can extract:

```
Alice   → 2 connections
Bob     → 3 connections
Charlie → 2 connections
David   → 1 connection
```

The number of connections is a feature.

So:

```
Graph
 ↓
Extract useful information
 ↓
Feature
```

---

## 3. Why Do We Extract Features?

Because the raw graph itself may be difficult to analyze directly.

Suppose we have:

```
10 million users
+
100 million relationships
```

Instead of only looking at the graph structure, we can calculate useful values such as:

```
number of connections
number of incoming links
number of outgoing links
importance score
number of triangles
neighbor statistics
```

These extracted values can then be used for:

```
Analysis
   ↓
Prediction
   ↓
Classification
   ↓
Recommendation
   ↓
Anomaly/Fraud detection
```

## 5. Vertex-Based Features

A vertex feature describes an individual vertex.

Example:

```
1 → Alice
2 → Bob
3 → Charlie
```

Possible features:

```
Alice → degree = 2
Bob → degree = 3
Charlie → degree = 2
```

So:

```
Vertex
  ↓
degree
  ↓
feature
```

## 6. Feature #1 — Degree

This is the easiest and most important graph feature.

> Degree tells us how many edges are associated with a vertex.

Our graph:

```
1 → 2
1 → 3
2 → 3
2 → 4
```

We can extract:

```scala
graph.degrees.collect()
```

Conceptually:

```
(1,2)
(2,3)
(3,2)
(4,1)
```

The result itself is a useful feature dataset:

```
Vertex ID → Degree
```

---

## 7. Why Is Degree a Useful Feature?

Imagine a social network.

```
Person A → 2 friends
Person B → 500 friends
Person C → 10 friends
```

Degree immediately tells us something about connectivity. For example:

```
high degree
    ↓
highly connected vertex
```

Possible applications:

```
identifying highly connected users
finding influential nodes
network analysis
detecting unusual connectivity
```

---

## 8. Feature #2 — In-Degree

For a directed graph:

```
A → B
C → B
```

B has:

```
in-degree = 2
```

because two edges enter B. In GraphX:

```scala
graph.inDegrees.collect()
```

Example:

```
Alice   → 0
Bob     → 1
Charlie → 2
David   → 1
```

So:

```
in-degree
    ↓
number of incoming relationships
```

## 9. Why Is In-Degree a Feature?

Consider a social media platform.

```
User A ← 1000 followers
```

A high incoming connection count could indicate:

```

influence
```

Similarly, on the web:

```
Web page
   ↑
many pages link to it
```

The incoming link count is useful information.

## 10. Feature #3 — Out-Degree

`outDegrees` tells us how many edges leave each vertex.


For:

```

```


Sometimes the feature of a vertex depends on its neighbors. Consider:

```
        Alice
       /     \
      ↓       ↓
```

## 14. Example — Average Neighbor Age

Suppose:

```
Alice = 20
Bob = 25
Charlie = 30
```

and:

```
Alice → Bob
Alice → Charlie
```

Alice's neighboring ages:

```

```

Average:

```

= 27.5
```

So:

```
Alice
 ↓

 ↓
27.5
```

This becomes a derived graph feature.

## 15. Feature #6 — Triplet-Based Features

Remember:

```
Triplet
=
Source Vertex
+
Edge
+
Destination Vertex
```

We can use triplets to extract features involving all three.

Example:

```
Alice ──friend──→ Bob
```

Suppose:

```
Alice age = 20
Bob age = 25
```

We can calculate:

```
age difference
=
|20 - 25|
=
5
```

using:

```scala
graph.mapTriplets { t =>
  math.abs(t.srcAttr - t.dstAttr)
}
```

That creates a derived edge feature.

---

## 16. Think of Triplet Feature Extraction Like This

```
                  TRIPLET
                     |
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
   Source          Edge        Destination
   feature       feature         feature
       \             |             /
        \            |            /
         └───────────┼────────────┘
                     ↓
              Derived Feature
```

For example:

```
Source age = 20
Edge weight = 100
Destination age = 25

             ↓

age difference = 5
```

## 18. Feature #8 — PageRank as a Graph-Derived Feature

Now we're entering a more advanced graph feature.

> **PageRank** gives an importance score to vertices based on the graph's link structure.

Conceptually:

```
A → B
A → C
B → C
```

If many important vertices point toward C, C may receive a higher importance score.

Think:

```
Graph
 ↓
PageRank algorithm
 ↓
score for every vertex
 ↓
importance feature
```

GraphX provides:

```scala
graph.pageRank(0.001).vertices.collect()
```

The exact values depend on the graph and parameters. The important conceptual point is:

> PageRank converts graph connectivity information into a numerical score associated with each vertex.

---

## 19. Why PageRank Is a Feature

Suppose:

```
User A → PageRank 0.02
User B → PageRank 0.15
User C → PageRank 0.04
```

We can use:

```
PageRank score
```

as an additional feature for analysis. For example:

```
User
 ↓
degree
 ↓
PageRank
 ↓
other features
 ↓
overall analysis
```

## 20. Feature #9 — Triangle Count

Another useful graph-derived feature is **triangle count**.

Consider:

```
       A
      / \
     /   \
    B-----C
```

We have:

```
A → B
B → C
A → C
```

Together they form a triangle. A triangle represents a tightly connected relationship structure.

GraphX provides triangle-counting functionality. Conceptually:

```
graph
 ↓
triangle count
 ↓
number of triangles around vertices
```

---

## 21. Why Are Triangles Useful?

In social networks:

```
Alice → Bob
Alice → Charlie
Bob → Charlie
```

This indicates:

```
three people
+
three mutual relationships
```

Triangle-related features can help analyze:

```
tightly connected communities
social clustering
network structure
```

You don't need to memorize the algorithm yet. For your exam:

> Triangle count is a graph-derived feature that measures triangular connectivity around vertices.

## 22. Feature #10 — Connected Components

Another useful graph-level analysis is identifying **connected components**.

Suppose:

```
A ─ B ─ C


D ─ E
```

There are two separate groups:


GraphX provides connected-component functionality. Conceptually:


Suppose vertex values are ages.


## 30. Feature Extraction vs Feature Transformation

🔥 This distinction is likely important because both appear together in your syllabus.

**Feature Extraction**

> Get/create useful information from existing graph data.

Example:

```
 ↓

```

**Feature Transformation**

> Modify or convert an existing feature into another representation.

Example:

```

 ↓
```

or:

```

 ↓
"ALICE"
```

or:


## 35. 🎤 Viva Questions — Feature Extraction

**Q1. What is a feature?**

> A feature is a useful piece of information or measurable attribute describing a vertex, edge, relationship, or graph structure.

**Q2. What is feature extraction?**

> Feature extraction is the process of deriving useful information or measurable attributes from graph data and structure for analysis.

**Q3. Give examples of graph features.**

> Degree, in-degree, out-degree, edge properties, neighbor-based statistics, PageRank scores, and triangle-related measures are examples of graph features.

**Q4. What is degree as a feature?**

> Degree represents the number of edges incident to a vertex and can be used as a measure of its connectivity.

**Q5. What is in-degree?**

> In-degree is the number of edges entering a vertex.

**Q6. What is out-degree?**

> Out-degree is the number of edges leaving a vertex.

**Q7. How can GraphX calculate degree?**

```scala
graph.degrees
```

**Q8. How do you calculate in-degree?**

```scala
graph.inDegrees
```

**Q9. How do you calculate out-degree?**

```scala
graph.outDegrees
```

**Q10. What is a derived graph feature?**

> A derived graph feature is information calculated from graph structure or existing graph attributes, such as degree, PageRank, triangle count, or a relationship-based value.

**Q11. Why is PageRank useful as a feature?**

> PageRank assigns an importance score to vertices based on the graph's link structure, so the score can be used as a feature for further analysis.

**Q12. What is triangle count?**

> Triangle count measures triangular connectivity in a graph and can provide information about tightly connected relationships.

**Q13. What is a neighborhood feature?**

> It is a feature derived from the properties or structure of vertices connected to a particular vertex.

**Q14. What is triplet-based feature extraction?**

> It derives information using the source vertex, edge, and destination vertex together.

**Q15. Difference between feature extraction and transformation?**

> Feature extraction derives useful information from graph data, whereas feature transformation modifies or converts existing data or features into another form.


> Out-degree means incoming.

Exactly opposite.
```

```

No. Features can come from:
```

edges
neighbors

```

> `mapVertices()` itself means feature extraction.

Not necessarily. `mapVertices()` is a GraphX transformation operation. It can be used as part of a feature-engineering pipeline, but the operation and the concept of extraction are not identical.

## 5. Transformation #1 — `mapVertices()`

We learned this already as a GraphX operation. Now look at it specifically from the feature transformation perspective.

Suppose:

```
1 → Alice
2 → Bob
3 → Charlie
```

We want to transform every name to uppercase.

```scala
val transformedGraph = graph.mapVertices {
  case (id, name) => name.toUpperCase
}
```

Now:

```
1 → ALICE
2 → BOB
3 → CHARLIE
```

So:

```
Original vertex feature
        ↓
    mapVertices()
        ↓
Transformed vertex feature
```

## 6. Basic `mapVertices()` Syntax

Remember:

```scala
graph.mapVertices {
  case (id, attr) => newAttr
}
```

Where:
```
id
 ↓
Vertex ID

attr
 ↓
Existing vertex property

newAttr
 ↓
New vertex property
```

Example:

```scala
graph.mapVertices {
  case (id, age) => age + 5
}
```

means:

> Add 5 to every vertex's age.

After:

## 12. Transformation #3 — `mapTriplets()`

Now things become more interesting. Remember a triplet:

```
Source Vertex
     +
Edge
     +
Destination Vertex
```

Suppose:

```
Alice ──100──→ Bob
```

with:

```
Alice age = 20
Bob age = 25
```

We can create a new edge feature:

```
age difference = 5
```

using:

```scala
val ageDifferenceGraph = ageGraph.mapTriplets {
  triplet => math.abs(triplet.srcAttr - triplet.dstAttr)
}
```

This is a transformation based on the relationship plus both endpoint attributes.

```
triplet.dstId
triplet.srcAttr
triplet.dstAttr
```

```
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
       SOURCE         EDGE      DESTINATION
          │            │            │
```

## 15. Why `mapTriplets()` Is Different

Suppose the question says:

> Increase every edge weight by 10.

We only need the edge:

```scala
graph.mapEdges(edge => edge.attr + 10)
```

But suppose:

> Set the edge value to the difference between source and destination vertex values.

Now we need:

```
source vertex
+
destination vertex
```

Therefore:

```scala
graph.mapTriplets(...)
```

🔥 **Decision rule:**

```
Only vertex?
    ↓
mapVertices()

Only edge?
    ↓
mapEdges()

Source + edge + destination?
    ↓
mapTriplets()
```

## 16. Transformation #4 — `subgraph()`

Feature transformation isn't always about changing numerical values. Sometimes we want to transform the graph dataset by restricting it.

For example:

```

     ↓

     ↓
Smaller graph
```

Use:

```scala
val filteredGraph = ageGraph.subgraph(
  vpred = (id, age) => age >= 21
)
```

This creates a new graph containing vertices satisfying the condition. So conceptually:

```
Graph
 ↓
Condition
 ↓
Filtered graph
```

## 17. Why Is This Considered Useful Transformation?

Because we're creating a new representation of our graph for a specific analytical purpose.

Example:

```
Full customer graph
       ↓
Customers age >= 25
       ↓
Target subgraph
```

Then we can perform graph analysis only on that relevant subset.

## 22. Feature Normalization — Basic Idea

Normalization means transforming values into a more standardized range or scale. For example, conceptually:

```
0 to 100
   ↓
0.0 to 1.0
```

A simple min-max normalization formula is:

```
x' = (x - min) / (max - min)
```

Example:

```
Values = 10, 20, 30

min = 10
max = 30

20:
(20 - 10)/(30 - 10)
= 0.5
```

So:

```
10 → 0.0
20 → 0.5
30 → 1.0
```

For your current Unit III, understand the concept:

> Feature transformation can change the scale or representation of a feature so it becomes more suitable for subsequent analysis.

We don't need to turn this into a separate ML preprocessing chapter here.

## 34. 🎤 Viva — Feature Transformation

**Q1. What is feature transformation?**

> Feature transformation is the process of modifying or converting existing graph features into another representation that is more suitable for analysis.

**Q2. Difference between extraction and transformation?**

> Feature extraction derives useful information from graph data, while feature transformation modifies or converts existing information.

**Q3. Which GraphX operation transforms vertex properties?**

```scala
mapVertices()
```

**Q4. Which operation transforms edge properties?**

```scala
mapEdges()
```

**Q5. Which operation uses source and destination vertex information?**

```scala
mapTriplets()
```

**Q6. What is the purpose of feature scaling?**

> Feature scaling changes the numerical scale of features so that values are represented in a more suitable or comparable range.

**Q7. What is normalization?**

> Normalization transforms feature values to a standardized range or scale, such as 0 to 1, depending on the chosen method.

**Q8. Can extracted RDD features be transformed?**

> Yes. Once a graph feature such as degree is extracted as an RDD, normal Spark RDD transformations such as `map()` and `filter()` can be applied.

🔥 That's an excellent answer because it connects RDD + GraphX.

**Q9. Does `mapVertices()` modify the original graph?**

> No. It returns a new graph with transformed vertex properties.

**Q10. Why use `mapTriplets()` instead of `mapEdges()`?**

> `mapTriplets()` is used when the new value depends on the source vertex, edge, and destination vertex, whereas `mapEdges()` focuses on the edge property.

And the most important practical recognition pattern is now:

```
CREATE GRAPH
    ↓
vertices + edges
    ↓
Graph(vertices, edges)
    ↓
WHAT DOES QUESTION ASK?
    │
    ├── vertex change → mapVertices()
    │
    ├── edge change → mapEdges()
    │
    ├── source + edge + destination → mapTriplets()
    │
    ├── filter graph → subgraph()
    │
    ├── connections → degrees/inDegrees/outDegrees
    │
    ├── relationships → triplets/neighbors
    │
    └── messages → aggregateMessages()
```

### 🎯 And the extraction/transformation distinction:

```
EXTRACT
   ↓
"What useful information can I GET?"
   ↓
degree / PageRank / neighbors / etc.

TRANSFORM
   ↓
"How can I CHANGE what I have?"
   ↓
mapVertices / mapEdges / mapTriplets / scaling
```
