# PART A — RDD Final Revision

## 1. RDD in One Line

> **RDD** (Resilient Distributed Dataset) is a fault-tolerant distributed collection of elements that can be processed in parallel across a cluster.

Remember:

```
R → Resilient
D → Distributed
D → Dataset
```

**Core properties**

```
RDD
│
├── Distributed
├── Immutable
├── Partitioned
├── Parallel
├── Lazy
├── Fault tolerant
└── Lineage based
```

---

## 2. Creating RDDs

**From Scala collection**
```scala
val nums = sc.parallelize(1 to 10)
```

**Specify partitions**
```scala
val nums = sc.parallelize(1 to 10, 4)
```

**From file**
```scala
val data = sc.textFile("C:/sparkdata/data.txt")
```

**Check partitions**
```scala
nums.getNumPartitions
```

---

## 3. RDD Transformations

> Transformation → creates another RDD and is generally lazy.

**Most important:**
```
map()
filter()
flatMap()
distinct()
union()
intersection()
subtract()
sortBy()
```

Example:

```scala
val result = nums
  .filter(_ % 2 == 0)
  .map(_ * 2)
```

Nothing actually needs to execute until an action is called.

---

## 4. RDD Actions

> Action → triggers execution and returns a result or performs a side effect.

**Important:**
```
collect()
count()
first()
take()
reduce()
sum()
min()
max()
mean()
foreach()
saveAsTextFile()
```

Example:

```scala
result.collect()
```

---

## 5. Transformation vs Action

🔥 Most important RDD viva question.

| Transformation | Action |
|---|---|
| Creates new RDD | Produces result/side effect |
| Generally lazy | Triggers execution |
| `map()` | `collect()` |
| `filter()` | `count()` |
| `flatMap()` | `reduce()` |
| `reduceByKey()` | `saveAsTextFile()` |

Mental shortcut:

```
Transformation
      ↓
"WHAT should Spark do?"

Action
      ↓
"NOW actually execute it."
```

---

## 6. `map()` vs `flatMap()`

**`map()`**

One input → one output.

```scala
val x = sc.parallelize(List(1,2,3))
x.map(_ * 2).collect()
```
```
1 → 2
2 → 4
3 → 6
```

**`flatMap()`**

One input → zero/multiple outputs.

```scala
val lines = sc.parallelize(
  List("hello world", "spark scala")
)

lines.flatMap(_.split(" ")).collect()
```
```
hello
world
spark
scala
```

🔥 Remember:

```
map     → transform
flatMap → transform + flatten
```

---

## 7. Pair RDD

A Pair RDD has:

```
RDD[(K,V)]
```

Example:

```scala
val pairs = sc.parallelize(
  List(("A",10),("B",20),("A",30))
)
```

Then:

```scala
pairs.mapValues(_ * 2).collect()
```

---

## 8. `reduceByKey()`

Used for aggregation by key.

```scala
pairs.reduceByKey(_ + _).collect()
```

For:

```
A → 10
B → 20
A → 30
```

result:

```
A → 40
B → 20
```

**Word count template**

🔥 Memorize this one.

```scala
val lines = sc.parallelize(
  List("hello spark", "hello scala", "spark fast")
)

val counts = lines
  .flatMap(_.split(" "))
  .map(word => (word, 1))
  .reduceByKey(_ + _)

counts.collect()
```

Mental formula:

```
lines
 ↓
flatMap
 ↓
words
 ↓
(word,1)
 ↓
reduceByKey
 ↓
word counts
```

---

## 9. `reduceByKey()` vs `groupByKey()`

**`reduceByKey()`**

Aggregates values:

```scala
pairs.reduceByKey(_ + _)
```

**`groupByKey()`**

Groups values:

```scala
pairs.groupByKey()
```

Example:

**Input:**
```
A → 10
A → 20
A → 30
```

**`groupByKey()`:**
```
A → [10,20,30]
```

**`reduceByKey(_ + _)`:**
```
A → 60
```

🔥 For aggregation, `reduceByKey()` is generally preferred because Spark can combine values locally before shuffle.

---

## 10. Lazy Evaluation

```scala
val even = nums.filter(_ % 2 == 0)
```

Spark doesn't necessarily execute the filtering immediately.

Then:

```scala
even.collect()
```

triggers execution. Diagram:

```
filter()
   ↓
map()
   ↓
map()
   ↓
collect()
   ↓
EXECUTION
```

**Why?** To allow Spark to optimize the overall computation instead of immediately executing every transformation.

---

## 11. Lineage

> Lineage is the history/dependency chain of how an RDD was created.

```
nums
 ↓
filter
 ↓
map
 ↓
result
```

If a partition is lost:

```
Lost partition
      ↓
Lineage
      ↓
Recompute required partition
```

That's the foundation of RDD fault tolerance.

---

## 12. Cache

```scala
val even = nums.filter(_ % 2 == 0)

even.cache()

even.count()
even.collect()
```

**Why cache?**

If `even` is expensive and reused:

**Without cache:**
```
computation
   ↓
action 1

computation
   ↓
action 2
```

**With cache:**
```
computation
   ↓
cache
 ↙   ↘
A     B
```

Remember:

> `cache()` requests persistence; it does not mean the data is permanently stored in RAM.

---

## 13. Narrow vs Wide

**Narrow**

Data generally doesn't require a shuffle across partitions.

Examples:
```
map
filter
flatMap
```

**Wide**

May require shuffle.

Examples:
```
reduceByKey
groupByKey
distinct
sortBy
```

Mental shortcut:

```
Narrow
 ↓
little/no shuffle dependency

Wide
 ↓
shuffle may occur
```

# PART B — GraphX Final Revision

## 14. What Is GraphX?

> GraphX is Spark's API/component for distributed graph processing and graph analytics.

Graph:

```
Vertices + Edges
```

Example:

```
Alice ───→ Bob
  │
  └──────→ Charlie
```

---

## 15. Vertex

A vertex represents an entity. Example:

```
1 → Alice
2 → Bob
3 → Charlie
```

Conceptually:

```
(VertexId, VertexProperty)
```

Example:

```scala
(1L, "Alice")
```

---

## 16. Edge

An edge represents a relationship. Example:

```scala
Edge(1L, 2L, "friend")
```

Meaning:

```
Alice ──friend──→ Bob
```

Edge contains:

```
source ID
destination ID
edge property
```

---

## 17. Creating a Graph

🔥 Memorize this practical template.

```scala
import org.apache.spark.graphx._

val vertices = sc.parallelize(Seq(
  (1L, "Alice"),
  (2L, "Bob"),
  (3L, "Charlie")
))

val edges = sc.parallelize(Seq(
  Edge(1L, 2L, "friend"),
  Edge(2L, 3L, "friend"),
  Edge(1L, 3L, "follows")
))

val graph = Graph(vertices, edges)
```

---

## 18. Inspect Graph

```scala
graph.vertices.collect()
graph.edges.collect()
graph.numVertices
graph.numEdges
```

---

## 19. GraphX Operation Decision Tree

🔥 This is your practical cheat code.

**Question says:** Modify vertex data → `mapVertices()`

**Question says:** Modify edge data → `mapEdges()`

**Question says:** Use source + edge + destination information → `mapTriplets()`

**Question says:** Filter graph → `subgraph()`

**Question says:** Find total connections → `degrees`

**Question says:** Find incoming connections → `inDegrees`

**Question says:** Find outgoing connections → `outDegrees`

**Question says:** Get source + edge + destination → `triplets`

**Question says:** Get neighbors → `collectNeighbors()`

**Question says:** Send and combine messages → `aggregateMessages()`

---

## 20. `mapVertices()`

Example:

```scala
val newGraph = graph.mapVertices {
  case (id, name) => name.toUpperCase
}
```

**Original:**
```
Alice
Bob
Charlie
```

**New:**
```
ALICE
BOB
CHARLIE
```

Key:

```
mapVertices()
      ↓
vertex properties
```

---

## 21. `mapEdges()`

Suppose:

```
1 → 2 : 100
2 → 3 : 200
```

Then:

```scala
val newGraph = graph.mapEdges {
  edge => edge.attr * 2
}
```

Result:

```
1 → 2 : 200
2 → 3 : 400
```

Key:

```
mapEdges()
     ↓
edge properties
```

---

## 22. `mapTriplets()`

Triplet:

```
Source Vertex
      +
Edge
      +
Destination Vertex
```

Important fields:

```
triplet.srcId
triplet.dstId
triplet.srcAttr
triplet.dstAttr
triplet.attr
```

Example:

```scala
val newGraph = graph.mapTriplets {
  t => math.abs(t.srcAttr - t.dstAttr)
}
```

Useful when the new value depends on both endpoints and/or the edge.

---

## 23. `subgraph()`

Filter graph data. Example:

```scala
val filteredGraph = graph.subgraph(
  vpred = (id, age) => age >= 21
)
```

Think:

```
Original graph
      ↓
condition
      ↓
subgraph
```

---

## 24. Degrees

```scala
graph.degrees.collect()
```
Total incident connections.

```scala
graph.inDegrees.collect()
```
Incoming connections.

```scala
graph.outDegrees.collect()
```
Outgoing connections.

🔥 Memorize:

```
degrees    → overall
inDegrees  → in
outDegrees → out
```

---

## 25. Triplets

```scala
graph.triplets.collect()
```

Gives:

```
source vertex
+
edge
+
destination vertex
```

Example:

```
Alice → friend → Bob
```

Useful when the question wants relationship information together with both connected entities.

---

## 26. `aggregateMessages()`

Core idea:

```
Vertex
 ↓
send message
 ↓
neighbor
 ↓
receive
 ↓
aggregate
```

Example:

```scala
val incomingCounts = graph.aggregateMessages[Int](
  triplet => triplet.sendToDst(1),
  (a, b) => a + b
)
```

This sends `1` to each destination and adds received messages.

Examples:

🔥🔥 VERY IMPORTANT

```

```

# PART E — 30 High-Probability Unit III Viva Questions

Since you wanted exactly 30, here's the final set.

**1. What is RDD?**

> RDD is a fault-tolerant distributed collection of elements that can be processed in parallel.

**2. What does RDD stand for?**

> Resilient Distributed Dataset.

**3. Why are RDDs immutable?**

> Immutability simplifies distributed computation and allows Spark to maintain lineage for fault recovery.

**4. What is a partition?**

> A partition is a logical chunk of an RDD that can be processed independently and in parallel.

**5. How do you create an RDD from a collection?**

```scala
sc.parallelize(collection)
```

**6. How do you create an RDD from a file?**

```scala
sc.textFile("file.txt")
```

**7. What is a transformation?**

> An operation that creates a new RDD and is generally evaluated lazily.

**8. What is an action?**

> An operation that triggers computation and returns a result or performs a side effect.

**9. Give examples of transformations.**

> `map`, `filter`, `flatMap`, `distinct`, `union`, and `reduceByKey`.

**10. Give examples of actions.**

> `collect`, `count`, `first`, `take`, `reduce`, `sum`, and `saveAsTextFile`.

**11. What is lazy evaluation?**

> Spark delays execution of transformations until an action requires the result.

**12. Why does Spark use lazy evaluation?**

> It allows Spark to optimize the overall computation and avoid unnecessary work.

**13. Difference between `map()` and `flatMap()`?**

> `map()` produces one output per input, while `flatMap()` can produce multiple outputs and flattens them.

**14. What is a Pair RDD?**

> An RDD whose elements are key-value pairs of the form `(K,V)`.

**15. What is `reduceByKey()`?**

> It aggregates values having the same key using a reduction function.

**16. Difference between `reduceByKey()` and `groupByKey()`?**

> `reduceByKey()` combines values into a result, while `groupByKey()` groups all values for each key.

**17. What is lineage?**

> Lineage is the dependency history showing how an RDD was derived from previous RDDs.

**18. How does lineage provide fault tolerance?**

> If a partition is lost, Spark can use lineage information to recompute the lost partition.

**19. What is caching?**

> Caching persists an RDD so that a reused computation can be accessed more efficiently.

**20. What is GraphX?**

> GraphX is Spark's distributed graph processing API for graph analytics.

**21. What are the two basic components of a graph?**

> Vertices and edges.

**22. What is a vertex?**

> A vertex represents an entity in a graph.

**23. What is an edge?**

> An edge represents a relationship between two vertices and can contain an edge property.

**24. What is `mapVertices()`?**

> It transforms vertex properties and returns a new graph.

**25. What is `mapEdges()`?**

> It transforms edge properties and returns a new graph.

**26. What is `mapTriplets()`?**

> It transforms data using the source vertex, edge, and destination vertex information.

**27. What is a triplet?**

> A triplet consists of a source vertex, an edge, and a destination vertex.

**28. Difference between `degrees`, `inDegrees`, and `outDegrees`?**

> `degrees` gives overall incident connections, `inDegrees` gives incoming connections, and `outDegrees` gives outgoing connections.

**29. What is feature extraction?**

> It is the process of deriving useful measurable information from graph data, such as degree or PageRank.

**30. Difference between feature extraction and feature transformation?**

> Extraction obtains useful features from graph data, while transformation modifies or converts those features into another representation.
