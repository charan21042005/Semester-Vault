## 🧠 THE ONE GRAPHX MENTAL MODEL

Whenever you see a GraphX question, think:

```
                    GRAPH
                      │
             ┌────────┴────────┐
             ↓                 ↓
         VERTICES             EDGES
        (entities)          (relations)
             │                 │
             ↓                 ↓
      vertex properties   edge properties
             │                 │
             └────────┬────────┘
                      ↓
               GRAPH OPERATIONS
                      │
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
   mapVertices    mapEdges     mapTriplets
        │             │             │
        └─────────────┼─────────────┘
                      ↓
              FEATURE EXTRACTION
                      │
        ┌─────────────┼──────────────┐
        ↓             ↓              ↓
     degrees       PageRank      neighbors
        │
        ↓
          FEATURE TRANSFORMATION
                      │
                      ↓
                   RESULT
```

### The most important translation:

| Question says | Think |
|---|---|
| Person/user/node/entity | Vertex |
| Relationship/connection | Edge |
| Change vertex data | `mapVertices()` |
| Change edge data | `mapEdges()` |
| Use source + edge + destination | `mapTriplets()` |
| Filter graph | `subgraph()` |
| Number of connections | `degrees` |
| Incoming connections | `inDegrees` |
| Outgoing connections | `outDegrees` |
| Get relationships | `triplets` |
| Get neighbors | `collectNeighbors()` |
| Send information between vertices | `aggregateMessages()` |
| Importance/ranking | `pageRank()` |
| Connected groups | `connectedComponents()` |
| Triangle relationships | `triangleCount()` |

If you remember this table, a huge percentage of GraphX practical questions become straightforward.

## 2. What Is GraphX?

**GraphX**

> GraphX is Spark's distributed graph processing API/component for processing graph-structured data.

A graph consists mainly of:

```
Vertices + Edges
```

For example, social network:

```
Alice ───── Bob
  │          │
  │          │
  ↓          ↓
Charlie ─── David
```

Here:

```
Vertices = people
Edges    = friendships
```

---

## 3. What Is a Graph?

A graph represents relationships between entities. Mathematically:

```
G = (V,E)
```

where:

```
V = set of vertices
E = set of edges
```

**Example:**

Vertices:

```
1 → Alice
2 → Bob
3 → Charlie
4 → David
```

Edges:

```
1 → 2
1 → 3
2 → 3
2 → 4
```

Visual:

```
       Alice
       /    \
      ↓      ↓
    Bob ───> Charlie
     │
     ↓
   David
```

```
1 → Alice
```

|---|---|

## 8. GraphX Property Graph

## 11. Create the Graph 🔥

Now combine them:

```scala

```

Mental model:

```

   +

```

```scala
import org.apache.spark.graphx._

  (1L, "Alice"),
  (2L, "Bob"),
  (3L, "Charlie"),
```

## 14. `mapVertices()` 🔥

**Question:** Change every vertex property.

Use:

```scala
mapVertices()
```

Example:

```scala
val upperGraph = graph.mapVertices {
  case (id, name) => name.toUpperCase
}
```

Then:

```scala
upperGraph.vertices.collect()
```

Output:

```
(1,ALICE)
(2,BOB)
(3,CHARLIE)
(4,DAVID)
```

**Mental rule:**
```
Want to change vertex?
        ↓
mapVertices()
```

---

## 15. `mapVertices()` Syntax

General pattern:

```scala
val newGraph = graph.mapVertices {
  case (id, attr) =>
    newAttr
}
```

You receive:

```
id
attr
```

and return:

```
new vertex property
```

Example with age:

```scala
val ageGraph = graph.mapVertices {
  case (id, age) => age + 1
}
```

The exact property type must support the operation you're performing.

## 18. `mapTriplets()` 🔥🔥

This is an important GraphX operation. A triplet contains:

```
Source Vertex
      +
Edge
      +
Destination Vertex
```

Visual:

```
source                    destination
  ↓                            ↓
Alice ─────── edge ─────────→ Bob
```

GraphX gives you all three pieces together.

Use:

```scala
mapTriplets()
```

when your calculation needs:

```
source + edge + destination
```

## 19. Triplet Fields

Inside a triplet:

```
triplet.srcId
triplet.dstId
triplet.srcAttr
triplet.dstAttr
triplet.attr
```

Remember:

| Field | Meaning |
|---|---|
| `srcId` | source vertex ID |
| `dstId` | destination vertex ID |
| `srcAttr` | source property |
| `dstAttr` | destination property |
| `attr` | edge property |

---

## 20. `mapTriplets()` Example

Suppose:

```
Alice age = 20
Bob age = 25
```

We want age difference on every edge.

```scala
val ageDiffGraph = ageGraph.mapTriplets {
  triplet =>
    math.abs(triplet.srcAttr - triplet.dstAttr)
}
```

Now edge property becomes:

```
5
```

**Mental rule:**
```
Only vertex?
    → mapVertices()

Only edge?
    → mapEdges()

Source + edge + destination?
    → mapTriplets()
```

🔥 This distinction is extremely viva-friendly.

## 29. `aggregateMessages()` 🔥🔥

This is used when vertices need to send information/messages to other vertices. Mental model:

```
Vertex A
   │
   │ message
   ↓
Vertex B
```

Example: Count incoming edges for every destination vertex:

```scala
val incomingCounts = graph.aggregateMessages[Int](
  triplet => triplet.sendToDst(1),
  (a, b) => a + b
)
```

Then:

```scala
incomingCounts.collect()
```

Conceptually:

```
Every edge
   ↓
send 1 to destination
   ↓
destination adds messages
```

So if three edges enter Bob:

```
Bob → 3
```

## 30. `sendToSrc()` vs `sendToDst()`

Inside `aggregateMessages`:

```scala
triplet.sendToSrc(value)
```

sends to source.

```scala
triplet.sendToDst(value)
```

sends to destination.

Example:

```
Alice ─────────→ Bob
  ↑                ↑
sendToSrc       sendToDst
```


## 45. Feature Extraction vs Feature Transformation 🔥🔥

This is very important for viva.

**Feature extraction**

Means:

```
Get useful information
from existing data
```

Example:

```scala
val degreeFeatures = graph.degrees
```

You extracted:

```
degree
```

**Feature transformation**

Means:

```
Modify/convert existing feature
```

Example:

```scala
val transformedDegrees =
  degreeFeatures.map {
    case (id, degree) =>
      (id, degree * 10)
  }
```

Original:

```
(1,2)
```

becomes:

```
(1,20)
```

---

## 46. Simple Difference

Remember:

```
EXTRACTION
    ↓
"What useful information can I get?"

TRANSFORMATION
    ↓
"How can I modify/change that information?"
```

Example:

```
Graph
 ↓
degree
 ↓
EXTRACTION

degree × 10
 ↓
TRANSFORMATION
```

🔥 **Viva answer:**

> Feature extraction derives useful features from graph data, while feature transformation modifies or converts those extracted features into another representation.

## 51. Feature Scaling

Sometimes numerical features are transformed to a common scale. One common formula:

```
x' = (x - min) / (max - min)
```

This is called **min-max normalization**. Conceptually:

```
Original values
      ↓
Normalization
      ↓
0 to 1 range
```

For your syllabus-level GraphX practical, remember the concept and formula.

## 54. GraphX vs Normal Graph

**Traditional graph:**

```
Entire graph
     ↓
One machine / memory structure
```

**GraphX:**

```
Large graph
     ↓
distributed
     ↓
```

## 75. Common GraphX Mistakes 🚨

### Mistake 1 — Forgetting import
```scala
import org.apache.spark.graphx._
```

### Mistake 2 — Forgetting `L`

Use:
```scala
1L
2L
3L
```
because GraphX vertex IDs are generally `Long`.

### Mistake 3 — Confusing vertex and edge
```
Vertex = entity
Edge   = relationship
```

### Mistake 4 — Using `mapVertices` for edge changes

Wrong concept:
```
change edge → mapVertices
```

Correct:
```scala
mapEdges()
```

### Mistake 5 — Confusing `mapEdges` and `mapTriplets`

If only edge property is needed:
```scala
mapEdges()
```

If source/destination properties are needed:
```scala
mapTriplets()
```

### Mistake 6 — Confusing degree types
```
degrees      → total
inDegrees    → incoming
outDegrees   → outgoing
```

### Mistake 7 — Thinking `subgraph` creates a totally unrelated graph

It creates a filtered graph derived from the original. Conceptually:

```
Original Graph
      ↓
  subgraph()
      ↓
Filtered Graph
```

### Mistake 8 — Forgetting `.collect()`

For displaying distributed results:
```scala
graph.vertices.collect()
```
not merely:
```scala
graph.vertices
```
when you want to inspect the contents in the shell.

## 76. 🔥 Most Important GraphX Viva Answers

**What is GraphX?**

> GraphX is Spark's distributed graph processing API for representing and processing graph-structured data using vertices and edges.

**What is a vertex?**

> A vertex represents an entity or node in a graph.

**What is an edge?**

> An edge represents a relationship between two vertices.

**What is a vertex property?**

> Data associated with a vertex, such as a person's name or age.

**What is an edge property?**

> Data associated with a relationship, such as weight, distance, amount, or relationship type.

**What is a triplet?**

> A triplet combines the source vertex, edge, and destination vertex information.

**What does `mapVertices()` do?**

> It transforms vertex properties and returns a new graph.

**What does `mapEdges()` do?**

> It transforms edge properties and returns a new graph.

**What does `mapTriplets()` do?**

> It transforms graph information using source vertex, edge, and destination vertex data.

**What is feature extraction?**

> Feature extraction means deriving useful characteristics from graph data, such as degree or PageRank.

**What is feature transformation?**

> Feature transformation means modifying or converting existing features into another representation.
