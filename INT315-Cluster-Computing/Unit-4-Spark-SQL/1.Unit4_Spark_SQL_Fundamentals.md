## Phase 1 — Spark SQL Fundamentals

### 1. First, understand the problem Spark SQL solves

   Before Spark SQL, let's understand SQL itself.

Imagine a college database containing student records:

| ID | Name    | Department | Marks |
| -- | ------- | ---------- | ----- |
| 1  | Alice   | CSE        | 85    |
| 2  | Bob     | ECE        | 72    |
| 3  | Charlie | CSE        | 91    |
| 4  | David   | IT         | 65    |
| 5  | Emma    | ECE        | 88    |

Suppose your examiner asks:

1. Display all students.
2. Find students scoring above 80.
3. Find the average marks.
4. Count students in each department.
5. Display students in descending order of marks.

How would you solve these problems?

One way is to write Scala code using collections or RDD transformations.

For example, with an RDD:

```scala
val students = sc.parallelize(Seq(
  ("Alice", "CSE", 85),
  ("Bob", "ECE", 72),
  ("Charlie", "CSE", 91),
  ("David", "IT", 65),
  ("Emma", "ECE", 88)
))

students.filter(_._3 > 80).collect()
```

This works.

But imagine the dataset has 100 million records.

Writing every operation through low-level transformations can become complicated.

Wouldn't it be easier if we could simply write SQL queries?

For example:

```sql
SELECT * FROM students;
```

To find students with marks above 80:

```sql
SELECT * FROM students
WHERE marks > 80;
```

To calculate average marks:

```sql
SELECT AVG(marks)
FROM students;
```

This is where Spark SQL becomes useful.

---

### 2. What is SQL?

   SQL stands for:

Structured Query Language.

It is a language used to communicate with relational databases and perform operations on structured data.

Some common SQL operations:

| SQL command | Purpose |
| --- | --- |
| `SELECT` | Retrieve data |
| `WHERE` | Filter records |
| `GROUP BY` | Group records |
| `ORDER BY` | Sort records |
| `JOIN` | Combine tables |
| `COUNT()` | Count records |
| `SUM()` | Calculate total |
| `AVG()` | Calculate average |

**Example:**

```sql
SELECT name, marks
FROM students
WHERE marks > 80;
```

**Meaning:**

1. Select the name and marks columns.
2. Read records from students.
3. Keep only records where marks exceed 80.

**Expected result:**

| name | marks |
| --- | ---: |
| Alice | 85 |
| Charlie | 91 |
| Emma | 88 |

**Important: SQL is a query language. Spark SQL is Spark's module for working with structured data using SQL and DataFrame APIs.**

---

### 3. What is Spark SQL?

**Important definition for viva**

   Spark SQL is a module of Apache Spark used for processing structured and semi-structured data through SQL queries and the DataFrame API.

In simple language:

Spark SQL allows us to process large datasets using familiar SQL queries while taking advantage of Spark's distributed processing capabilities.

Imagine:

```text
              LARGE DATASET
                    |
                    ↓
                SPARK SQL
                    |
          ┌─────────┴─────────┐
          ↓                   ↓
      SQL QUERIES        DATAFRAME API
          ↓                   ↓
          └─────────┬─────────┘
                    ↓
             SPARK PROCESSING
                    ↓
                 RESULTS
```

You can work with structured data without manually writing every low-level RDD transformation.

**Example:**

Instead of:

```scala
students.filter(_._3 > 80).collect()
```

You can register the data as a table and write:

```sql
SELECT *
FROM students
WHERE marks > 80;
```

Both approaches can solve the same logical problem, but SQL is often more readable for relational operations.

### 4. Why do we need Spark SQL?

   Let's understand its importance from practical situations.
   Problem 1 — Complex data processing
   Suppose you need to:

- Group employees by department.
- Calculate average salaries.
- Sort departments by salary.
- Join employee and department records.
  Doing all this with low-level RDD operations requires several transformations.

Spark SQL allows you to express the same logic using familiar SQL syntax.
Problem 2 — Working with structured data
Many applications store data in structured formats:

- CSV
- JSON
- Parquet
- ORC
- Relational databases
  Spark SQL provides interfaces to work with these data sources.
  Problem 3 — Distributed processing
  Suppose your company has 500 GB of employee and transaction records.

A normal in-memory Scala collection on one machine is not the appropriate approach for processing all that data.

Spark can distribute supported data processing across a cluster.
Problem 4 — Integration with existing applications
Data analysts may understand SQL, while developers may prefer Scala or Python.

Spark SQL supports both styles.

```text
Data Analyst             Developer
     |                       |
 SQL Queries           Scala / Python
     |                       |
     └──────────┬────────────┘
                ↓
             Spark SQL
                ↓
          Distributed Data
```

### 5. Important features of Spark SQL

   Let's understand each feature individually.

#### 5.1 SQL interface

   Spark SQL allows users to execute SQL queries.

**Example:**

```sql
SELECT * FROM students;
```

**Use when you want to retrieve or manipulate structured data using SQL syntax.**

#### 5.2 DataFrame API

Spark SQL provides the DataFrame API.

A DataFrame is a distributed collection of data organised into named columns.

**Example:**

| name | age | marks |
| --- | ---: | ---: |
| Alice | 21 | 85 |
| Bob | 22 | 72 |

Think of a DataFrame as a table-like structure distributed across a Spark cluster.

We'll study DataFrames deeply in Phase 2.

#### 5.3 Query optimization

Spark SQL uses a component called Catalyst Optimizer.

Its job is to optimize logical query plans before execution.

For example:

```sql
SELECT name
FROM students
WHERE marks > 80;
```

Spark can optimize how the filtering and column selection are performed.

**The key point:**

Catalyst analyzes and optimizes query plans so Spark can execute queries more efficiently.

#### 5.4 Distributed processing

Spark SQL can process data across multiple partitions and machines.

```text
            DATASET
               |
       ┌───────┼───────┐
       ↓       ↓       ↓
    PART 1   PART 2   PART 3
       ↓       ↓       ↓
       └───────┼───────┘
               ↓
            RESULTS
```

#### 5.5 Multiple data sources

Spark SQL can work with:

- CSV
- JSON
- Parquet
- ORC
- JDBC sources
  For example:

```scala
  val df = spark.read.csv("students.csv")
```

We'll learn the complete syntax later.

#### 5.6 Integration with Spark ecosystem

Spark SQL works with other Spark components.

```text
              APACHE SPARK
                   |
       ┌───────────┼───────────┐
       ↓           ↓           ↓
     RDD       SPARK SQL     MLlib
                   |
               DataFrames
```

You can convert RDDs to DataFrames, process data with SQL and continue working with Spark.

#### 5.7 Support for multiple languages

Spark SQL can be used through APIs in:

- Scala
- Python
- Java
- R
  For our practical examination, we'll use Scala through spark-shell.

### 6. Spark SQL architecture — understand the flow

   This is a common theory and viva topic.

jaceklaskowski.github.io

Understand the important components:

| Component | Responsibility |
| --- | --- |
| SQL Parser | Parses the SQL query |
| Catalyst Optimizer | Optimizes the logical query plan |
| Physical Planner | Chooses a physical execution plan |
| Execution Engine | Executes the plan using Spark |

**Example query**

```sql
SELECT name
FROM students
WHERE marks > 80;
```

**Conceptual processing:**

```text
SQL QUERY
   |
   ↓
SQL PARSER
   |
   ↓
LOGICAL PLAN
   |
   ↓
CATALYST OPTIMIZER
   |
   ↓
OPTIMIZED LOGICAL PLAN
   |
   ↓
PHYSICAL PLANNER
   |
   ↓
PHYSICAL EXECUTION PLAN
   |
   ↓
SPARK EXECUTION
   |
   ↓
RESULT
```

**Exam point: Catalyst is Spark SQL's query optimizer. It is not the SQL parser or the execution engine.**

### 7. SparkSession — the most important practical concept

   Now let's enter the practical side.

Earlier, when learning RDDs, we used:

```scala
sc
```

Remember?

sc represents the SparkContext.

But when working with Spark SQL, we primarily use:

```scala
spark
```

This represents the SparkSession.

**What is SparkSession?**

SparkSession is the main entry point for using Spark SQL functionality.

It allows us to:

- Create DataFrames.
- Read structured data.
- Execute SQL queries.
- Register temporary views.
- Access Spark SQL functionality.

**Important distinction**

| SparkContext (`sc`) | SparkSession (`spark`) |
| --- | --- |
| Traditional entry point for RDD operations | Main entry point for DataFrame and SQL operations |
| Used with `parallelize()` | Used with `read` and `sql()` |
| Supports RDD creation | Supports DataFrame creation and SQL queries |

In modern Spark applications, SparkSession also provides access to the underlying SparkContext.

### 8. First practical — create a DataFrame

### 9. What exactly is a DataFrame?

**Very important**

   A DataFrame is a distributed collection of data organised into named columns, similar to a table in a relational database.

Consider:

```text
DataFrame: students

+-------+---+----------+-----+
| name  |age|department|marks|
+-------+---+----------+-----+
| Alice |21 | CSE      | 85  |
| Bob   |22 | ECE      | 72  |
+-------+---+----------+-----+
```

Its important characteristics:

1. Data is distributed across partitions.
2. Data is organised into named columns.
3. It has a schema.
4. It supports SQL and DataFrame operations.
5. Spark can optimize DataFrame queries.
   DataFrame vs RDD

| RDD | DataFrame |
| --- | --- |
| Distributed collection of objects | Distributed data organised into named columns |
| No mandatory named-column schema | Has a schema |
| Lower-level API | Higher-level structured API |
| Uses RDD transformations | Uses DataFrame operations and SQL |
| Less automatic relational query optimization | Uses Spark SQL optimization |

Important viva distinction: In modern Spark, a DataFrame is conceptually a Dataset of Row objects. In Scala, DataFrame is an alias for Dataset[Row].

---

### 10. What is a Dataset?

    A Dataset is a distributed collection of strongly typed objects with Spark SQL's structured processing capabilities.

For example:

- DataFrame: structured rows with named columns, represented as Dataset[Row].
- Dataset: can represent typed objects such as Dataset[Student].
  In Scala, Datasets can provide compile-time type safety through their encoders.

For this unit, focus primarily on DataFrames and SQL queries. We will not let the Dataset concept distract us from the syllabus.

### 11. First SQL query — a preview

    We have created a DataFrame:

    val df = data.toDF("name", "age", "department", "marks")

But how do we query it using SQL?

Spark SQL needs a table-like name for the DataFrame.

We create a temporary view:

```scala
df.createOrReplaceTempView("students")
```

Now execute:

```scala
spark.sql("SELECT * FROM students").show()
```

**Expected output:**

```text
+-------+---+----------+-----+
|   name|age|department|marks|
+-------+---+----------+-----+
|  Alice| 21|       CSE|   85|
|    Bob| 22|       ECE|   72|

|  David| 23|        IT|   65|
|   Emma| 22|       ECE|   88|

```

Congratulations — you've executed your first SQL query using Spark SQL!

### 13. Phase 1 — common mistakes

| Mistake | Correct understanding |
| --- | --- |
| Using `sc.sql()` | Use `spark.sql()` |
| Assuming `sc` and `spark` are the same | SparkContext and SparkSession have different responsibilities |
| Calling `show()` on an RDD | `show()` is a DataFrame display method |
| Thinking DataFrame is just a Scala List | It is a distributed structured dataset |
| Thinking `toDF()` creates a permanent SQL table | It creates a DataFrame |
| Thinking a temporary view is permanent | A normal temporary view is tied to its SparkSession |
| Forgetting SQL view registration | Register the view before querying its name |
